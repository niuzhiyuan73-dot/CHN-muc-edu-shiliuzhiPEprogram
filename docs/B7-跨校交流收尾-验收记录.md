## 本批完成

按指南 §8 先核对、再补缺，不从头重写（跨校交流的核心闭环已在 S4 实现并测试）：

- **核对权限矩阵与流程**（对照 S4 实施记录与 `exchange-service.js`）：创建赛事 /
  接受或婉拒邀请 / 锁定名单（主办校或受邀校管理员、协会负责人）、抽签与指定
  裁判（平台管理员或双方校管理员）、比分确认（管理员 / 指定裁判 / 未指定裁判时
  双方参赛者）、名次确认（管理员）——与记录一致；普通会员只能报名 / 取消。
- **交流赛与校内计分边界**：独立集合（exchange_events / invitations / signups /
  matches），服务端固定 `eventScope=inter_school`、`ratingPolicy=unrated`，
  全部动作不写旧 events / matches / memberRatings——既有回归测试继续守着。
- **补页面级测试（`tests/exchange-page.test.js` +2）**：
  - 身份切换经 app 统一入口（B3 链路在交流页生效：切演示身份后页面按新身份
    重取能力，兼容会话随之一致）；
  - 普通会员不能处理邀请 / 锁定名单，误触发无副作用（邀请状态原样、名单未锁定）。
- 既有覆盖复核：16 条服务测试（邀请处理、双名额并发、锁定冻结、隐私投影、
  拒绝后不可反悔、身份失效在报名与锁定时复核、审计回滚、日期与名额校验、
  旧集合零写入、抽签权限与确定性、比分推进与非法比分、裁判指派、名次推导）
  + 5 条页面测试（两校全流程、重试幂等、云模式拒绝、上述两条）。
