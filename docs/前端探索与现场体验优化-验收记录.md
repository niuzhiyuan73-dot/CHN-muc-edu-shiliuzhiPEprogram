## 3. 关键口径

- **“分页”是服务端 offset 分页，不是新游标协议**：复用 `listSchoolEvents` 已有 `limit/offset/hasMore/nextOffset`。本批没有新增 action，避免为同一列表再造一套契约。
- **数据库物理读没有随分页下降**：`listSchoolEvents` 仍先读本协会赛事集合再做条件过滤与排序；本批降低的是响应体、客户端传输和视图节点，不是云端扫描量。要真正下推，需要带范围条件的仓储查询与索引，另立批次。
- **本地草稿不是服务端草稿**：只存未提交输入，按账号与场次隔离，24 小时过期；保存成功才代表服务端接收。版本冲突不自动恢复，避免覆盖他人修改。
- **“晋级之路”只做展示分组**：胜负、对手、比分、能力旗标全部来自既有 `buildBracketRows`，前端不推算晋级关系；“明细”始终保留。
- **“默认项目”不筛选首页**：它只决定协会工作台入口；首页仍是跨协会聚合。该文案与直达动作是语义澄清，不改数据范围。
- **“生涯节点”不是完整生涯总量**：只基于当前已加载护照页，页面明确提示；不生成成长值、不把名单入选写成实际出场。
- **没有重启暂不做项**：场地看板、校园赛历、成绩分享卡仍按原产品决定排除。

## 4. 踩坑与纠正

1. **页面测试工装不认数组下标路径**：`onInputStat` 改为 `statRows[0].points` 后，测试仍读旧值，实际是 `tests/helpers/page-harness.js` 只按点拆路径，把整串当普通属性。已让工装按真机语义解析 `a[0].b`，否则后续单字段更新都会被误判。
2. **剥离 `allRows` 后原有测试失效**：排行榜/赛事页搜索测试原本从 `data.view.allRows` 取完整榜。实现已改为实例持有完整榜、视图层副本不含 `allRows`；测试改读 `page.view.allRows`，保留“减少序列化”的目标而不是退回旧实现。
3. **签表“本人获胜”第一版判断过宽**：只判断“本人参赛且有 winner”会把输球也标成赢。已改为判断本人是否在 `winner` 对应的一侧。
4. **“全部赛事”看似全量读取，实际仍受仓储限制**：页面不再 `listLimit: Infinity`，但服务端还是先取范围集合。验收不把它写成“数据库读已下推”，避免把应用层限量冒充查询层优化。
5. **草稿不能按场次单独做键**：只按 `matchId` 会在共用设备或换账号时串输入；最终键包含学校、协会、场次与账号，并记录 revision。
