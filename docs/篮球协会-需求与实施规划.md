# 篮球协会：需求与实施规划

日期：2026-10-19
状态：**A 期已落地**（协会注册 + 能力导航 + 6 集合 + 规则纯模块 + 后端闸门）；B 期组队待开工
上游：[篮球足球排球协会-调研与实施规划](篮球足球排球协会-调研与实施规划.md)（三运动共用草案）
范围：只做篮球，五人制优先；三人制**列入计划、首版不做**

---

## 一、结论先行

篮球和现有四个球拍运动**不是同一种东西**：球拍运动是「个人 vs 个人，结果决定等级分」，篮球是「球队 vs 球队，结果决定名次与统计」。所以篮球不是「加一个协会 + 加一个赛制」，而是**在协会里加一条新的业务线**。

三条判断，决定了整个方案的样子：

1. **团队赛不复用 `matches`。** 现有 `matches` 是个人 Elo 的唯一流水，`stats` / `member_ratings` / 榜单 / 个人成绩都会扫它。团队赛一旦写进去，个人账本立刻被污染（一场 5v5 会被算成什么？双打？单打？都不对）。**必须独立集合、独立服务、独立 action。**
2. **抽签与晋级可以复用。** `utils/bracket.js` 的 `drawBracket({entries})` 只认「参赛单位 id」，`draw.js` 的 `planNextRound` 只认 `draw.slots` 与已生效比赛。把**球队**当成一个 entry id 传进去，签表、轮空、三四名、下一轮推进都能直接跑——这是省掉三分之一工作量的地方。
3. **比分是权威，个人统计是解释。** 强制「先录投篮事件再算总分」在校园赛会卡住（很多场次只有一个记分牌）。所以：总分必须能单独录；详细统计可选；两者不一致时**以总分为准并显示差额**，绝不静默改分。

## 二、规则口径（查证结果）

### 2.1 五人制：FIBA / 中国篮协 / CUBAL 一致

| 项 | 口径 | 来源 |
|---|---|---|
| 比赛时间 | 4 节 × 10 分钟；加时 5 分钟，可多次 | FIBA 官方规则 2024（2024-10-01 起施行） |
| 节间休息 | 1-2 节之间、3-4 节之间 2 分钟；半场 10 分钟（CUBAL 基层赛口径） | 第 27 届 CUBAL 基层赛竞赛规程 |
| 得分 | 罚球 1 分、三分线内 2 分、三分线外 3 分 | FIBA |
| 三分线 | 6.75 m（底角 6.60 m）；球场 28 × 15 m | FIBA |
| 进攻时限 | 24 秒；进攻篮板后 14 秒 | FIBA |
| 个人犯规 | **5 次离场**（含技术犯规）；NBA 是 6 次，别照搬 | FIBA |
| 全队犯规 | **每节第 5 次起**，对方每次非投篮犯规获 2 次罚球（进攻犯规除外） | FIBA |
| 暂停 | 上半时 2 次、下半时 3 次；第 4 节最后 2 分钟最多 2 次；每个加时 1 次；每次 1 分钟 | FIBA |
| 报名人数 | CUBAL 基层赛：报名 15 人、到场 12 人、不足 8 人不得参赛。**本项目不采用 8 人下限**：报名满 5 人即可比赛，上限建议 12 人 | CUBAL 规程 / 本项目决策 |

> 校园院系赛最常见的变体是 **2 节 × 20 分钟（上下半场）** 或 **4 节 × 8/10 分钟**、个人犯规 4/5 次、全队犯规 4 次起罚球。这些**不做成代码常量**，而是赛事创建时选的规则快照（见 4.2）。

### 2.2 三人制：是另一项运动，不是「5 改 3」

**已列入计划，但首版不做**——先让五人制跑通一届真实比赛，再按同一套球队与赛事模型接 3x3 规则模板。

| 项 | 口径 |
|---|---|
| 场地 | 半场、一个篮筐 |
| 时间 / 得分上限 | 10 分钟，或先到 21 分立即结束 |
| 得分 | 弧内 1 分、弧外 2 分、罚球 1 分 |
| 进攻时限 | 12 秒 |
| 加时 | 先得 2 分者胜 |
| 人数 | 3 人 + 1 替补 |

计分方式、场地、犯规罚则全都不同，**必须独立规则模板**。首版只把 `sportFormat` 字段留出来（`basketball5` / `basketball3`），不实现 3x3。

### 2.3 统计口径（FIBA 统计员手册）

| 指标 | 判定要点 |
|---|---|
| 投篮命中/出手 | 分 2 分球、3 分球两套；**有出手才谈命中率**，没记出手就不能显示 0% |
| 罚球命中/出手 | 单独一套 |
| 篮板 | 分进攻 / 防守；球队篮板与个人篮板分开 |
| 助攻 | 传球**直接**导致得分；接球后运球突破再得分通常不计；不能自己助攻自己 |
| 抢断 / 盖帽 / 失误 | 事件级，与得分无派生关系 |
| 犯规 | 个人犯规、全队犯规、技术犯规、违体/取消资格**分开建模**；走步等违例不算犯规 |

关键设计：统计值有四种状态——**有值、确认是 0、未记录、本赛事不统计**。用一个 `null` 打天下会把「没统计」显示成「0 次」，场均直接被拉低。这也是草案 2.4 的判断，我同意并把它落成字段。

## 四、数据模型（首版 6 个集合）

| 集合 | 存什么 | 关键字段 | 唯一约束 |
|---|---|---|---|
| `teams` | 球队 | `schoolId`、`association`、`sport`、`name`、`logo`、`captainId`、`college`（可选）、`status`(pending/active/archived) | 同一协会内队名唯一 |
| `team_members` | 队员与入队申请 | `teamId`、`userId`、`role`(captain/member)、`status`(pending/active/left/rejected)、`joinedAt`、`leftAt` | 一队一人一条；同赛事只能代表一队 |
| `team_events` | 赛事 | `rules`（规则快照）、`format`、`entryMin/Max`、`collegePolicy`、`statPolicy`(basic/detailed)、`status`、`draw`、`results` | — |
| `team_event_entries` | 球队报名 | `eventId`、`teamId`、`status`(submitted/approved/rejected)、`roster`（姓名+号码快照）、`lockedAt` | 一赛事一队一条 |
| `team_matches` | 比赛 | `eventId`、`round`、`stage`、`teamA/teamB`、`scoreA/scoreB`、`periods[]`、`winner`、`status`、`court`、`matchTime`、`referees[]`、`recorder`、`revision` | `_id` 用确定性键（赛事+轮次+阶段+签位） |
| `team_match_stats` | 单场已发布统计 | `matchId`、`version`、`rows[{userId,no,pts,fga2,fgm2,fga3,fgm3,fta,ftm,rebO,rebD,ast,stl,blk,to,fouls}]`、`integrity` | 一场一版本一条；重发替换不累加 |

**不做的**：`player_season_stats`。个人累计从「已发布单场」聚合出来即可（现有赛季积分就是聚合而非落库），多一张表就多一次不一致的机会。

### 4.1 规则快照（`team_events.rules`）

只存**会影响判定**的字段，不塞规则书：

```json
{
  "sportFormat": "basketball5",
  "periods": 4,
  "periodMinutes": 10,
  "overtimeMinutes": 5,
  "personalFoulLimit": 5,
  "teamFoulPenalty": 5,
  "threePointLine": 6.75,
  "shotClock": 24,
  "rosterMin": 5,
  "rosterMax": 12,
  "minOnCourt": 2,
  "allowDraw": false,
  "ruleVersion": "fiba-2024"
}
```

`rosterMin: 5` 是**本项目口径，不是 FIBA / CUBAL 口径**：CUBAL 基层赛是报名 15 人、到场 12 人、不足 8 人不得参赛；本项目按「场上 5 人齐即可比赛、不强制替补」处理。赛事可在创建时上调到 8 / 10，但不能低于 5（低于 5 人凑不齐场上阵容）。

`minOnCourt: 2` 是犯规离场后的兜底：报名只要 5 人就没有替补，一旦有人 5 犯离场，场上会只剩 4 人甚至更少；按 FIBA 口径，一队场上不足 2 人即判负。这条必须留在规则快照里，否则「5 人开赛」会撞上一个没定义的死局。

`allowDraw` 是给小组循环赛用的：联赛允许平局，淘汰赛必须加时。**赛事一旦开赛，规则不可改**（改了历史比赛不可比）。

### 4.2 三份名单，不能混

| 名单 | 存在哪 | 锁定后 |
|---|---|---|
| 长期球队成员 | `team_members` | 随时可进出（退队留 `leftAt`） |
| 赛事报名名单 | `team_event_entries.roster` | 赛前锁定，快照姓名与号码 |
| 单场出场名单 | `team_matches.rosters` | 开赛即定，用于「实际出场」判定 |

历史成绩只认快照。之后队员退队、改名、换号**都不回写历史**——这是草案 4.1 的核心，我原样保留。

## 五、流程与页面

### 5.1 组队

```
学生申请建队 → 协会管理员审核 → 球队建立（captain）
→ 队员申请 / 队长邀请（本人须接受）→ 队长审批 → 入队
→ 队长可移出队员、交接队长 → 解散 = 归档（历史成绩仍可查）
```

页面：`team-list`（我的球队 / 全部球队 / 招募中）、`team-detail`（队徽、成员、申请、管理、赛程战绩）。

### 5.2 赛事

```
管理员建赛（选规则模板 + 赛制 + 报名范围）
→ 队长报名并提交名单 → 审核 → 锁定名单
→ 抽签（复用 bracket）→ 排赛程（时间/场地/裁判）
→ 录分 → 审核发布 → 名次与统计
```

页面：`team-event-edit`（建赛）、`team-event-detail`（报名、名单、赛程、对阵、积分）、`team-match-score`（录分台）。

### 5.3 录分台（篮球专用）

竖屏优先，左队右队，按节记录。

```
顶部：队名 · 比分 · 第 N 节 · 剩余时间(可选) · 保存状态
中部：两队球员（号码+姓名），点人 → 2 分 / 3 分 / 罚球 / 犯规
底部：撤销上一操作 · 结束本节 · 结束比赛
侧栏：最近 5 条操作（可点开纠正）
```

三条硬规则：

1. **点人得分才记个人分**；只点「+2」不点人 → 记球队得分，个人分显示「待归属」（允许赛后补）。
2. **不能自己助攻自己**；助攻是得分后的可选项，允许「稍后补记」。
3. **撤销是流水里的反向操作**，不是改数字；撤销后关联助攻一并回退。

### 5.4 结果与展示

- 赛事详情：赛程、单场比分（含分节）、对阵图、小组积分、球队名次、单场统计。
- 个人页：加入「我的球队」「参赛经历」「团队名次」；技术统计与球拍运动的等级分**分栏展示**，不混算。
- 公开页面只读已发布版本；实时比分若开放，必须标注「进行中 · 非最终结果」。

## 七、风险与红线

| 风险 | 处理 |
|---|---|
| 污染个人 Elo | 团队赛写 `team_matches`；后端在 `submitMatch` 入口显式拒绝 `sportType==='team'` 的协会，不靠前端藏按钮 |
| 两台手机同时录分 | 主记录员 + `revision` 乐观锁；冲突返回「已被他人更新，请刷新」而不是静默覆盖 |
| 重试导致重复加分 | `requestId` 幂等；同一次操作只生效一次 |
| 发布写一半 | 比分、统计、名次在同一事务；超事务边界则先写「准备中」再翻版本指针 |
| 名单锁定被绕过 | 校验在服务端，按 `lockedAt` 判断；页面禁用只是体验 |
| 规则常量硬编码 | 一律进 `rules` 快照；改规则 = 新建赛事，不改历史 |
| 沿用运动会集合 | 禁止。运动会 15 个集合一律带 `meetId`，球队赛事借用会污染届次 |

## 八、6 项决策（2026-10-19 已确认）

| # | 决策 | 结论 | 落地位置 |
|---|---|---|---|
| 1 | 首版规则模板 | **4 节 × 10 分钟**（对齐 FIBA / 中国篮协 / CUBAL），另提供「2 节 × 20 分钟」预设给院系赛 | §4.1 `rules` |
| 2 | 个人统计首版范围 | **总分 + 个人犯规**（得分可归属到人）；篮板 / 助攻 / 抢断 / 盖帽 / 失误放 D 期详细模式 | §6 C、D |
| 3 | 球队与学院 | **球队可选绑定学院**；赛事级 `collegePolicy` 决定是否强制代表学院，默认不要求 | §4 `team_events.collegePolicy` |
| 4 | 谁能建队 | **学生申请 + 协会管理员审核**；队长只管自己队，不因此获得协会管理权 | §5.1、§9 |
| 5 | 是否进积分 / 等级分 | **都不进**。只记球队名次 + 个人参赛 / 获奖记录（与运动会荣誉同构） | §1、§3 |
| 6 | 三人制 | **列入计划、首版不做**，只留 `sportFormat` 扩展点 | §2.2 |
