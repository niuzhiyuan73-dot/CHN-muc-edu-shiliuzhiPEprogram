# mock 演示账号与切换指南

本地模拟数据源（`miniprogram/services/mock.js`）里预置了一批演示账号，
用来演「同一个人在不同协会身份不同」「一个人身兼数职」这类场景。
本文说清两件事：**每位演示账号的编号与权限**，以及**怎么切换当前演示种子**。

种子登记的角色表在 `miniprogram/services/seed.js` 的 `ASSOC_ROLE_SEED`
（按协会登记）与 `MEMBER_SEED`（账号的全局角色）里，改动后本文要同步更新。

---

## 一、怎么切换当前演示种子（登录账号）

mock 的「当前登录是谁」是一个**编译期常量**，没有运行时切换入口：

`miniprogram/services/mock.js`

```js
const DEFAULT_CURRENT_USER_ID = 'u06';   // ← 改这里
```

切换步骤：

1. 打开 `miniprogram/services/mock.js`，把 `DEFAULT_CURRENT_USER_ID`
   改成下表里某个编号（例如 `'u01'`）。
2. 保存，在微信开发者工具里点一次「编译」。
3. 启动时 `app.js` 的 `refreshSession()` 会把已登录的演示账号校正成
   这个常量指向的人——「我的」页、各管理入口随之按他的权限显示。
   若当前页面还停着旧账号，**切到别的标签页再切回来**（页面 `onShow`
   会重读登录态）即可看到新的。

几个要点：

- **它只决定「当前登录是谁」**，不改数据集本身。换回来（改回 `'u06'`）再编译即可。
- 编号必须是种子里存在的会员（`u01`–`u24`），写错会回落到名单里的第一个人。
- 权限随**当前协会**变化：同一个人切到不同协会，身份可能不同
  （见下表与第三节）。所以「切账号」和「切协会」是两件事，配合使用。
- **登录快照会缓存**：账号一旦登录过，`app.js` 会把它写进本地缓存；
  启动时的校正是「按常量切人」，正常改常量即可覆盖这份缓存。若遇到没有
  按预期切换（例如页面缓存了旧数据），用最可靠的两步：**「我的」→ 退出登录**，
  再重新编译登录。也可以在开发者工具里 **清缓存 → 清除数据缓存**。
- **例外**：缓存里那个账号若在数据源中已查不到（例如当场注册、重启后内存
  清空的账号），会**原样保留**，不会强行换成演示种子。只有当缓存里是
  「另一个种子会员」时，才会被切成常量指向的那个人。

### 这批演示账号同时带着「学校维度」

改常量不只换「老页面」的登录人。启动时 `school-mock.js` 的 `attachLegacyMembers`
会把 u01–u24 一并登记成 **中央民族大学（`muc`）的在册会员**，并在同一份学校种子里
补齐他们的校级角色：

- **u01** → 民大**校级管理员**（`school_roles.role = 'admin'`）；
- `ASSOC_ROLE_SEED` 里登记的各协会负责人 / 学院负责人 → 对应协会的
  `memberships`（`leader` / `staff`）；`u02` 只在默认协会 `pkb` 记 `staff`；
- 每位账号都有一条民大的 `school_members`（学院、学号一并补上）与 `member_ratings`。

因此**学校维度的页面全部认这批账号**：协会空间、学校身份、跨校邀请赛都按
`DEFAULT_CURRENT_USER_ID` 指向的人取权限。要演「民大校管理员」就把常量改成
`'u01'`，演「匹克球协会负责人」就改成 `'u09'`——**不用再进「学校身份」页切换体验身份**。

> 「学校身份」页上原有的「体验身份」下拉（演示身份切换器）已经移除。演示身份
> 只由 `DEFAULT_CURRENT_USER_ID` 决定，改完重新编译即可。
>
> 「跨校邀请赛」页仍保留它自己的「体验身份」下拉：那是为了在同一台机器上分别
> 扮两家学校的角色，走完「发起邀请 → 对方接受 → 双方报名 → 锁定名单」的流程，
> 与上面的全局演示身份是两回事，互不影响。

## 二、怎么切换当前协会

协会是运行时的选择，不用改代码：

- 首页**右上角的协会切换徽章**（`association-switch` 组件）——点开选择
  匹克球 / 乒乓 / 羽球。
- 或在首页跨协会聚合的**公告 / 赛事列表**里，点一条属于别的协会的条目，
  会先整体切到那个协会再看详情。

切换后，同一账号显示的权限会跟着变——这正是下表要演的效果。

## 四、怎么演

- **演「协会负责人」**：把 `DEFAULT_CURRENT_USER_ID` 设为 `'u09'`，编译。
  在 pkb（默认协会）里他是管理员级的「协会负责人」——能审核入会、发布与管理
  赛事、发公告、任免学院负责人、更改会员等级分。切到 tt 或 bd，他立刻退回普通会员。
- **演「全局管理员 vs 协会负责人」的区别**：`u01` 与 `u04` 在 tt 里有效角色都是
  「管理员」，但只有 `u01` 是全局管理员。区别体现在个人主页上的
  **「协会负责人任免入口」只对全局管理员显示**（`u04` 看不到这个按钮）。
- **演「跨协会两种身份」**：设为 `'u04'`。在 tt 他是协会负责人，切到 bd 变成
  学院负责人，切到 pkb 是普通会员。
- **演「身兼两个协会的学院负责人」**：设为 `'u10'`。在 pkb 与 tt 都是学院负责人，
  在 bd 什么都不是。

## 五、各角色能做什么（权限速查）

判定口径见 `miniprogram/services/permission.js`，本地与云端一致。

**全局管理员（u01）** —— 全部功能，且不受协会限制：

- 审核入会申请、发放/管理账号
- 发布 / 修改 / 抽签 / 开始赛事，赛季重置
- 发布与下架公告
- 任免学院负责人、任免协会负责人（协会负责人这一项**仅全局管理员**可操作）
- 更改任意会员的当前等级分
- 代录 / 改判比赛、学院赛全套管理

**协会负责人（在各协会有效角色为「管理员」）** —— 在本协会内等同管理员：

- 管理本协会的赛事、会员与公告
- 任免本协会的学院负责人
- 更改本协会会员的当前等级分
- **看不到**「协会负责人任免入口」（那是全局管理员的专属）

**学院负责人（ROLE.STAFF）** —— 以**本学院**为界：

- 代签、代录本学院的比赛
- 提交本学院的学院赛名单、排阵

**普通会员** —— 报名、录入自己的比赛等日常功能，无任何管理入口。

## 六、改动须知

### 学院赛 S2 演示补充（2026-10-15）

学校身份页可切换 `demo_muc_college_leader`（民大学院负责人）。学校身份和协会
管理记录均为民大 **c02：民族学与社会学学院**，管理范围仅匹克球协会本学院。
该学院可用 u10（男）与 u24（女）排男单 / 女单；对阵学院可选 c05（历史文化学院），
使用 u07（男）与 u23（女）。负责人角色自身无性别字段，不作为上述单打排阵队员。

管理员可审核名单及替两侧排阵；学院负责人仅有本学院入口；普通会员不可提交名单。
这些操作使用 S2 独立内存库，不向旧 `mock.js` 的学院赛台账同步。

- 演示角色的登记在 `miniprogram/services/seed.js` 的 `ASSOC_ROLE_SEED`：
  `协会 id → { 会员编号: ROLE }`。没登记的协会 / 会员落回 `MEMBER_SEED`
  的角色或普通会员。
- `MEMBER_SEED` 里 `u01` 是全局管理员、`u02` 是只在默认协会成立的学院负责人；
  `scopeSeedRoles` 负责把非默认协会里的 `u02` 退回普通会员。
- 种子登记的角色是**底**，运行时在界面上的任免盖在其上：管理员把某位
  种子负责人「撤销」，撤销结果优先于种子登记生效（`roleStore`）。
- 把演示账号接进学校维度的是 `miniprogram/services/school-mock.js` 的
  `attachLegacyMembers`：改了 `MEMBER_SEED` / `ASSOC_ROLE_SEED`（增删会员或
  改组别负责人）后，这批账号在学校维度里的身份会自动跟着重算，无需另行登记。
- **pkb（默认协会）的角色只落在 u05 / u09 / u10**：端到端测试会在 pkb 里挑
  「经济学院 / 管理学院」等学院的普通会员当无权限夹具（见 `tests/referee.test.js`），
  若把负责人落在这些学院的人头上会令夹具失真。tt / bd 的角色不参与默认协会的用例，
  落在谁头上都无妨。

## 七、学校维度演示数据规模与三层差异性（2026-10-16 扩充）

学校维度（S2）的演示账号与演示内容**不在** `mock.js` 那一套里，而是由
`miniprogram/services/school-seed.js` 提供：

- 账号：`DEMO_ACCOUNTS`（两校共 8 位，见下表）；
- 内容：`DEMO_CONTENT_SPECS`（五个「学校 + 协会」范围各一份公告 / 赛事 / 比赛）。

两者都由 `school-mock.reset()` 默认挂进内存仓储，重启小程序即恢复种子。

### 7.2 三层差异性

1. **不同协会**：公告条数（5 / 4 / 3）、赛事数量（3 / 2 / 1）、标题与分类都不同，
   榜单也各是各的（乒乓榜上是 u04 等乒乓会员，匹克球榜上是 u03 等）。
2. **不同演示账号**：比赛分给不同会员，场次与等级分各不相同。例如北航内部
   `demo_buaa_member` 3 场、`demo_buaa_member_2` 3 场、`demo_buaa_member_3` 2 场、
   `demo_buaa_leader` 2 场、`demo_buaa_college_leader` 1 场——切身份即可对比。
3. **跨校**：北航不再是空态，也不是民大那套；民大身份读北航协会空间会被拒
   （范围隔离），换成北航账号才读得到。
