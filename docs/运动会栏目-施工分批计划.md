## 0. 全局约束（每批都必须遵守）

| 约束 | 具体做法 |
| --- | --- |
| 单一源码 | 共享逻辑只改 `miniprogram/` 源文件；改完执行 `npm run sync:cloud`；提交前看 `git status` 确认镜像已更新。直接改 `cloudfunctions/data/lib/` 会被下次同步覆盖（本项目已发生过一次） |
| 动作白名单 | 新动作必须同时登记在 `miniprogram/utils/school-actions.js` 的新分组与 `miniprogram/services/school-cloud.js` 的客户端门面；`tests/school-action-surface.test.js` 双向守护，多一个或少一个都红 |
| 集合注册四处 | 新增集合需同步：`cloudfunctions/data/src/school-repository.js` 的 `SCHOOL_COLLECTIONS`／`SCOPED_COLLECTIONS`；`miniprogram/services/school-memory-repo.js` 的 `KEYS`／`SCOPED`；`tests/helpers/memory-repo.js` 自动展开；契约测试自动覆盖 |
| 事务限制 | 云开发事务内**不能 where 查询**，只能确定性主键点读。所有占用计数、兼项声明、评分唯一键必须设计成可点读的确定性 ID |
| 事务预算 | 单事务写入上限按 200 条护栏（`TX_WRITE_BUDGET`）。报名"一次提交"在服务端必须**按项目组别拆分为多事务**并返回部分成功回执 |
| 规模上限 | 40 学院／120 项目组别／3000 参赛／100 裁判／50 并发录分。结果表、成绩表、名单必须分页；总榜需快照 |
| 与协会隔离 | 运动会不写入 `matches`、不产生 Elo、不复用 `manageCollege`、不挂 `schoolAssociation`。scope 用 `{ schoolId, meetId }` |
| 提交节奏 | 按用户要求减少提交次数：**三批合并提交**（见第 10 节），每批末尾写验收记录后再入库 |
| 设备边界 | 只做小程序，不做 PC 管理端（D100） |

## 2. B1　项目模板库与精度内核

**范围**：46 条项目模板 + 搜索归一 + 成绩数值精度校验，全部为纯函数，不依赖仓储与页面。

**产品依据**：4.1 全量启用（46 项）；精度表（计时 2 位、田赛截断到厘米、次数整数、评分 0–100 一位小数）；N17 不做手计时换算；N16 展示类不计分。

**新增文件**
- `miniprogram/services/meet-event-catalog.js`：模板元数据，每项含 `id`、`name`、`aliases`、`category`、`scoreType`（time／distance／height／count／score／versus）、`order`（asc／desc／bracket）、`entryForm`（single／group／team）、`defaultMembers`、`recommendedGroups`、`unit`、`defaultScored`
- `miniprogram/services/meet-measure.js`：`normalizeMeasure(scoreType, raw)`、`compareMeasure(a, b, order)`、`formatMeasure(scoreType, value)`

**关键实现点**
- 别名与归一：全角转半角、去空格、数字与中文数字互认（`100米`＝`一百米`＝`百米`）。
- 距离与高度：**截断**到 0.01 米（6.789→6.78），不四舍五入；计时保留 2 位、不足补零；次数整数；评分 0–100 且最多 1 位小数。越界一律拒绝，不静默截断到边界值。
- `entryForm`：`single` 1 人／`group` 固定 N 人／`team` 队伍；`group` 与 `team` 的 N 不写死在模板，由创建时填写（仅 `defaultMembers` 给建议值）。
- `versus` 类（**仅拔河**）不走数值比较，只返回赛制名次。团体跳绳归为「次数」型（按单位时间跳绳个数计），仍按队伍报名，不要误做成胜负赛。

**测试**：`tests/meet-event-catalog.test.js`——46 条完整性、id 唯一、别名命中、归一正确、截断方向（向下）、越界拒绝、排序方向区分、展示类 `defaultScored=false`、趣味类 `defaultScored=true`。

**完成定义**：`npm test` 全绿；无任何页面或云端改动；模板可被 B4 直接引用。

## 4. B3　学院部长授权模型

**范围**：新增学校级「学院部长」角色，单院一名，授予／撤销，撤权即时生效。

**产品依据**：D11 新增专门权限、D12 一名、D28 交接、B3 审计豁免但需有效状态、7.2 不复用 `manageCollege`。

**关键实现点**
- 授权记录含 `userId`、`schoolId`、`collegeId`、`status`、`grantedBy`、`grantedAt`。
- 授予入口仅校管理员及以上；同一学院已有有效部长时**拒绝授予并提示先撤销**（D12 一名的确定性处理）。
- 每次写操作在同一事务内重查授权有效性；撤权后旧部长立即失去写权限，已提交名单不删除。
- 独立判断函数 `canLeadCollegeMeet()`，不得复用 `school-permission.js` 的 `manageCollege`。

**测试**：普通学生／协会负责人写入被拒；跨院被拒；伪造 `collegeId` 被拒；撤权后立即被拒；同院第二人被拒；交接后新部长可写、旧部长不可写。

**完成定义**：权限测试全绿；未接入任何页面。

## 6. B5　报名主链

**范围**：学生提交意向 → 部长从候选人中筛选 → 按项目组别提交正式名单 → 校管理员审核 → 生效；截止后修改窗口；管理员代报。

**产品依据**：R10／R11／R12；D10 双层；D14 只能选已申请者；D16 学院冻结；D21 须审核；D22 按项目组别提交＋全部确认；D23 空项目即未报名；D24 全届统一窗口；D25 提交即停该院该项目意向；D26／D27 修改；D29–D39 限额／兼项／团队；D13 代报；B5 驳回回退；B6 可自审。

**动作**：`submitMeetInterest`／`withdrawMeetInterest`／`getMyMeetParticipation`／`getCollegeApplicantPool`／`saveCollegeEntryDraft`／`submitCollegeEntries`／`withdrawCollegeEntry`／`reviewMeetEntries`／`openMeetLateWindow`。

**关键校验（全部服务端）**
1. 学院归属取学籍 `collegeId` 并于提交时冻结；客户端传入一律不采信。
2. 资格：`profile.gender` 对男／女组；混合组不限（A6）。
3. 兼项：个人项目 ≤2；团体与接力不限；两人三足／三人板鞋计入个人额度（D35）。
4. 重复：同一项目组别只报一次（D37）。
5. 人数：队伍必须等于创建时设定的每队人数（D39，不设替补 D40）。
6. 限额：每学院每组人数／队数／组数（4.2 默认）。
7. 截止：服务端时间；截止后仅 D27 限时窗口，仍由部长提交。

**事务设计**
- 按项目组别逐个事务，单事务 ≤200 写；整院"全部确认"在 UI 是一次操作、服务端是多个批次，返回逐项成功／失败。
- 占用与兼项声明用确定性 ID 点读（`quotaKey`／`claimKey`），并发抢最后一名额必须只有一个成功。
- 撤回／驳回／换人原子释放；重复请求不重复释放。
- 驳回＝回退未提交：意向池重开、名额释放、"全部确认"标记失效（B5）。

**测试**：伪造 `collegeId` 被拒；跨院成员被拒；并发抢名额不超卖；重复提交不重复占用；兼项 3 项被拒；队伍缺人被拒；截止后无窗口被拒；驳回后意向池重开；代报可自审。

**完成定义**：12.2 全项通过；可完成一次完整报名。

**产品依据**：R06；D53 报名结束后赛程发布前须配齐时间与场地、裁判可随时指定、未指派不能开赛；D54 场地由发布者自由填写；D55 不做冲突检测；D56 不做检录；D59 裁判须本校有效用户；D60 项目统一分配＋场次覆盖；N4 只允许撤换已提交者。

**动作**：`saveMeetSession`／`publishSchedule`／`assignMeetJudge`／`removeMeetJudge`／`startMeetEvent`／`getMeetSchedule`／`getMyMeetJudgeTasks`。

## 8. B7　成绩录入与正式结果发布

**范围**：裁判录分、汇总平均、名次、无效判定、逐项目组别发布。

**产品依据**：R07；D61 可选单／多裁判；D62 3 人全员提交；D63 去最高最低后平均；D64 精度；D66 提交后汇总前可改；D67 撤换已提交者；D68＋A3 无效只在发布时判定；D73 竞赛排名；D74 各得名次分；D75 按实际名次计；D76 分组别汇总；D85 逐项目组别发布；D87／D88 无痕更正；N2／N13 只录最终成绩；N10 并列晋级。

**动作**：`saveJudgeScoreDraft`／`submitJudgeScore`／`previewMeetResults`／`publishMeetResults`／`revisePublishedResult`。

**关键实现点**
- 评分唯一键 `entryId + sessionId + judgeId`；revision 防旧草稿覆盖新提交。
- 汇总门槛：3 名裁判全部提交才可汇总；不足时拒绝并提示剩余人数（不做"缺一人按 0 算"）。
- 平均：去掉一个最高、一个最低后算术平均，保留 2 位小数四舍五入；3 人时等价取中间值。
- 排序：计时小者优先；距离／高度大者优先（截断后比较）；次数大者优先；评分大者优先；`versus` 用赛制名次。
- 名次：竞赛排名 1,2,2,4；并列各得该名次分（D74，总分不守恒）；录取前 8 名；人数不足按实际名次计（D75）。
- 无效／弃权／犯规：发布时标记，记「无成绩」，不参与名次、学院 0 分；**不得以数值 0 参与排序**（A3）。
- 发布幂等：重复发布不重复计分；更正为无痕覆盖，仅保留"当前生效标记"。
- 总裁判可发布与更正（B4），本届全部发布完毕或归档后自动撤销身份（N5）。
- 不录逐次试投；不比较次优成绩；跳高同高度并列（N13）。

**测试**：88/90/92→90；仅 2 人提交拒绝汇总；撤换未提交者被拒；计时小者优先；距离截断后比较；无成绩不排第一；并列各得名次分；重复发布不重复计分；更正替换不叠加；预赛不发荣誉。

**完成定义**：12.3 全项通过；可完成一个项目组别从录分到发布。

## 8.5 B8a　预赛晋级与赛制名次（2026-10-18 补做）

原计划把「预赛晋级」与「胜负项目赛制名次」留给后续批次，B7 只支持单场决赛与手填赛制名次。
本轮补齐，原因是这两项是 R06／R07 的正文要求，缺了它们「拔河」这类项目只能手填名次，
而手填与自动出表并存必然出现两套互相矛盾的名次。

- **晋级**：`advanceFromHeats` 支持每组前 N／总成绩前 N／混合三种口径；边界同分全部晋级（D47）。
  抽签随机但落库种子，可复核（D48）。
- **赛制**：单败淘汰与循环赛两种；名次由「输在哪一轮」或「胜场+相互战绩」推出，不再手填。
  双败与小组赛**未实现**，`configureMeetEvent` 当场拒绝，不按单败硬跑。
- **实现取向**：一场比赛就是一条 `sportsMeetSessions` 记录（`round=r1..r9`／`rr`），
  复用赛程、裁判、开赛与录分，不新增集合。
- **不变量**：预赛发布不计分（否则一个项目计两次分）；未打完的签表不能发布。

## 9. B8　学院积分、总榜与个人荣誉

**范围**：积分纯函数、学院总榜、个人荣誉、跨协会荣誉聚合、删除与更正的下游同步。

**产品依据**：R08／R13／R14；D72 团体×2；D76 分组别汇总；D77 无参与分；D79 只算已发布；D80 同分比金银铜；D81 展示字段；D82 参与范围；D83 不跨届；D89 全部有效正式名次；D90 全部正式报名成员；D92 不发学院冠军；D93 与 Elo 无关；D94 保留跨校历史；D95 展示姓名／昵称分场景；B3 删除连带撤销；N16 展示类不计分。

**动作**：`getCollegeStandings`／`getPublishedResults`／`getMyHonors`／`deleteSportsMeet`。

**关键实现点**
