# 运动会栏目 —— 流程完整性与界面合理性复查（2026-10-18）

## 1. 复查结论

**主链是通的，但有三处「服务端已实现、界面无入口」的断点，以及一处会把管理员卡死的重排死路。** 这三类问题不是样式瑕疵，而是用户在实际比赛现场走不下去：

| 级别 | 数量 | 一句话 |
|---|---|---|
| P0 断链 | 1 | 学院部长授权没有任何页面入口 → 学院自主报名（R11）整条路在界面上不可达 |
| P1 卡死 | 3 | 抽签后无法重排（提示让人「先删除场次」，但没有删除动作）；报名截止后界面仍显示可报名；草稿基本信息不能改 |
| P2 体验 | 5 | 补报窗口无入口、已提交项目仍可再点提交、未抽签也能进「批量派裁判」、开赛与录分不耦合、报名时间显示 ISO 原文 |
| P3 文案 | 3 | 「已分 3 枪决赛」、裁判空态无引导、学生能看到学院工作台入口 |

复查方式：逐页静态通读 7 个页面（JS + WXML + WXSS）、动作白名单与页面调用的集合比对、服务端前置条件与页面反馈的对照。**未做**真机与云端验收，凡涉及「真实环境是否可点」的结论都只到代码层面。

## 3. 问题清单

### F2（P0）学院部长授权没有页面入口 —— 学院自主报名主链在界面不可达

**证据**：`grantMeetCollegeLead` / `revokeMeetCollegeLead` / `listMeetCollegeLeads` / `getMyMeetCollegeLead` 都在 `miniprogram/utils/school-actions.js:96-98` 的动作白名单里，但 7 个运动会页面一次都没有调用（集合比对结果）。唯一的调用方是演示种子 `miniprogram/services/meet-seed.js:218`。

**后果**：`resolveCollege`（`meet-registration-service.js:103-118`）对非管理员一律返回「只有学院部长可以提交正式报名」。真实环境里没有任何人能成为学院部长，于是：

- 学院工作台对普通学院负责人是死路；
- 只能由校级管理员逐学院代报（D13 变成了唯一路径），R11「学院自主报名」形同未实现。

**建议**：详情页报名期增加「学院部长」管理面板（列表 + 任命 + 撤销），一院一名由主键保证，无需额外防重。这是本轮唯一必须补的链路。

### F4（P1）抽签后无法重排，且提示指向一个不存在的动作

**证据**：`meet-service.js:284-286` 在已排场次时拒绝改结构，提示「如需重排请先删除场次」；但全仓没有 `deleteMeetSession` / 撤销抽签的动作（grep 为空）。`meet-advance-service.js:108` 又拒绝重复抽签。

**后果**：组数、每组人数、跑道数填错一次（这在现场很常见：临时发现报名人数是 37 而不是 32），管理员只能改库。提示语还把责任推给一个点不到的按钮。

**建议（二选一，需产品确认）**：
1. 补 `resetMeetDraw`：仅当该项目「无场次成绩、无发布记录」时允许清空场次与 `heatDraw`/`bracket`；
2. 短期不实现的话，把提示改成「该项目已排场次，无法改赛制，请联系技术管理员」并写进操作手册。**当前文案必须改**，它是一句假承诺。

### F3（P1）报名截止后界面仍显示「可报名 / 报名中」

**证据**：服务端以时间判定窗口（`meet-registration-service.js:69-82`），届次 `status` 不会因为时间到自动流转；页面用 `status === 'registration'` 判报名期（`meet-detail.js:91`）。

**后果**：截止后学生仍看到「我要报名」，学院工作台仍标「可报名」，列表页仍写「报名中」；点了才收到「当前不在报名时间内」。

**建议**：`getSportsMeet` / 列表 DTO 增加服务端算好的 `registrationOpen`（复用 `registrationWindow`），页面据此显示「报名已截止」并禁用按钮；列表页状态标签在 `registration` 且窗口已关时显示「报名已截止」。

### F5（P1）草稿基本信息不能改

**证据**：`updateMeetDraft` 在动作白名单（`school-actions.js:88`），无页面调用；向导第一步只在「新发起」时出现（`meet-setup.wxml:11`）。

**后果**：名称、年份、起止日期、地点写错，只能删草稿重建；已勾选的项目配置全部重来。

**建议**：详情页草稿区加「编辑基本信息」，复用向导第一步（带 `meetId` 时预填并调 `updateMeetDraft`）。

### F1（P1）学院工作台「切换学院」是死路

**证据**：`meet-college.js:157-159` 的 `onChangeCollege` 只把 `needCollege` 置真、清空 `collegeId`，**没有拉取学院列表**；`colleges` 只有 `reload()` 失败分支（`:99-107`）才会填充。而 `meet-college.wxml:19-40` 的学院选择区块在列表为空时只显示「没有匹配的学院」，整个工作台被 `wx:elif="{{!needCollege}}"` 藏起来，页面上没有返回按钮。

**后果**：校管理员先落到自己学院，再点「切换学院」→ 空白页无出路，只能返回上一页重进。

**建议**：`onChangeCollege` 里先 `await this.loadColleges()`；空态补「返回本院」按钮。

### F6（P2）补报窗口（D27）无入口

**证据**：`openMeetLateWindow` 已实现（`meet-registration-service.js:600-618`），云门面与动作白名单齐备，页面零调用。

**后果**：报名截止后要补报只能改库 —— 而这恰恰是现场最常发生的事（漏报一个人）。

**建议**：详情页报名期/赛程期加「开放补报」入口（起止时间 + 说明「仍由学院部长提交」）。

### F7（P2）学院工作台对已提交项目仍给完整选人面板

**证据**：`closed: mine.length > 0`（`meet-registration-service.js:310`）只用于标签（`meet-college.wxml:61`「已提交」），点开面板（`:65-83`）照常可选人、可提交。服务端会以名额/重复规则拒绝。

**建议**：`closed` 时面板只显示「本院已提交，如需修改请先撤回」并隐藏提交按钮。

### F8（P2）未抽签的项目也能点「批量派裁判」

**证据**：`meet-schedule.wxml:103` 无条件渲染，此时 `item.sessions` 为空；提交按钮文案退化成「指派 N 人到 本项目全部场次」（`meet-schedule.wxml:141-143`），服务端无场次可派。

**建议**：`item.sessions.length === 0` 时按钮置灰 + 提示「请先抽签分组」。

### F9（P2）「开赛」与录分不耦合，届次状态可能永远停在「赛程已发布」

**证据**：录分与发布链路不校验 `session.status`（`meet-score-service.js` 无 `running` 判断）；只有 `startMeetEvent`（`meet-schedule-service.js:578-598`）会把场次与届次推到 `running`。

**后果**：管理员不点开赛也能录分发成绩，而详情页/列表页一直显示「赛程已发布」，与现实不符；现场也没人知道该点谁。

**建议（需产品确认）**：① 首次录分自动把场次与届次推到 `running`（推荐，少一步操作）；或 ② 录分前置校验 `running`，并在录分页提示「请先在赛程页开赛」。

### F10（P2）报名时间直接渲染 ISO 原文

**证据**：`meet-detail.wxml:25-27` 输出 `meet.registration.openAt`，值为 `2026-10-01T00:00`，截图里就是「报名：2026-10-01T00:00 至 2026-12-31T23:59」。

**建议**：DTO 出 `openAtText` / `closeAtText`（复用 `formatDateTime`），页面只渲染文本。同类检查：报名窗口的补报时间也应统一格式。

### F13（P3）学院工作台入口对所有学生在报名期可见

**证据**：`meet-detail.wxml:112-114` 的 `wx:if="{{isRegistration}}"` 不含角色判断。

**后果**：普通学生点进去得到「只有学院部长可以提交正式报名」，像是报错。

**建议**：详情 DTO 增加 `canLeadCollege` / `canManage`，入口按二者显示。

### F14（P2）抽签后学生仍可提交意向

**证据**：`submitMeetInterest`（`meet-registration-service.js:167-200`）未校验 `event.heatDraw`，而正式名单提交已校验（`:370`）。

**后果**：抽签后意向照收，部长永远提交不进去，意向池堆积无效记录。

**建议**：意向提交同样校验 `heatDraw`；详情页对已抽签项目隐藏「我要报名」。

### F11（P3）录分页文案错误：「已分 3 枪决赛」

**证据**：`meet-schedule.js:449` 三元两侧都写「已分」，`rounds==='final'` 时拼成「已分 3 枪决赛（人数 …）」。

**建议**：改为 `已分 ${n} 枪（人数 …）` / `已分 ${n} 组预赛（人数 …）`。

### F12（P3）裁判无任务时的空态没有出路

**证据**：`meet-score.wxml:15-17` 只有「还没有指派给你的场次」。

**建议**：补一句「请联系赛事管理员在赛程编排页指派裁判」，并给一个「返回详情」的轻链接。

### 其他小项

- 场次只有「开始」（`meet-schedule.wxml:163-173`），`endAt` 无输入，赛程页无法表达「这场 9:00–9:30」。
- `canPublishMeetResult` 接受 `chiefJudge`（`meet-permission.js:100`），但全仓无人传入 —— 总裁判（B4）是半成品，界面上也没有任命入口。
- 总榜表 `.meet-college{flex:1}` 无截断，超长学院名会把「总分」列挤窄（`meet-standing.wxss`）。

## 4. 界面一致性观察（非缺陷）

1. 七个页面的错误出口已统一为弹窗（`utils/meet-ui.js`），但**成功提示**仍是 toast + 页面顶部文字双份，长页面里顶部那段基本看不到，可考虑只留 toast。
2. 详情页、赛程页、录分页都用「行卡片展开编辑器」的同一套模式，交互一致，可保留。
3. 项目组别文案（男子/女子/混合）在 6 处各写了一遍三元表达式，建议收到 `utils` 里统一，避免以后改文案漏一处。
