## 三 关键口径

- **X-1 的差分为什么可以在事务外算**：入参台账是调用方刚读到的（`listByEvent`），事务内还有 `event.revision` 与 `match.revision` 比对，版本变了就要求刷新重试。版本没变 ⇒ 不需要改的场次在事务里也不会需要改。已生效（`status=active`）的比分一律不动（撤销走专门入口）。
- **X-2 阈值取 6 而不是 8**：服务端是每账号每秒 8 次读，贴着上限排队会让任何一次并发（轮询、用户点击、另一页预取）把整批推回被拒状态。写动作不排队——它们是用户逐个触发的，塞进队列会让「点下去没反应」变成新的体感问题。
- **X-3 为什么非学院负责人可以给空目录**：`recordOptions` 的学院映射只参与「学院负责人管本学院」这一档的行级判定；管理员与参赛者本人在 `canRecordScore` 里更早返回，不需要学院关系。这与 `getSchoolMatch`（H-4）同一口径，只是列表按批读。

## 四 踩坑与纠正

1. **测试桩缺方法**：`tests/helpers/memory-repo.js` 的云端桩没有 `liveScores.listByIds`，`listSchoolMatches` 一进这条路径就 TypeError。补齐并注明「桩缺方法 = 本地红/在线绿，最难查的一类差异」。
2. **节流器让会话用例变慢**：`app-session.test.js` 一连十几个用例各发 2~3 次请求，累计越过 6/秒窗口，下文那次 `getSchoolIdentitySession` 要等 1 秒，而用例只 `flush()` 一个 `setImmediate` 就断言 —— 2 条用例变红。修法是在 `beforeEach` 里 `pacer.reset()`（该文件本就复位 runtime / appSession / school-session 等模块级单例）。
3. **改了 `utils/constants.js` 忘同步镜像**：`cloud-lib-sync` 报 `utils/constants.js` 漂移。按守则「改 `miniprogram/` 纯模块必须 `npm run sync:cloud`」，补跑后 91 文件一致。
4. **X-15 的上限放在入队口而不是提交口**：放在提交口只会让失败晚一步（队列已经涨起来了），必须挡住「继续往队列里堆」这个动作。
