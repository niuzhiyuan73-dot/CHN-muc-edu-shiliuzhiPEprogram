## 三 关键口径

1. **赛程版本落在届次文档上，不用 `event.revision`。** `event.revision` 是**单项目**粒度，录分、裁判指派、报名都会碰它；发布赛程要判的是「时间与场地是否配齐」，因此需要届次级的一个版本戳。维护约定写在 `touchScheduleRevision` 的注释里：只改成绩或裁判名单的写路径不必调它。
2. **重复统计行「拒绝」而不是「合并」。** 合并需要定义优先级（谁盖谁），而这两条记录在业务上本就非法；拒绝能让提交方当场发现，也不给审核人留下「通过了一个我没看全的数」的口子。历史脏数据由读取侧 `uniqueRows` 保留第一条兜住——这与审核面板一直以来的 `find()` 行为一致。
3. **陈旧转校申请「作废」而不是「静默拒绝」。** 只报错会让那条申请永远挂在待办里、每次点开都失败；作废后申请人重新提交即可，`identityVersion` 在幂等重提时刷新，不会形成死结。
4. **`ratingsOnly` 必须带 `userIds`。** 没有指定人时它只会返回一堆没有 `points` 的行（看起来像「全校都是 0 分」），因此直接拒绝，而不是静默降级。
5. **单次读取超限「报错」而不是「截断」。** 截断的失败方式是「少了几条数据但界面正常」，比报错难查得多；需要更多数据就按 `_id` 游标续读。
6. **页面「可见性」用 `visible === false` 判，不用真值判。** 页面夹具与既有用例不一定走 `onLoad`，缺字段时应当按「可见」处理，否则会静默把所有轮询关掉。

## 四 踩坑与纠正

1. **改完 `school-membership-service.js` 后转校用例仍绿，但新用例红了。** 原因是 `handleSchoolRequest` 走的是 `cloudfunctions/data/lib/**` 镜像，忘了 `npm run sync:cloud`——正是施工守则第三条写的那种「改动静默不生效」。同步后 20 条全过。这条记在这里，因为它是本轮唯一一次「改了却没生效」。
2. **审计报告说的「已复现 101 次操作」，本轮按同一口径复现为 8 次。** 修复后事务只做「身份复核 + 运动会点读 + 版本比对 + 落库」，与项目数无关；`TX_PROBE=1` 可现场复算。
3. **`getSchoolMemberStats` 按人下推后先红了 `memberRatings.listByIds is not a function`。** 云端 `forScope` 的 `listByIds` 只挂在 `EVENT_SCOPED` 与三个身份集合上，`memberRatings` 不在其中；本地模拟端同理。两端各补一处，并把 `for-scope-contract.test.js` 的方法面快照同步——这条测试的意义正在于此。
4. **想过给 `top` 加「超过 100 就自动分批」，最后没做。** 分批要自己拼 `_id` 游标，放在适配器里等于把分页语义隐式化；改为「超限报错 + 仓储层显式 `readUpTo`」，责任边界更清楚。
5. **「查一个会员成绩」的全量列表路径没有改成新分页接口。** 见第七段：它的调用方（协会面板首页）本就要求一次拿到全员积分，改分页是产品形状变更，不在本次修复范围。
6. **`detail-stale-response.test.js` 第一版测不出问题。** 因为 `refresh()` 的第一个 `await` 之后才发请求，两次连发的刷新中第一次会被序号直接作废、压根不发请求——用例必须等一拍再发第二次，才是真正的「两个请求都在途」。
