## 一、系统定位与名称

- **对外名称：中央民族大学石榴籽体育管理小程序。**
- 定位：一个微信小程序，统一承载**校内多个体育协会**的会员、赛事、成绩与排名管理。
- 三个已知协会（乒乓球协会、羽毛球协会、匹克球俱乐部）是**首批使用者，不是上限**；
  协会清单**按 N 个设计**，后续能增加其它协会（如网球、排球等）而**不必改业务逻辑、
  不必改数据、不必整体重做**。
- 澄清：**新增协会本身是一次（小范围）前端改动**——要有人确定其名称、主题色、图标字
  （乃至品牌图），这本就落在代码里。我们**不追求**「管理员在后台自助建协会」，
  但要求新增协会时**只动协会注册表这一处**，不牵动数据与业务逻辑。
- 各协会**功能完全一致**，差异只体现在：协会名称/主题色等品牌，以及**按协会配置的少数规则默认值**。

> 现实约束（沿用第一版结论）：微信 AppID 与小程序名称一一对应，客户端**无法显示多个
> 不同名称**。小程序对外显示「中央民族大学石榴籽体育管理小程序」这一个名字，各协会的差异
> 在小程序内部体现（进入时选择协会、页内标题与主题色按协会切换）。

## 二、协会（可扩展）

| 编号 | 需求 | 说明 |
|---|---|---|
| A1 | 协会不写死数量，**可扩到 N 个** | 不能把「只有乒乓/羽毛/匹克球」硬编码进代码分支，也不能写死数量 |
| A2 | 协会信息至少包含：名称、简称、主题色、图标字/标识、状态 | 用于界面品牌与列表展示 |
| A3 | 协会可承载**各自独立的**规则默认值（赛制默认、Elo 锚点、防刷阈值等） | 见 §六 |
| A4 | 新增协会后，**全体已注册会员自动成为其成员** | 与 §三 的「注册即入全部协会」一致 |
| A5 | 协会定义随**代码**维护（注册表），用 `status` 标识启用/停用 | 停用以保留历史数据；不做后台自助建协会 |

**扩展方式（已定，见 §八 决策 3）：**
- **采用候选乙：协会作为配置**——一份代码注册表（`utils/associations.js`）列全部协会。
  新增协会 = 在注册表加一条并配品牌，随后发版。
- 放弃候选甲（协会作为数据 + 后台自助增删）：新增协会必然要有人定名称与配色，
  本就是一次前端改动；为低频操作建后台增删 + 数据集合不划算。

> 无论甲/乙，**业务代码都不得出现「三个协会」的分支判断**，一律按当前协会的 id 泛化处理。
> 乙 也要按 N 个写：加第 4 个协会时**不改业务逻辑、不改数据库、不改云端接口**，只动注册表。

## 三、用户与身份

### 3.1 账号与入会

| 编号 | 需求 |
|---|---|
| U1 | **一个微信 = 一个账号**（仍以 OpenID 唯一），注册一次即可 |
| U2 | **注册即自动视为参加了全部协会**（现有协会），无需逐个报名协会 |
| U3 | 未来新增的协会，**已注册会员同样自动属于它**（无需二次注册） |
| U4 | 实名信息（姓名、性别、学号、学院、手机号）**全局一份**，与协会无关 |

> 由此：**会员资格是全局的，不是按协会逐条登记的。** 这与第一版「(openId, 协会) 一账号」
> 完全不同——账号只有一份，协会维度只作用于**内容数据**（比赛/赛事/积分…），不作用于「是不是会员」。

### 3.2 身份与权限

| 身份 | 范围 | 权限 |
|---|---|---|
| **管理员** | 全局 | 各协会内容的审阅与设置；任免**各协会负责人**与学院负责人；可在全部协会间切换 |
| **协会负责人**（新增） | **本协会** | 管理本协会的**全部内容**（赛事、比赛、学院赛、公告、报名审核、赛季等），并可**任免本协会学院负责人** |
| **学院负责人** | **本协会内、按学院**（见 §八 决策 1） | 在授权学院范围内处理学院赛临场事务 |
| **会员** | 全局 | 参与比赛/赛事、查看榜单与公告、维护个人资料 |

- 角色分层：`会员 < 学院负责人 < 协会负责人 < 管理员`。
- **任免规则**：协会负责人由**管理员**任免（可一人负责多个协会）；学院负责人由**本协会的协会负责人或管理员**任免。
  协会负责人只能任免**本协会**的学院负责人，不能任免其它协会的人，也不能任免其他协会负责人。
- **全局角色**（会员/管理员）记在账号上；**协会角色**（协会负责人/学院负责人）是「某人在某协会」的
  属性，需要按协会记录（建模见 §七）。
- 现状参照：现有角色为 `MEMBER(0) / STAFF(1) / ADMIN(2)`（`utils/constants.js:16-26`），
  权限判定集中在 `services/permission.js`。本次需**新增「协会负责人」**这一档，
  并让「范围」从「全局 / 学院」扩展到「全局 / 协会 / 学院」。

## 四、数据归属与隔离

| 编号 | 需求 | 说明 |
|---|---|---|
| D1 | 内容数据按协会隔离，互不可见 | 比赛、赛事与报名、公告、学院赛（大场/名单/排阵）、实时比分、赛季、排行榜 |
| D2 | **各协会的积分独立** | 同一人在不同协会的赛季积分各算各的 |
| D3 | 等级分（Elo）同样按协会独立 | 建议与积分一致（同一个人在不同球类有各自等级分）；待 §八 决策 4 确认 |
| D4 | **学院名单三个协会共用**一份 | 同一所学校，同一份 26 所院系；不按协会各配一份 |
| D5 | 会员实名信息全局共用 | 姓名/性别/学号/学院/手机号一份，跨协会一致 |
| D6 | 协会之间不做跨协会联合榜单或跨协会比赛 | 各自独立闭环 |

## 五、功能清单（各协会一致，沿用现状）

1. **会员**：注册与实名、入会审核、会员名单、个人主页与资料编辑。
2. **个人赛**：录入成绩 → 对手确认 → 生效 / 驳回 / 撤销；弃权；裁判指定；防刷分。
3. **等级分与排行榜**：单打/双打池、男单/女单/双打榜、总榜/赛季榜。
4. **赛事**：发布、报名、签到、抽签（多种赛制）、名次录入、赛季积分结算。
5. **学院赛**：学院报名审核、抽签、大场/小项、排阵、实时与录分、学院名次。
6. **实时计分台**：逐球计分、撤销、定稿，横向屏幕。
7. **公告**：发布、下架、分类。
8. **赛季**：赛季重置（只清积分、等级分延续）。

> 以上全部为现有功能（`miniprogram/app.json` 共 27 页），**功能本身不改**，只是叠加「协会」维度。

## 六、比赛规则（保持不变）

| 编号 | 需求 |
|---|---|
| R1 | 赛制可选项保持 **11 / 15 / 21 分制**，局数 **1 / 3 / 5 局**（`utils/match-format.js:25,28`） |
| R2 | 判分规则保持：先到设定分且**净胜 2 分**为胜一局，无封顶（`match-format.js:101-127`） |
| R3 | 默认赛制保持 **11 分制 · 三局两胜**（`match-format.js:38`） |
| R4 | **「支持到 21 分封顶」含义 = 分制选项上限为 21，维持现状**；本次**不做**羽毛球 30 分封顶等新规则 |
| R5 | 学院赛小场维持现状（`utils/constants.js:1029`，11 分一局一胜） |

> 规则**可选值/默认值**后续可按协会配置（§二 A3），但本次不改判定算法本身。

## 七、关键流程

1. **首次进入**：选择协会（进入某个协会的首页）。选择会被记住；未选定前不进入业务页。
2. **注册**：填写实名信息提交 → 自动成为**全部协会**的会员（无需逐协会报名）→ 等待管理员审核。
3. **日常使用**：在所选协会内查看榜单、录入比赛、报名赛事、浏览公告。
4. **切换协会**：首页与「我的」页均提供入口；切换后**中间三个界面（排行榜/比赛/赛事）**随之切换。默认协会与各页展示范围细则见 **§十一**。
5. **管理员**：可在全部协会间切换；任免各协会负责人与学院负责人；管理各协会内容。（协会的新增/修改随代码发布，不在小程序内做。）
6. **协会负责人**：进入本协会的管理能力（发布赛事/公告、审核、抽签、赛季等），并可**任免本协会学院负责人**。
7. **学院负责人**：在本协会、授权学院范围内处理学院赛事务；由**本协会的协会负责人或管理员**任免。

## 十一、协会切换与界面展示范围（2026-10-10 追加确认）

> 本节是对 §七 关键流程第 4 条的细化与修订：切换入口从「我的」扩展到**首页**；
> 默认协会由「记住上次选择」改为「**取该用户比赛最多的协会**」。与本节冲突处以本节为准
> （§八 决策 6 的「记住上次选择」一并被本节取代）。

### 11.1 默认协会
- **每次进入小程序**，中间三个界面（排行榜 / 比赛 / 赛事）默认取**该用户比赛最多的协会**；**不记忆**上次选择。
- **并列最多时按注册表顺序取第一个**；该用户无任何比赛（或未登录）时回落默认协会 `defaultAssociationId()`（即 `pkb`）。
- 页面局部的切换（个人详情页 / 他人主页）进入时同样默认「**该页面对应用户**比赛最多的协会」——**他人主页取被查看者**、个人详情页取本人；退出即失效、不写回全局。

### 11.2 切换按钮的分布与作用域

| 位置 | 作用域 | 说明 |
|---|---|---|
| **首页** | 全局 | 仅切换**中间三个界面**（排行榜/比赛/赛事）的数据范围；首页自身不变 |
| **我的** | 全局 | 同上；「我的」自身内容不随切换变化 |
| **个人详情页**（点自己头像进入） | **页面局部** | 只切本页展示，**不影响页面外任何内容** |
| **他人主页**（点他人头像进入） | **页面局部** | **整页内容**随切换 |

- **首页与「我的」用同一个切换组件。**

### 11.3 首页展示
- 公告、近期赛事**跨全部协会聚合展示**：**各取 3 条**、**按时间统一排序**、**每条标注所属协会**。
- 点某条公告/赛事进详情时：若其所属协会 ≠ 当前全局协会，则**自动整体切换到该协会**
  （**中间三个界面也一并切换**），再进入详情。
- 首页「看全部赛事 ›」入口跳转到**当前全局协会**的赛事 tab（不做跨协会合并列表页）。

### 11.4 「我的」页展示
- **移除所有随协会变化的内容**：
  - 等级分（男/女单·双打 Elo）→ 移入**个人详情页**；
  - 赛季积分 → 移入**个人详情页**（各协会不同）。
- **保留**：会员卡（头像/昵称/入会日等全局信息）+ **全部荣誉（跨协会聚合）**。
- 会员卡的**角色徽标只显示全局身份**（会员 / 管理员），**不显示协会角色**（协会负责人 / 学院负责人按协会各异，故不在此卡呈现）。
- 会员卡原「赛季积分」标签**直接去掉**（赛季积分已移入个人详情页）。
- **荣誉聚合呈现**：汇总数字（赛事数 / 冠军数 / 前三数）为**各协会相加**；下方**按协会分组**列出名次明细；
  **未参赛的协会不显示**。

### 11.5 个人详情页（点自己头像进入）
- 承接「我的」移出的全部按协会变化内容（等级分、赛季积分），连同现有分数卡 / 走势 / 逐场 / 交锋 / 搭档。
- 页内自带切换按钮，**仅切本页**，默认「本人比赛最多的协会」。

### 11.6 他人主页（点他人头像进入）
- 页内自带切换按钮，**整页内容**（等级分 / 走势 / 交锋 / 搭档 / 赛事名次等）随切换，只看**该人在不同协会**的数据。

### 11.7 品牌
- 首页头图与导航标题用**中性名**（中央民族大学石榴籽体育管理小程序）。
- 中间三个界面、个人详情页、他人主页**按协会套品牌**（导航标题 + 主题色）。
- TabBar 文案保持通用词不变。

### 11.8 游客 / 未登录
- 未登录时**仅首页可见公告**；其余界面一律显示「请登录」；**任何界面都不显示切换按钮**。
- 「我的」页保留现有登录引导（游客卡 + 登录按钮），即其「请登录」形态。

### 11.9 实现取向
- 跨协会聚合读（首页公告 / 赛事、我的荣誉）**先在客户端合并各协会数据**，暂不新增云端聚合接口。
