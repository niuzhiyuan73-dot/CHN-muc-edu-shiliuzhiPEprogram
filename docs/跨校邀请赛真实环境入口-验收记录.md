日期：2026-10-16。用户口径原话：

## 二、排查结论：云数据源下的入口现状（用户怀疑成立）

**结论：底层链路是通的，卡住的全是前端门控。** 两处门控，一处比一处隐蔽：

| 功能 | 云数据源下的入口 | 根因 |
|------|------------------|------|
| 跨校邀请赛 | **完全没有入口** | 双保险：`pages/profile/profile.wxml` 上 `wx:if="{{isMock}}"` 让整张卡不渲染；`profile.js` 的 `onGoSchoolExchange` 里还有一道 `if (facade.isMockNow()) return;` |
| 转校 | 有入口，但很隐蔽 | 「我的 → 学校身份 → 切换学校 → 提交转校申请」走得通；但首页的学校切换器在云端被 `index.js` 的 `loadSchoolScope()` 提前 return 清空，而「浏览外校」才是发现转校的自然路径 |

**为什么说链路是通的**（不是坏在数据层）：

- 协议 2 的 `cloudfunctions/data/src/core/school-request.js` 已合并三个 handlers，
  学校身份注册 13 个动作（含 `applySchoolTransfer` / `reviewSchoolTransfer` /
  `cancelSchoolTransfer`）、邀请赛注册 16 个动作；
- `miniprogram/services/school-cloud.js` 的客户端清单与之一一对应；
- 两个页面自身（`school-exchange.js` / `school-identity.js`）**都没有** mock 门控。

另有三个文案破绽一并修掉：

- `profile.wxml` 邀请赛副标题写死「模拟邀请与报名」；
- `school-exchange.wxml` 顶部写死「本地模拟体验」；
- `school-exchange.wxml` 的「切换体验身份」下拉在云端会是个**空下拉**
  （`getDemoActors()` 云端返回 `[]`）——空下拉比不显示更糟。

## 三、本批改动

### 3.1 解开入口门控

| 文件 | 改动 |
|------|------|
| `pages/profile/profile.wxml` | 邀请赛入口卡去掉 `wx:if="{{isMock}}"`；副标题按数据源分流（`isMock ? '民大与北航 · 本地模拟邀请与报名' : '与受邀学校交流 · 不计入校内等级分'`） |
| `pages/profile/profile.js` | `onGoSchoolExchange` 去掉 `isMockNow()` 早退，只留 `wx.navigateTo`。理由写进注释：协议 2 云端走得通，这里再拦一道就成了「点不动的卡片」，比没有入口更糟 |
| `pages/index/index.js` | `loadSchoolScope()` 删掉「云端提前 return 并清空 schoolList」的分支：目录与会话本就由 `school-cloud` 与协议 2 提供，真取不到（未登录 / 接口报错）时既有的 `catch` 照样把控件收起 |
| `pages/school-exchange/school-exchange.js` | `data` 与 `reload()` 里补 `isMock: identity.isMockNow()`，只用于两处展示口径 |
| `pages/school-exchange/school-exchange.wxml` | 「本地模拟体验 · 」改为按数据源分流；「切换体验身份」下拉加 `wx:if="{{isMock}}"` |

### 3.2 预置演示数据与补演示账号

`services/school-seed.js` 新增两块（都由 `school-mock.reset()` 默认挂库）：

**（1）两场跨校邀请赛** —— `demoExchangeDocs(now, schoolNames)`，产出赛事 / 邀请索引 /
报名 / 对阵四张表：

| 赛事 | 赛制 | 状态 | 报名 |
|------|------|------|------|
| 民大北航匹克球交流赛（报名中） | 单败淘汰 | `signup` | 2 人（民大 1 + 北航 1） |
| 民大北航匹克球邀请赛（已抽签） | 小组赛+淘汰（2 组 / 每组出线 1） | `drawn` | 4 人（两校各 2） |

三个关键决定：

- **开赛时间钉在 2030-03-01 / 2030-03-08**：报名与锁名单拿**真实当前时间**与
  `startTime` 比大小，而演示内容锚点 `DEMO_CONTENT_NOW`（2026-03-01）早已过期，
  照它加偏移得到的开赛时间会被服务端当「已开赛」拒掉。用固定但远在未来的常量，
  既走得通又仍是常量（每次 `reset()` 结果完全一致）。
- **签表由引擎现算**：调 `exchange-plan` 的 `planExchangeDraw` / `planExchangeMatches`
  （纯函数，与云端 `drawExchangeEvent` 同一段代码），随机种子固定 `20261016`。
  手写签表迟早与引擎分叉，而分叉的演示数据最误导人。
- **四张表同一次产出**：避免「赛事在、名单不在」的半截演示（名单为空时对阵里只剩编号）。

**（2）一条待北航审批的转校申请** —— `demoTransferApplication(now)`，挂在
`schoolMembers` 上（与真实 `applySchoolTransfer` 同表同形状，`transferFrom='muc'`、
`status='pending'`、`revision=1`）。

**（3）补一位民大会员** —— `demo_muc_member_2`（民大 c01 / 女 / 学号 `TEST007`），
加在 `DEMO_ACCOUNTS` 末尾：

- 北航有会员二 / 三，民大原只有一位会员，跨校邀请赛**凑不出「两校各两人」的四人签表**；
- 同时它承载上面那条转校待办，而 `demo_muc_member` 保持**干净**——于是
  「当场提交转校申请」与「审批转校申请」两条路径各有一个专属账号，不必二选一。

`services/school-mock.js` 的 `DEMO_ACTORS` 末尾追加 `{ id: 'demo_muc_member_2',
label: '民大会员二' }`（**追加**，不动既有下标——页面与用例按下标选身份）。

### 4.1 新增用例

`tests/exchange-entry.test.js`（+7）：

- 云数据源下「我的」页仍能进邀请赛页（`onGoSchoolExchange` → `navigateTo`）；

`tests/exchange-demo-data.test.js`（+8）：

- 两场赛事的状态互补、边界字段（`inter_school` / `unrated` / `singles` / 两校名额）
  与**开赛时间在未来**；

  `signupCount` 与报名条数同源；
- 对阵由引擎现算：签位与报名名单同批人、两组都排出来、全部停在「待比赛」；
