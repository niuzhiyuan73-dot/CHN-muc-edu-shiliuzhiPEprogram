# 登录与会话 S2 统一验收记录

日期：2026-10-16。项目收尾顺序第 3 批（B3：登录与会话统一）。
接手代码基线：`aa67ea0`；提交后 hash：`9016e85`。

## 本批完成

- 新增 `services/app-session.js`：客户端统一会话存储。事实来源只有 S2 的
  `getSchoolIdentitySession`；为尚未迁移页面派生**兼容用户对象**的单一适配入口
  （`buildCompatUser`），能力档位 → 旧栈数值角色的映射、学校身份状态 → 旧栈数字
  状态的映射都只写这一处，不伪造 `_id / role / college`，也不把兼容角色当授权依据。
  每次写入递增 epoch，异步响应凭它丢弃过期回写。
- `getSchoolIdentitySession` 补发本人账号展示字段（`realName / gender / avatarUrl /
  platformStatus`）——登录页据此分清「没有账号 / 账号停用 / 账号正常」，兼容视图
  不再需要第二次取数。
- 登录页三步走改走 S2：一键登录 = 会话读取；新会员注册 = `registerSchoolAccount`
  （凭微信身份开平台账号，幂等且不改写实名）→ `applySchoolMembership`（登记学号 /
  学院，落学校身份申请）。表单按两段模型重排：真名 / 性别 / 昵称 / 头像归账号，
  学号 / 学院归学校身份，学院候选来自目标学校的目录（每校独立），手机号不再收集。
- 旧栈 `login / registerMember` 不再被登录页调用；新注册不向旧栈台账写任何记录
  （有回归测试守着）。
- app.js 启动校正、切协会重解、演示身份切换、退出全部收敛到统一会话：
  - `refreshSession` 以 S2 会话校正本地缓存；明确「无账号」才清，网络故障保留；
  - `refreshViewerRole` 按当前协会重解能力（不换人）；
  - `switchDemoActor` 切完身份后刷新本人学校、浏览范围、成员状态、能力与兼容
    视图；未登录只校正浏览范围，不自动登录；
  - `clearUserInfo` 同时清统一会话与学校范围（home/current），退出后不再残留
    上一人的「我的学校」与旧能力。
- 模拟端新增「当前微信身份」：`simulateNewWechat` 把身份拨到尚无账号的 OpenID，
  身份 / 协会空间 / 跨校交流三套客户端按同一身份解析，可完整演示「新微信号 →
  注册 → 申请 → 待审核」闭环；登录页提供「演示：模拟一个新微信号」入口。
  `setDemoActor` 同时接受 u01–u24 与 demo_* 身份。
- 跨校交流页切换演示身份统一经 `app.switchDemoActor`（无 app 实例的测试环境
  退回只切 mock 身份）。
- 竞态防护：登录 / 提交各自带请求序号，退出与重新加载使旧响应作废；页面加载
  与登录再以 app-session 的 epoch 挡一层跨入口竞态。慢请求不回写、退出后晚到
  响应不恢复登录态、提交中重复点击不重复开户 / 申请，均有测试。

## 权限与范围检查

- 兼容角色 / 状态只用于展示：能力档位来自 `getSchoolIdentitySession` 的服务端
  布尔量，旧数值 `role/status` 由单一适配器推导，任何写路径仍以 S2 服务端判定为准。
- 登录、切身份、切协会都以「一次操作开始时绑定范围」的客户端取会话，异步等待后
  不重读全局 scope；会话写入受 epoch 保护。
- 退出后学校范围复位（home/current 清空），「看得到外校名单」不会残留为「管得了」。
