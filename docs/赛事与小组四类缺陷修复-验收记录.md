## 一、用户报的四件事与根因

| # | 用户现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 赛事详情点「报名」显示**赛事不存在** | 跳转方 `encodeURIComponent(eventId)`，微信开发者工具 / 真机把 query **原样透传**（未解码）；读路径早已用 `routeIdCandidates` 探测两种候选，**写路径没有**——页面实例上留的还是路由原值，报名 / 取消 / 开赛 / 抽签 / 代签 / 确认比赛 / 名次结束全部拿未解码编号去写，服务端按主键查不到 | 装载器把探测命中的**真实编号回传**（`loadSchoolEventDetailView` / `loadSchoolEventPlacementView` 的 `eventId`），页面采纳后再读写与跳转（跳转只编码一次） |
| 2 | 已创建并结束的赛事**持续显示 0 人** | 两处叠加：① 演示种子 `demoEventDocs` 把 `signupCount` 写死为 0，且从不产出报名记录；② 读端展示人数直接用主记录计数器，计数器与报名台账一旦分叉就长期显示错值 | ① 种子按赛事补 `signups` 规格并生成 `eventSignups`，`signupCount` 与报名条数同源；② 读端展示人数以**报名台账**为准（台账为空才回退计数器，并与已录名次人数取大），名额判断仍在写入事务内用计数器串行化 |
| 3 | mock 里**最终名次显示编号而不是姓名** | 名次行姓名走「报名名单 → 会员档案」这条链；演示赛事没有报名记录 → 名单为空 → 档案表为空 → `buildResultRows` 回退把 `userId` 当昵称 | ① 种子补齐报名记录（与名次同源）；② `loadEventParts` 取档案时把 `results` 里的 userId 也带上，历史数据只有名次没有名单时同样解析得出姓名 |
| 4 | 协会空间发布小组后**无法删除整个小组**（成员全部移除后小组仍在） | `association-group-service.js` 只有 `archiveAssociationGroup`，**没有删除接口**；面板也只有「查看名单 / 退出 / 编辑 / 归档」四个按钮 | 新增 `deleteAssociationGroup`（软删除）+ 面板「删除」按钮与二次确认 |

## 二、连带修好的同类问题（用户要求「核对整个赛事部分」）

学院赛（`cev:` 编号，**自身含 `%3A` 嵌套**）是同一个缺陷类的重灾区：装载器探测出了真实编号却
没有回传，六个页面的写路径全部拿着路由原值去写。

- `school-college-view.js`：六个装载器回传真实编号（`eventId` / `tieId` / `matchId`）；
- 页面：`college-entry`（提交名单）、`college-entry-review`（通过 / 退回）、
  `college-event-detail`（抽签 / 开赛 / 大场开赛 + 四个跳转）、`college-lineup`（提交排阵）、
  `college-match`（录分 / 确认 / 撤销 + 跳实时计分）、`college-placement`（名次结束）；
- 顺带修掉三处「未解码环境下读不到」的缺口：排阵页大场列表按 eventId 候选序列取、
  「我交没交过」按解析后的 tieId 比对、名次页候选学院名单改用解析后的 eventId 查。

修复前后对照（`.review/repro-college-page.cjs`，真实 mock 栈六页全链路）：
详情页 `page.eventId` 由 `cev%3Amuc%3A…` 变为真实编号，`onDraw` 由「学院赛不存在」变为
「抽签完成，名单已锁定」，`onStartEvent` 由「学院赛不存在」变为正常开赛；名单 / 审核 / 排阵 /
小场 / 名次六页写操作全部落库成功。

## 三、接口与数据模型变化

1. **新增动作** `deleteAssociationGroup({ groupId, expectedRevision })`：
   - 返回 `{ ok, groupId, deleted, message }`，`deleted` 标记本次是否真的改了数据；
   - 软删除（仓储 `forScope` 只有 list/getById/set/insert/update，且历史活动与审计都按
     groupId 指向小组，物理删会留下悬空引用）：组文档 `status='deleted'` + `deletedAt/deletedBy`、
     `memberCount` 归零、`revision+1`；组内 ACTIVE 关系转 `REMOVED`；释放组名占位（同名可重建）；
     写 `deleteAssociationGroup` 审计；
   - 幂等：不存在 / 不属本范围 / 已删除 → `ok(deleted:false)`；版本不符 → 「小组已修改，请刷新后重试」；
   - 已删除小组从列表消失，`get/update/archive/add/remove/leave` 一律按「小组不存在」处理；
     归档的小组同样可删。附带修复：同 `requestId` 撞上「已删除」旧组时真正重建
     （沿用同一 groupId、`revision` 续号，避免审计键互相覆盖）。
2. **新增常量** `GROUP_STATUS.DELETED='deleted'`；`school-cloud.js` 客户端动作白名单补
   `deleteAssociationGroup`（该文件是显式白名单，不加则云端数据源下方法不存在）。
3. **DTO 口径**：`eventSummary` 的展示人数允许由读端按台账算好传入（`eventSummary(doc, mySignup, signupCount)`）；
   `listSchoolEvents` / `getSchoolEvent` 的人数、`quotaText`、`signupCount` 三者一律以报名台账为准。
   与此同时，「名额满没满、能不能报」改用**占用数 = 主记录计数与台账取大**
   （`occupiedSignupCount`），读端能力与写入端拒绝用同一把尺子，写入成功时把占用数回填主记录。
   **展示要准、名额要稳**：只按偏小的计数会超员，只按台账会漏掉计数虚高的水位。取消仍是
   「计数 − 1」（保守，绝不放超员）。
4. **演示数据契约**：`DEMO_CONTENT_SPECS` 的每个赛事条目新增 `signups`；`createSchoolDemoContent()`
   多返回一张 `eventSignups` 表（`school-mock.reset()` 按键名自动挂表，无需改动）；
   规模变为 18 公告 / 9 赛事 / 39 比赛 / **38 条报名**。已结束赛事的报名记录必须覆盖 `results`。
5. **页面实例口径**：赛事详情、名次页、六个学院赛页面在装载成功后把探测出的真实编号落回
   `this.eventId / this.tieId / this.matchId`，之后所有读写与跳转都用它。
6. 顺手改正 `school-mock.js` 里「演示内容（公告 / 赛事 / 比赛）」的过期注释（现在还有报名表）。

## 五、未完成 / 说明

- 没有真实云端与真机验收；不推送远程、不部署、不改真实数据（`CLOUD_ENV_ID` 仍为空）。
- 工作区里 `DEFAULT_CURRENT_USER_ID` 曾被本地改成 `u01`（管理员演示）：**经用户确认已改回 `u06`**
  （文档与既有 2516 条用例的约定）。要演示管理功能（发赛事 / 删小组）按 `docs/mock演示账号.md`
  改这一行，或走跨校交流页的演示身份切换。
- 删除小组是**软删除**：组与成员关系不再有效，训练 / 赛事按该组限定报名的资格随之失效
  （它们只认 ACTIVE 关系）；历史活动、审计与报名快照保留。这是有意的口径，若产品要求
  「删组后历史活动仍按原名单开放」需另开一批。
- 演示数据里默认身份（u06）没有报名任何「报名中」的赛事，首页「我报没报」与「点一下报名」
  都保留可演示的初始态；已结束赛事的名单与名次同源。
- **已知边界（接口不可达，不改）**：若某场赛事的报名记录全部是「已取消」而名次里仍有人
  （只有导入 / 手工改库才造得出来——`finishSchoolEvent` 会拒绝给已取消者录名次），
  详情会显示「0/N 人」与名次表并列。展示以「有效报名」为准是有意选择，宁可显示 0 也不虚报。
- 取消报名仍是「计数 − 1」：在计数虚高的历史数据上，占用数可能比真实活跃报名多 1
  （偏保守：少放一个人进来，绝不超员）。这是事务内读不到台账的取舍，理由写在
  `cancelSchoolEventSignup` 的注释里。
- 旧栈（协议 1）的赛事页面仍保留原有行为，本轮只改学校维度（协议 2）的活跃入口链。
