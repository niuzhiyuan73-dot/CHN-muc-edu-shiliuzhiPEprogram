## 前置条件与开放范围

S2 全站业务隔离、S3 存量迁移和真实云联调尚未完成，用户也确认目前没有云环境。因此本轮仍只开放民大、北航的本地模拟体验，不上传云函数、不初始化真实学校或学生数据。

共享逻辑已纳入云端镜像、仓储已预留集合，但**没有注册跨校云 action**。云数据源下页面和服务门面均拒绝进入模拟流程，不静默改用本地数据。学校身份协议仍独立运行。

平台管理员路径在服务层已实现（平台管理员可抽签、指定裁判、确认比分与名次），但演示身份里没有平台管理员，当前只由双方校管理员走通。

## 已完成

- 主办学校管理员或该项目协会负责人创建单打邀请赛，指定参加学校、时间、地点、总名额和各校名额。
- 受邀学校自己的管理员或协会负责人接受/婉拒邀请。主办方不能替外校接受，普通会员不能处理邀请。
- 受邀校接受后，该校有效会员可自行报名、取消；服务端决定报名者和代表学校，忽略前端伪造的 userId/学校字段。
- 总名额和每校名额在同一赛事文档事务内维护。重复报名幂等，重复取消只释放一次；同校多人和跨校多人抢名额都不超额。
- 邀请处理完毕、至少两校各有一人报名后，主办方可以锁定名单，状态转为 `ready`。锁定复核报名版本、人数与参赛身份。
- **抽签（本轮）**：锁定后由平台管理员或双方校管理员抽签，**支持与校内赛完全一致的六种赛制**
  （单败淘汰 / 循环赛 / 小组赛+淘汰 / 循环赛+淘汰 / 双败淘汰 / 小组赛+双败淘汰），无种子纯随机；
  落位只由写入的随机种子值决定，可复算。赛制规则不另写一套，全部复用校内赛的
  `services/format-plan.js` + `services/draw.js`，邀请赛只做「跨校记录 ↔ 引擎视角」的形状翻译。
- **指定裁判（本轮）**：每场单独指定，仅未确认比分的比赛可改派；裁判必须是参赛学校的有效会员。平台管理员或双方校管理员可指定。
- **比分确认（本轮）**：平台管理员、双方校管理员、或该场指定裁判可确认；**未指定裁判时，该场双方参赛者也可**。比分需为非负整数且不能打平，服务端判胜并推进签表——下一轮对阵在双方都确定时才生成。状态转为 `drawn`。
- **名次确认（本轮）**：全部比赛确认后，平台管理员或双方校管理员确认名次，状态转为 `finished`。名次按赛制分流推导：单败按落败轮次（冠军第 1，第 r 轮落败者名次为 `size/2^r + 1`，同轮并列）；循环赛按积分表（`computeStandings`）；双败按败者组淘汰轮次倒排。确认前先做一次「全量投影已全部确认比分」的闸门，只要还有未生效场次就拒绝确认。
- 每一步写入都与审计一同提交或回滚。创建请求具有幂等编号，失败重试不新建第二场赛事，同编号不同内容会拒绝。
- 参赛名单和名次只返回昵称、代表学校及用户标识，不返回学号、手机号或学校身份记录引用。
- 两校共用一份正式赛事主记录，通过邀请索引找到赛事，没有为每个学校复制一场比赛。

各动作的乐观并发都以赛事 `revision` 为准：读快照后事务内复核 revision，变化即要求刷新重试，避免并发写覆盖。

范围限制：共享服务支持 2–8 所学校、最多 128 个总名额；当前页面仅针对民大/北航两校提供创建表单。比赛项目固定为当前试点的匹克球单打。邀请一旦接受或婉拒，本轮不支持反向修改；抽签在已有比赛确认生效后不可重抽。裁判指派、签到、退赛/撤销等更细流程见文末。

## 权限矩阵

| 动作 | 允许身份 |
| --- | --- |
| 创建赛事 / 接受或婉拒邀请 / 锁定名单 | 主办校或受邀校的管理员、协会负责人 |
| 抽签 / 指定裁判 | 平台管理员、双方校管理员 |
| 确认比分 | 平台管理员、双方校管理员、该场指定裁判；未指定裁判时该场双方参赛者 |
| 确认名次 | 平台管理员、双方校管理员 |

普通会员只能报名/取消并与自己的比赛交互，不能抽签、指定裁判或确认名次。

## 数据隔离与不计分保证

本轮采用独立集合：

| 集合 | 数据 |
| --- | --- |
| exchange_events | 唯一主赛事，主办学校/项目、邀请状态、各校名额与计数、报名状态、赛制与参数、签表、名次、版本 |
| exchange_invitations | 某校某项目指向主赛事的索引，不复制赛事业务事实 |
| exchange_signups | 赛事 + 用户的唯一报名，代表学校、昵称快照、学校身份引用与报名状态 |
| exchange_matches | 赛事签表内的单场比赛，轮次 / 阶段 / 小组 / 位次、双方、比分、胜者、裁判、状态 |

比赛键 `xm:<eventId>:<middle>:<slot>`，其中 `<middle>` 无小组时为 `r<轮次>_<阶段>`、有小组时为 `g<小组>_r<轮次>_<阶段>`；轮次从 1 起、位次从 0 起。阶段与小组必须入键——双败的胜者组/败者组/总决赛、小组赛的 A 组/B 组同轮次都是不同的比赛，只靠「第几轮第几场」分不开（本项目无线上历史数据，编号变形安全）。

这是对原需求中“在 events 增加 eventScope”的实施调整：旧 events 的读取与回放还没有全面加入学校边界，当前直接复用会有被旧流程读取和计分的风险。独立集合保持一份主赛事，也能让新旧业务互不干扰。以后接入赛程时沿用这个边界，不把交流赛复制进校内流水。

服务端固定 `eventScope = inter_school`、`ratingPolicy = unrated`、`matchType = singles`，不接受客户端更改这些字段。所有本轮动作都不写旧 events、matches、memberRatings；回归测试在抽签、比分确认、名次确认之后逐一验证这些原有集合不发生变化。

报名人数、抽签对阵、名次与最终交流战绩都不是校内 ELO/积分，也不进入校内定级样本、比赛场次和积分回放。

## 赛制（2026-10-16 扩展：与校内赛同一套口径）

创建赛事时可选六种赛制，与普通赛事完全一致；参数项按赛制显隐，服务端只保留该赛制用得到的参数：

| 赛制 | 值 | 参数 | 阶段序列 |
| --- | --- | --- | --- |
| 单败淘汰（默认） | `single_elim` | 三四名 | main（+ 季军赛） |
| 循环赛 | `round_robin` | — | 单循环积分表 |
| 小组赛+淘汰 | `group_knockout` | 组数、每组出线、三四名 | group → main（+ 季军赛） |
| 循环赛+淘汰 | `round_robin_knockout` | 每组出线、三四名 | 单循环 → main（+ 季军赛） |
| 双败淘汰 | `double_elim` | 总决赛重赛 | wb → lb → gf（可选 gf.reset） |
| 小组赛+双败淘汰 | `group_double_elim` | 组数、每组出线、总决赛重赛 | group → wb → lb → gf |

**实现纪律：赛制规则不另写一套。** `services/exchange-plan.js` 只是薄适配层——抽签落位交 `services/draw.js`
（`planGroupDraw` / `drawBracket`，与校内同一套）、对阵推进交 `services/format-plan.js`
（`planStageMatches` 的 `full` 全量投影）、名次推导交 `derivePlacements`、撤销前的依赖自查交
`findDependentMatches`。因为通用引擎认的比赛记录形状（`draw.eventMatchKey` 编号、数字
`MATCH_STATUS`、`winner: 'A'/'B'`、`teamA` 数组）与跨校集合的形状不同，中间只加
`engineMatchOf`（跨校记录 → 引擎视角）与 `exchangeDraftOf`（引擎对阵 → 跨校记录）两个纯投影函数做映射，
存储契约两边都不改。邀请赛比分只有一个整数，折成「一局」交给积分表算，保留净胜分。

**两条推进路径。** 引擎同时支持「逐轮补入」（`includeExisting = false`，新建路径，只回答还缺哪几轮，
既有行为不变）与「全量投影」（`full = true`，交出此刻应当存在的全部轮次）。邀请赛的详情页走全量投影，
所以改签表（撤销比分后重录）能刷新下一轮对阵；具体策略是「已生效不覆盖 / 对阵未变保留 / 换人则
`revision + 1` 刷新」，绝不把已有比分重建成待比赛。

**名次确认前的收官闸门。** `placementsFromExchange` 先跑一次全量投影，只要有一场 `status !== 'active'`
（即还有没确认比分的场次）就直接返回「还有比赛未确认比分，名次尚未确定」，不给出可确认标记。

**边界不变。** 赛制扩展没有放松邀请赛的隔离纪律：仍写独立集合、仍 `ratingPolicy = unrated`、
仍不写校内 `events` / `matches` / `memberRatings`，也不影响校内 ELO 与积分。项目仍固定单打。

## 本地操作步骤

1. 编译小程序，进入“我的 → 跨校邀请赛”。
2. 选择中央民族大学，体验身份切到“民大校管理员”。
3. 填写未来的日期、地点、总名额和每校名额，选择赛制（默认单败淘汰；小组赛类会多出组数与每组出线，双败类会多出总决赛重赛），点击“创建并发出邀请”。
4. 切学校为北京航空航天大学、身份为“北航校管理员”，打开赛事并接受邀请。
5. 切为“北航会员”报名；再切回民大与“民大会员”，打开同一场赛事报名。
6. 切回“民大校管理员”，点击“锁定报名名单”。页面显示“名单已锁定”。
7. 再次点击“抽签生成对阵”，按所选赛制出现首轮比赛（单败下两校各两人时为两场半决赛；小组赛类为分组对阵并带“第 N 组”前缀；双败类先出胜者组）。
8. 逐场填写比分并“确认比分”；如有裁判，可先“指定/更换裁判”，此后由裁判或管理员确认。每轮确认完自动推进下一轮（单败到决赛；双败依次进败者组与总决赛）。
9. 全部确认后点击“确认最终名次”，页面按赛制列出名次（单败为第 1–3 名、半决赛落败者并列第 3；循环赛与双败按积分/淘汰轮次排序）。

学校身份页与邀请赛共用学校模拟仓储。原演示账号与旧校内比赛数据不受体验身份切换影响。演示数据仅存在内存中，重启恢复种子数据。
