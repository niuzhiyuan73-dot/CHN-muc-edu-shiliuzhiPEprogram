## 三 关键口径

1. **N 取 20、阈值取 40。** 20 球覆盖一局（11 分制最长的一局约 20 球），「刚打完那一局」整局仍在窗口里，撤销制胜球不受影响；40 的缓冲让折叠次数与**局数**同阶而不是与球数同阶。
2. **只在局边界折叠。** 切点必须落在「新一局开局」（小分 0:0、不在抢七），`base` 才只需要局数 / 盘数这几个整数；半局切点会多出一个会漂移的字段。
3. **重算必须从 base 续算，不能只合并摘要。** 「局数过半即整场结束」的判定要看折叠前已赢的局；只把两段进度相加会漏判 `finished`，比分 3:0 的比赛会停在 2:0 继续打。
4. **定稿必须拼两段。** `toOfficialScores` = `folded.games/sets/tiebreaks` + 窗口内打完的。只算窗口那份会把前面的局整段漏掉，正式比分从 3:1 变 1:1 且不报错——这是本项最容易踩且最难发现的一处。
5. **撤销口径（旧 → 新）。** 旧：「可一直撤到开场」；新：「最近一局 + 最近 20 球，折不到开场」。窗口撤空时分数停在折叠水位，不是回到 0:0。
6. **幂等窗口同步收窄。** 判重靠扫 `rallies` 里的 `rallyId`，折叠掉的编号查不到。取舍见「未完成及原因」。
7. **一次单局特别长（> 40 球且无边界）不折。** 折叠被推迟到下一局结束，窗口临时变长——有界（等于单局长度），不影响正确性。

## 四 踩坑与纠正

1. **`bestOf` 只有 1 / 3 / 5。** 夹具先写成 7 局制，`formatOfRecord` 判为非法 → 回落默认 3 局制 → 需要 2 局就结束，折叠前缀一重算就 `finished`，用例连红两次。测试里的赛制必须取 `BEST_OF_OPTIONS` 内的值，否则测的是兜底默认值。
2. **折叠与定稿的耦合是隐藏的。** 第一版只想改 `applyRally`，写到 `toOfficialScores` 才发现它也是从 `rallies` 全量重算——不合并 `folded` 就会静默少报局数。此项是本轮唯一「不修就会产出错数据」的连带改动。
3. **撤销文案不能沿用旧句。** 窗口撤空与「一球没判」在数据上同形（`rallies` 为空），只有 `folded.count` 能区分。沿用旧文案会让裁判以为比赛没开始。
4. **三轮复核发现 3 处「表述与代码不一致」（均非代码缺陷）**：
   - 第二轮/第三轮把 `association-training-service.js:981` 记为「按 `trainingId` 内存过滤」，实际那一处是**赛季重置的全量扫描**（按签到状态筛，范围本就该是全协会，且该函数尚未接入重置流程）。第三轮 X-8 真正改的是详情页那一处。
   - 第一轮「4 处 `colleges.find` 改 Map」之后，`school-rank-service.js:764` 与 `meet-college-lead-service.js:190` 仍是 `find`：前者按学院名解析（学院表 ~30 行，每页几十次比较），后者是单次查找。量级不构成读放大，**保留**并登记在此，避免下轮再当新问题报一遍。
   - `avatar.js` 的「扩展名白名单」实现是**把未知扩展名纠偏成 `jpeg`**，不是拒绝上传。对 `wx.chooseMedia` 给出的图片临时文件足够（也在云存储侧限额之内），但若要求「非白名单直接拒绝」，需产品确认交互文案后再改。

## 八 回归与反向验证

- **折叠不改比分**：逐球判下去（64 / 80 球）后，派生字段与「同一串球从开场全量重算」逐字相同；整场结束的判定与终局比分也相同。
- **定稿不少报**：`toOfficialScores` 与全量重算的每局比分逐项相等；网球另比盘分与抢七。
- **续算点自洽**：`folded.games.length === base.gamesA + base.gamesB`——不等就说明切在了半局中间。
- **撤销仍正确**：折叠后撤一球，状态等于「同一串球去掉最后一球」的全量重算；一路撤到窗口空会停住，分数停在折叠水位。
- **幂等窗口**：最近一球命中、首球（已折叠）不命中——把「窗口收窄」钉成显式行为，而不是留给人猜。
- **三轮复核**：13 项第三轮修复 + 第二轮 12 项 + 第一轮 8 项逐条核对落地位置与口径（见 §四 第 4 条的偏差登记），未发现新缺陷；`npm test` 全量连跑两次均为 0 失败。
