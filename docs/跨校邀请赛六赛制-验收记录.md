# 跨校邀请赛扩到六种赛制 验收记录

日期：2026-10-16（B8 之后）。用户口径原话：

> 「帮我把给跨校邀请赛加上其他的赛制，和普通比赛一样」

**基线**：本批之前邀请赛固定「单打单败淘汰」（`exchange-plan.js` 自己写了一套走签表的代码），
普通赛事/个人赛事/学院赛则共用 `services/format-plan.js` + `services/draw.js` 的赛制派发器。
本批把邀请赛拉到同一把尺子上。

## 一、结果

邀请赛现在支持与校内赛**完全一致**的六种赛制，参数项按赛制显隐：

| 赛制 | 值 | 参数 | 阶段序列 |
|---|---|---|---|
| 单败淘汰（默认） | `single_elim` | 三四名 | main（+ 季军赛） |
| 循环赛 | `round_robin` | — | 单循环积分表 |
| 小组赛+淘汰 | `group_knockout` | 组数 / 每组出线 / 三四名 | group → main（+ 季军赛） |
| 循环赛+淘汰 | `round_robin_knockout` | 每组出线 / 三四名 | 单循环 → main（+ 季军赛） |
| 双败淘汰 | `double_elim` | 总决赛重赛 | wb → lb → gf（可选 `gf.reset`） |
| 小组赛+双败淘汰 | `group_double_elim` | 组数 / 每组出线 / 总决赛重赛 | group → wb → lb → gf |

**边界一个字没松**：仍写独立集合（`exchange_events` / `exchange_invitations` / `exchange_signups` /
`exchange_matches`），仍 `eventScope=inter_school`、`ratingPolicy=unrated`、`matchType=singles`，
仍不写校内 `events` / `matches` / `memberRatings`，不影响校内 ELO 与积分。项目仍固定单打。

## 二、实现关键

### 1. 不重写引擎：`exchange-plan.js` 改成薄适配层

原实现自己走签表，六种赛制各写一套必然与 `format-plan.js` 分叉。现在这一层只做**翻译**：

| 职责 | 交给谁 |
|---|---|
| 抽签落位 | `services/draw.js`（`planGroupDraw` / `drawBracket`，与校内同一套） |
| 对阵推进 | `services/format-plan.js`（`planStageMatches`，`full` 全量投影） |
| 名次推导 | `format-plan.derivePlacements` |
| 撤销前依赖自查 | `format-plan.findDependentMatches` |

中间只加两个**纯投影函数**做形状映射（存储契约两边都不改）：

- `engineMatchOf`：跨校记录 → 引擎视角。跨校是 `playerA` / 字符串 `'pending'|'active'` /
  `winner` 直接记 userId；引擎要 `teamA` 数组 / 数字 `MATCH_STATUS` / `winner: 'A'|'B'`。
  邀请赛只录一个整数比分，折成一局（`scoreA: [11]`）交给积分表算，保留净胜分。
- `exchangeDraftOf`：引擎对阵 → 跨校草稿。

导出的仍是原函数名（`exchangeMatchKey` / `planExchangeDraw` / `planExchangeMatches` /
`placementsFromExchange` / `findExchangeDependents`），服务层改动很小。

### 2. 通用引擎加「全量投影」，默认行为不变

`planNextRound` / `planStageMatches` 原本只回答「**还缺哪几轮**」（逐轮补入），
改签表时需要「**此刻应当存在的全部轮次**」。于是新增开关：

- `draw.planNextRound({ includeExisting = false })`：`true` 时首轮与已排轮次也交出；
- `draw.planPlacement(..., includeExisting = false)`：季军赛两场同理；
- `format-plan.planStageMatches({ full = false })` 并透传到
  `planSingleKnockout` / `planDoubleElim` / `planGroupPhase`。

默认值保证既有 200+ 用例零回归——新建路径行为一字未变。

复合赛的 `full` 分支有个坑：`planGroupPhase(..., true)` 一旦有小组轮次就返回，转段信号会失效。
现在是先用**非全量**的 `planGroupPhase` 问一句「小组赛是否已走完」，没走完才只交小组轮次，
走完了就 `groupRounds.concat(knockout.rounds)`。

### 3. 记录键必须带阶段与小组

`xm:<eventId>:<middle>:<slot>`，无小组时 `<middle> = r<轮次>_<阶段>`，
有小组时 `g<小组>_r<轮次>_<阶段>`。

理由：双败的「胜者组第 2 轮第 1 场」与「败者组第 2 轮第 1 场」是两场不同的比赛；
小组赛的 A 组第 2 轮与 B 组第 2 轮也各是一张桌子。光靠「第几轮第几场」根本分不开。
键只由位置决定、不含人与时间，抽多少次都复算得出。单败的键因此也变了形——本项目无线上历史数据，安全。

### 4. 重录策略：绝不把已有比分重建成待比赛

`planExchangeMatches` 三分支：**已生效（`active`）不覆盖 / 对阵未变保留 / 换人则 `revision + 1` 刷新**。
撤销半决赛后重录、晋级者换人时，决赛不会挂着上一个晋级者。

### 5. 名次确认前先过「收官闸门」

`placementsFromExchange` 先跑一次全量投影，只要还有一场 `status !== 'active'`，
直接返回「还有比赛未确认比分，名次尚未确定」，`getExchangeEvent` 据此给出
`canConfirmRanking = false` 与 `rankingHint`。

**为什么必须有这道闸门**：小组赛还有轮次没排时，`derivePlacements` 会误判「积分表算完了」。

### 6. 赛制参数收敛在服务端

`normalizeExchangeFormat(payload)` 只保留该赛制用得到的参数：非法赛制回落 `single_elim`；
循环赛不留 `groupCount` / `advancePerGroup`（恒为单组）；只有双败类存 `gfReset`。
`formatConfig` 并入创建指纹与赛事记录，`summary` 下发 `format / formatLabel / groupCount /
advancePerGroup / bronzeMode / placementMode / gfReset`。

### 7. 页面与云端

- `pages/school-exchange`：新增赛制 picker 与按赛制显隐的参数项（组数 / 每组出线 / 三四名 / 重赛）；
  切换赛制一律清 `requestId`；赛事列表与详情显示 `formatLabel`；对阵行改为
  `{{item.groupText}}{{item.stageText}}第{{item.round}}轮：…`。
- 云端：`exchange-service` / `exchange-plan` 是共享库纯模块，`npm run sync:cloud` 后
  自动进 `cloudfunctions/data/lib/services/`，协议 2 的邀请赛动作无需改动。

本批新增用例：

- `tests/exchange-service.test.js`（+6）
  - **赛制与参数随创建落库**：循环赛不留 `groupCount`；非法赛制回落 `single_elim` 且列表显示「单败淘汰」。
  - **双败淘汰**：胜者组 3 场 / 败者组 2 场 / 总决赛 1 场，名次排到第 4。
  - **循环赛**：四人共 6 场；刚开始只有 2 场（一轮打完才放下一轮）；没打完拒绝确认名次；
    打完后按积分表出 1–4 名。
  - **小组赛+淘汰**：首轮全是 `group` 且带组号；打完后自动接上 `main`；名次含小组名次。
  - **双败不满四人拒绝抽签**：提示「至少需要 4 名」。
  - **六赛制端到端总闸门**：六种赛制逐个「创建 → 抽签 → 逐场录分 → 确认名次」，
    四人全部拿到名次、有冠军、名次连续无空洞、不超出人数；并核对中文名（`EVENT_FORMAT_LABEL`）。
- `tests/exchange-page.test.js`（+1）：赛制可选、参数项按赛制显隐（选双败后三四名消失 / 重赛出现）；
  按所选赛制创建后抽签，首轮全是小组赛且两组都排出了对阵。

> 单败淘汰的季军是**并列第 3**（既有口径），所以端到端闸门断言的是「名次连续无空洞」而不是「互不重复」。

## 四、未完成 / 说明

- **跨校统一实力口径**仍未做：邀请赛仍 `ratingPolicy=unrated`，不混排两校校内 ELO。
  这是产品口径问题，不是技术债。
- 没有真实云端与真机验收（B9 已确认不在范围）。
- 邀请赛项目仍固定单打（`matchType=singles`），未开双打。
- 「六种赛制与校内赛一致」目前由**共享同一份派发器 + 同一批纯函数测试**保证；
  若日后改校内赛制规则，邀请赛会自动跟随（这是本批刻意选择的结构，不要退回各写一套）。
