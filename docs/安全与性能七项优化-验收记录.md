## 三 关键口径

七项技术现象成立，风险采用六项中风险、一项低风险。学号问题存在本校有效身份限制；OpenID 泄露不等于能够伪造微信上下文。

账号编号采用不可逆且稳定的摘要，支持注册幂等；旧编号必须迁移全部关联数据。迁移工具不连接云端，不自动导入、删除或覆盖备份。维护后客户端需重载，不能重放迁移前缓存的创建请求。

成员目录不引入另一份会籍状态副本：数据库关联当前 `school_members` 与 `users`；仅冗余账号姓名的归一搜索值与排序键。跨校、停用及离校状态仍以权威文档判定。任意子串搜索和关联排序仍可能扫描本校候选，优化主要减少应用层全量文档、网络传输和深翻页 RPC。

## 四 踩坑与纠正

- 数据库字符串排序与 JavaScript UTF-16 排序在部分非 BMP 字符上不同。增加 UTF-16 十六进制排序键，并保留原游标内容，防止昵称包含 emoji 时跨页错序。
- 只比更新时间和人数不足以识别同一毫秒内的一退一进；成员变动递增球队版本，候选集合过期时重新读取。
- 两条旧云端模拟测试的查询桩不支持数组点路径，最初导致个人统计为空；补齐多键路径匹配后，原有预期保持不变，未放宽业务断言。
- `acceptance-audit.cjs` 的 F5 仍直接调用已下线的 `revokeSchoolMatch`。改为经实际协议入口确认旧动作被拒绝，并逐条比较比赛与下游签表未改变。
