## 四、阻断级 2：云端仓储与本地 mock 的接口不一致

这是本次审计**最值钱**的结论：整类「本地 mock 全绿、切到真实云环境即 100% 失败」的缺陷。
`CLOUD_ENV_ID` 目前为空，所以它被完全掩盖着。

### 4.1 探针实测（本人复现）

用 `tests/school-cloud-repo.test.js` 同款 db 桩建云端仓储，与内存仓储逐项对照：

| 调用 | 云函数仓储 | mock 仓储 |
|------|-----------|-----------|
| `tx.events.set(...)` | **undefined → TypeError** | function ✅ |
| `tx.matches.set(...)` | **undefined → TypeError** | function ✅ |
| `tx.eventSignups.set(...)` | **undefined → TypeError** | function ✅ |
| `tx.ties.set(...)` | **undefined → TypeError** | function ✅ |
| `tx.announcements.set(...)` | **undefined → TypeError** | function ✅ |
| `tx.liveScores.set(...)` | **undefined → TypeError** | function ✅ |
| `repo.seasons.getById(...)` | **undefined → TypeError** | function ✅ |
| `repo.schoolMembers.set(...)` | function ✅ | function ✅ |

实测输出（节选）：

```
cloud tx.events.set(...)  -> 抛错: tx.events.set is not a function
mock  tx.events.set(...)  -> 成功
cloud repo.seasons.getById -> 抛错: cloud.seasons.getById is not a function
cloud forScope.events.set   : function | mock forScope.events.set : undefined
```

### 4.2 根因（代码对照）

- `cloudfunctions/data/src/adapters/cloud-repo.js:126-266` 里，`events` / `matches` /
  `eventSignups` / `collegeEvents` / `collegeEntries` / `ties` / `lineups` / `announcements`
  只定义了 `list / getById / insert / update`，`liveScores` 只有 `getById / insert / update`，
  `seasons` 只有 `get / set` —— **都没有 `set` / `getById`**。
- `cloudfunctions/data/src/school-repository.js:22-28` 只给 `SCHOOL_COLLECTIONS`（学校、协会、
  学院、会员、等级分、邀请赛、协会空间、`pairCounts`）补 `getById/set/list`，上面那批**不在名单里**。
- 共享服务（`miniprogram/services` → 镜像到 `cloudfunctions/data/lib/services`）普遍写
  `ctx.repo.transaction(async tx => { await tx.events.set(...) })`，而 `cloudfunctions/data/index.js:78`
  传进 `ctx` 的是**原始 repo**（不是 `forScope(...)` 的结果），所以 `tx` 就是上面那批缺 `set` 的仓储。
- mock 侧「恰好」齐全：`miniprogram/services/school-memory-repo.js:4-15` 的 `KEYS` 里每个集合
  都统一生成 `getById/set/list`。

### 4.3 为什么 2606 条测试一条都没抓到

因为 **school 域测试全部注入内存仓储**（`createSchoolMemoryRepo`），唯一的真适配器测试
`tests/school-cloud-repo.test.js` 只覆盖了 `forScope` 的范围隔离，没有覆盖基础集合的 `set`
与 `seasons.getById`。这属于「测试跑的是另一套仓储」的经典盲区。

**补救**：新增一条**从服务代码静态推导仓储调用面**的契约测试 —— 扫描 `lib/services/*.js`
里所有 `tx.<集合>.<方法>(` / `repo.<集合>.<方法>(` 的调用，断言云端与 mock 两套仓储都提供该方法。
这样以后任何一侧少一个方法都会立刻红灯，不必靠人去比对。

### 4.4 其它不对称（本人复现）

- `forScope()` 的返回值：云端提供 `list/getById/set/insert/update`，mock **只有 `list`**。
  当前业务只对 `forScope(...)` 用 `list`，所以尚未暴露；但两端契约不一致是隐患。
- 云端事务内禁止整表读（`cloud-repo.js:132,153,173,192,204,215` 主动抛错），mock 不禁止 ——
  这是有意设计，但会让「mock 里顺手写的 `tx.X.list()`」在云端炸掉。
- `rankings` 在云端有 `get/set`、mock 的 `KEYS` 里没有它；学校路径不使用该集合（属遗留死代码）。

### 4.5 客户端门面漏接口（本人复现）

`miniprogram/services/school-cloud.js` 的 `forAssociationSpace` 手写了 80 个动作名，
**没有** `listSchoolEventSignups`；而 `miniprogram/services/school-event-view.js:441`
（详情页与名次页共用的 `loadEventParts`）会调 `api.listSchoolEventSignups({ eventId })`。
云数据源下 `association-space.js:23` 返回的正是这个门面 → `api.listSchoolEventSignups is not a function`。
服务端其实**已注册**该动作（`lib/services/school-event-service.js:888` 导出），mock 门面也有 ——
只有云端门面漏写。

## 五、逻辑缺陷

### 5.1 【高】终态赛事仍可被改写（三处同源）

共同的形状：**子实体（比分 / 比赛 / 大场）的写动作只看自身状态，不看父赛事是否已进终态**，
于是「已结束」的赛事事后还能改台账，而对外公布的名次（`results`）已经冻结 —— 两者分叉。

| 位置 | 缺的检查 | 后果 |
|------|----------|------|
| `services/exchange-service.js:350-388` `revokeExchangeScore` | 不看 `event.status`（只挡 `match.status !== 'active'`） | 赛事 `finished`、名次已确认后仍能撤销比分，甚至把胜负翻过来 |
| `services/exchange-service.js:540` `submitExchangeScore` | 只挡 `canceled`，不挡 `finished` | 同上，已结束的赛事仍能重录比分 |
| `services/school-match-service.js:533-620` `revokeSchoolMatch` / `transition` | 不看父赛事 `status` | 已结束的赛事仍能撤销/确认比赛 |
| `services/school-event-service.js:800-842` `finishSchoolEvent` | 不要求签表打完（手工录名次是**有意**允许的） | 一场没打就结束之后，再确认比赛会经 `advanceSchoolEvent` 在**已结束**赛事上补出一场新比赛 |
| `services/school-college-service.js:854-916` `forfeitCollegeTieLeg` | 不看 `collegeEvent.status` | 已结束的学院赛仍能记弃权并推进大场 |

**本人复现**（跨校那条，读码即可确认）：`exchange-service.js` 的 `drawExchangeEvent:450`、
`confirmExchangeRanking:571,587` 都显式挡了 `finished`/`canceled`，`revokeExchangeScore`
与 `submitExchangeScore` 恰好漏了这一道。子代理另外给出了三处各自的探针输出，结论一致。

**统一口径**：终态（`finished` / `canceled`）**不可变** —— 需要更正时另开「赛事修订」能力，
而不是让已公布的名次悄悄漂移。

### 5.2 【中】11 个文件的写路径没有 try/catch

`miniprogram/services/school-cloud.js:11` 在信封 `ok:false` 时会 `throw`（无 `wx.cloud` 时也 throw），
而这些页面的写路径是「`setData({submitting:true})` → `await` → `setData({submitting:false})`」，
中间没有 `try/catch`：一旦云端调用失败，`submitting/acting` 永久停在 `true` —— 按钮一直转、
无红字无提示，只能退出页面重进。

对照：`live-score.js`、`school-exchange.js`、`school-identity.js`、`login.js`、`profile-edit.js`
等都已正确包了 `try/catch`，属**漏做**而非约定。

（已注：业务性拒绝走的是 `{ok:false}` 分支，页面有正常提示；本条专指网络/基础设施故障。）

### 5.3 【中】同一 openId 存在两套 `users._id`（代码对照，未端到端复现）

- 旧协议：`cloudfunctions/data/src/core/idempotency.js:96` `memberKey(openId) = 'u_' + digest(openId)`
- 协议 2：`cloudfunctions/data/lib/utils/school.js:170` `schoolAccountKey(openId) = 'acc:' + encodeURIComponent(openId)`
- 读取端 `cloud-repo.js:140-144` 用 `.where({openId}).limit(1).get()`，**无 `orderBy`**

同一微信身份若既走过旧注册、又走协议 2 注册，会留下两条 `users` 文档；此后解析到哪条不确定，
可能出现「注册过却进不去」「榜单里没有我」。**修法涉及数据迁移口径，属待产品确认项，本批未动。**

### 5.4 【中】28 个内部辅助函数被注册成 action

`cloudfunctions/data/src/core/school-space-handlers.js:18-22` 与
`miniprogram/services/school-mock.js:25-29` 都用
`Object.entries({...11 个 service}).filter(([, v]) => typeof v === 'function')` **全量注册**，
把 `loadSeason` / `defaultSeason` / `buildDirectory` / `medalOf` / `isEventDoc` 这类内部函数
也暴露成了可调用动作（客户端从不声明它们）。后果：攻击面扩大；ctx 优先的辅助函数被按
`(payload, ctx)` 调用会 `TypeError`，纯谓词函数返回非信封值。

### 5.5 【中】性能

- `lib/services/school-actor.js:64,111` 的 `buildDirectory` 读 `users.list()`（**整表**，云端按 100 条翻页读全量），
  而它几乎在每次判权时被调用。
- `lib/services/school-member-service.js:68`、`association-member-service.js:43`、
  `association-training-service.js:350,394` 在循环里逐条 `getById`（N+1）。

### 5.6 【低】

- `pages/index/index.js:283-288` 的 `onOpenMember` 是死方法（模板没绑定它），且读的是没人给的 `dataset.userId`。
- `pages/login/login.js:469`、`profile-edit.js:154` 把服务端异常统一说成「网络异常」，丢掉真实原因。
- `cloudfunctions/data/index.js:76` 的路由启发式：旧协议请求只要顶层带 `schoolId` 就会被判为协议 2 而报「请升级客户端」。
- `lib/services/auth.js:251` 函数体内 `require('./index.js')`，该文件在 `lib/services/` 下不存在（当前不可达）。
- 首页学校切换器解除门控后，云端会先加载整套 mock 演示数据（`school-mock.js:179` 在 require 时 `reset()`），
  **只是启动开销，不串数据**。

### 9.1 做法上与原计划的两点不同

- **④ 没有逐页补 `try/catch`，而是从根上修。** 项目本来就有 `utils/write.js` 的
  `guardWrite` / `isWriteAction` 机制（旧门面 `services/index.js:108,157` 早已套用），
  只是学校维度的三个门面（`school-cloud.js` / `association-space.js` / `exchange.js`）
  没套上。本次补了 `SCHOOL_WRITE_ACTIONS` 名单与 `isSchoolWriteAction`，在 `requestFor`
  里对写动作套 `guardWrite`、读动作放行——**一处修好 11 个页面**，且将来新增写动作若
  漏登记，会被 `tests/school-write-guard.test.js` 当场点名（「非读动作必须都在名单里」
  是双向校验的）。逐页打补丁反而是错的方向：二十来个页面、三十个写接口，手工补必然漏。
- **② 的 `forScope` 两端不对称**（云端有 `set`、mock 只有 `list`）**未一并改**：
  目前无调用方踩到，属隐患而非现网缺陷，留作记录（见 §6）。
