## 二、关键口径

| 项 | 决定 | 理由 |
|---|---|---|
| 可计算数字 | **多处同步 + 自动校对**（不做单锚点引用） | 读者在不同文档都要能直接看到数；靠 `doc-audit` 兜住漂移 |
| 文档分类 | A1 数字校对 / A2 定点更新 / B 产物 / C 冻结 | 「同步所有文档」若不分层，第一件事就是去改历史验收记录 |
| 自动修改 | **只做半自动**：audit 全自动，替换逐条人工放行 | `42 页` 与 `主包 5 + 分包 37` 是同一事实两种写法，全自动替换会误伤 |
| skill 存放 | 项目级 `.workbuddy/skills/`，随代码入库 | 约定是项目专属，用户级 skill 交接后看不到 |

**明确不做**：Skill 里不写 Elo / 抽签 / 赛制等业务规则。它们已由 `utils/` + 176 个测试文件守着，写进 skill 会变成第二份会分叉的真相。

## 三、踩坑与纠正

1. **`--only-frozen` 不触发检查**。初版把 `doFrozen` 只认 `--frozen-check`，反向验证时「改了历史验收记录」竟然返回 0 —— 检查器恒绿等于没有。修正为两个参数都认。
2. **`git -c core.quotepath=false` 必须带 `git` 前缀**。写成 `execSync('-c core.quotepath=false ...')` 时 Windows 把 `-c` 当命令，报「不是内部或外部命令」。
3. **中文路径被转义导致冻结检查全失效**。不加 `-c core.quotepath=false` 时 `git status` 输出 `"docs/\344\272\244..."`，所有中文文件名模式都匹配不上。本项目文件名全是中文，这条不修则整个冻结检查是装饰。
4. **新建验收记录被误判为「修改冻结文件」**。冻结的本意是「已存在的历史不许回写」，新建是本批正常产物。已改为只检查 `M/D/R` 状态，`??` 不拦。
5. **数字漂移比预想的多**。人工只看出 4 类，脚本抓出 13 条：分包数 37→38、packageMember 9→10、action 分组 101→119 都是手工漏掉的。
