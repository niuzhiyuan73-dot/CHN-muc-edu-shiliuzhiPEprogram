## 0. 本轮确认与校正

你的三个决定：

1. **乙** —— 学院负责人在赛事详情里点「为本学院报名」，系统负责建队，不需要先手动建队再报名。
2. **一院一队够了**（不需要「法院一队 / 法院二队」）。
3. **按建议来**（工作台赛事页仍显示学院赛并带标签；杯赛页只列学院赛）。

在此基础上补了一条关键修正，本版据此重写：

> 给每个学院**自动分配一个院队**，不需要任何人操作，这个院队就存在；以后每次石榴籽杯都只能由这个院队报名；所有学院负责人自动进入该院队；院队不设人员上限。

**先回答你问的那句「现在的方案是把所有队伍都按学院分了吗」——不是，而且好在你提了这条。** v2 的做法是「要报学院赛的球队去绑学院」，会牵出两件事：所有球队都要补 `collegeId`、要迁移历史自由文本、要处理跨院入队。按你的思路改成系统预置院队后，**普通球队一个字都不用改**：学院标记只存在于院队身上，院队由系统按学院目录生成，用户看不见「创建院队」这个动作。

## 1. 院队是什么

**院队 = 一个学院在一个项目里的常设代表队，由系统预置，永远存在。**

| 属性 | 取值 |
| --- | --- |
| 唯一键 | `(学校, 协会, 学院)` 三元组派生的确定性编号 `tm:<校>:<协会>:<collegeId 摘要>` |
| 名称 | `{学院全名}代表队`（如「法学院代表队」），**读时按学院目录现拼**，院改名自动跟随，不落库 |
| 存在性 | 不需要任何人创建。首次读取时若缺则补建（幂等），学院目录新增学院后自动补齐 |
| 成员 | **由学院负责人挑选**：从「本学院在该项目的在册会员」里勾选，选中即入队（落 `team_members`，`source: 'picked'`），无需对方同意 |
| 人选来源 | `collegeMemberCandidates`：本学院 + 本协会 + 在册 + 账号可用。挑不了别院的人，别院负责人也挑不动本院 |
| 人员上限 | **无**。院队是常年队伍，不按比赛名单限额（一场比赛的参赛名单仍按赛事规则的 5–12 人） |
| 学院负责人 | 管理权挂在角色上（`staff` + 同院，含协会负责人与校管），不要求本人先在队里 |
| 队长 | **不设单一队长**。多个负责人各管一段会造成反复交接，所以没有「转让队长」这个动作 |
| 可做的操作 | 报名（学院赛）、挑人、移出队员；成员可**自行退出**；**不可**申请入队、改名、解散 |

### 为什么成员落表，而不是「全院会员的投影」

先想清楚一件事：**被选进院队 ≠ 全院都在这支队里**。院队是「这次比赛代表学院出战的人」，负责人挑人是一次真实授权，落表之后报名选人、出场名单、我的球队、荣誉归属全部沿用现有那一套，不需要为院队再写第二套逻辑。

代价是院队不会自动跟着入会/转院变动——但这个代价可以接受：院队不是会员名录，它是参赛队；真有人转走了，负责人把他移出即可，历史名单是快照本来也不回改。

## 2. 石榴籽杯 · 篮球/足球 = 学院赛

| 维度 | 球拍学院赛（现有） | 篮球/足球学院赛（本方案） |
| --- | --- | --- |
| 参赛单位 | 学院 | **院队**（一院一队，系统预置） |
| 内部结构 | 小项 → 大场 → 小场 → 排阵 | **一场一场**（同团队赛，无小项） |
| 报名 | 学院负责人提交名单 | **学院负责人为本院院队报名**，从本院会员里选 5–12 人 |
| 赛制 | 大场 N 局 | 单败 / 循环 / 小组+淘汰 / 双败（同团队赛） |
| 规则 | 球拍规则 | 节数、节长、犯规、加时、（足球）点球 —— **完全同该项目团队赛** |
| 录分与统计 | 逐局 | 逐场 + 球员统计 + 实时计分台 —— **完全复用** |
| 名次 | 学院名次 | 院队名次 = 学院名次（`placements` 里存的就是院队编号） |

一句话：**「按学院分」只体现在参赛单位上，比赛本身与今天的篮球/足球赛事一模一样。**

## 3. 数据设计

只加两个字段，不新建集合：

| 位置 | 字段 | 说明 |
| --- | --- | --- |
| `teamEvents` | `cupMode: 'college'` | 缺省/空 = 普通团队赛事；`college` = 石榴籽杯学院赛。只影响资格与文案，**不进 `rules` 快照** |
| `teams` | `type: 'college'` + `collegeId` | 只存在于院队。普通球队保持现状（自由文本 `college` 仅作展示），**不迁移、不校验、不改建队页** |
| `teamEventEntries` | 无新增 | 学院由院队编号推导，不在报名上重复存 |

**一院一队由主键天然保证**：报名记录的主键是 `entryKey(eventId, teamId)`，而一个学院只有一个确定性的院队编号 → 同一届赛事里一个学院只可能有一条报名。不需要「同院唯一」的额外校验，也**没有 v2 里那个并发窗口**（v2 要事务外查重，这里结构上就不可能出现两条）。

## 4. 报名流程（乙）

```
管理员发起学院赛（cupMode='college'）
   ↓
学院负责人在赛事详情点「为本学院报名」
   ↓ 系统取/补建该学院院队（幂等）
从「本学院在册会员」里选 5–12 人 → 填球衣号 → 提交
   ↓
校管审核 → 锁定 → 抽签 → 逐场 → 名次
```

要点：

- **选人来源不是「院队成员表」**，而是「本学院 + 本协会的在册会员」——这正是虚拟成员的含义，报名面板直接列这批人。
- 名单人数仍按赛事规则（`entryMin`/`entryMax`，默认 5–12）。「院队不设人员上限」指**队伍本身**，不是一场比赛的参赛名单。
- 普通球队点报名：直接拒绝 —— `学院赛只接受学院代表队报名`。
- 学院负责人替别院报名被拒（`managesCollege` 同院判定，改为按 `collegeId` 比较）。
- 校管可代任意学院报名（沿用现有口径）。
- 本学院在该项目一个会员都没有时，院队存在但为空，报名提示：`本学院还没有会员加入该项目协会`。

### 5.2 赛事详情（`team-event-detail`）

- 标题旁「学院赛」标签；报名列表按学院展示（`法学院代表队 · 12 人 · 已锁定`）。
- 报名面板三种身份三种文案：学院负责人「为本学院报名」、校管「代 X 学院报名」、普通会员「本院报名由学院负责人提交」。

### 5.3 球队详情与我的球队

- 院队详情：只读。成员区显示「本院会员 128 人（自动，不可增减）」，「申请入队 / 退出」按钮不出现；队长区换成「学院负责人」。
- 我的球队：本院用户的列表里**自动包含院队**（无需加入），排在自由球队之前。
- 组队页：**不列院队**。组队页是「自由组队与入队申请」的地方，把二十来支院队铺进去只会淹没有用的信息；院队从杯赛页与我的球队进。

## 6. 两处口径要守住

1. **院队人数 = `team_members` 里 ACTIVE 的行数**。队员既然落表，就不存在「推导 vs 实际」两套账——这正是选择落表而非投影的原因（「球队人数恒为 0」「已记录出场 0」两次事故都是两套账对不上）。
2. **可选名单 = `collegeMemberCandidates`**。挑人面板、报名面板、校验「他是不是本院的」三处必须调同一个函数，任何一处自己筛都会漏掉「账号被停用」「已退会」这类条件。

## 8. 边界与非目标

- **不做**「学院团体总分」跨项目累计（需运动会与各项目名次统一折算，独立课题）。
- **不改**普通球队的任何行为：不要求绑学院、不迁移历史 `college` 文本。
- **不做**一院多队。
- **不改**球拍学院赛逻辑。
- **不做**院队的人员管理后台：成员完全由「学院 + 会员身份」推导，没有增删入口。

## 10. 确认结果（已定）

1. **院队成员由负责人挑选**（选了即入队，无需对方同意），**没有申请入口**，成员**可以自己退出**。
2. **组队页不列院队**：院队只在石榴籽杯页、我的球队与赛事报名里出现。
3. **院队不可改名**，固定「XX 学院代表队」。

### 10.1 与 v3 的差异（按你的新口径调整）

v3 设想的是「院队成员 = 全院会员的虚拟投影」；你确认改为**负责人挑人、落表成真实队员**。改动落点：

- 院队成员写入 `team_members`（`source: 'picked'`），报名选人、出场名单、我的球队全部沿用现有那一套，不必为院队特判；
- 候选池（选谁）仍是「本学院在该项目的在册会员」，由 `collegeMemberCandidates` 统一给出；
- 因此「人数」不再需要推导函数——`team_members` 就是真相，v3 里那个「四处不得各自 count」的风险随之消失。

## 13. 修复记录（2026-10-20 晚）

复核发现三条「文档写了、代码没做到」，其中第一条会阻断首场报名，本轮一并修掉。

### 13.1 惰性预置的院队没人触发补建（阻断级）

**现象。** 全新库里建一场学院赛，学院负责人打开赛事详情看不到报名入口；直接调报名被拒
`球队不存在或未通过审核`；校管代报同样被拒。只有先调用一次 `getCollegeTeam` 之后才正常。

**根因。** 院队是「读时补建」的（`ensureCollegeTeam`），而它只被 `getCollegeTeam` 调用，
`getCollegeTeam` 又只被 `team-detail` 调用；报名候选列表走的是 `teams` 集合遍历，不补建。
于是「概念上永远存在」的院队，在干净库里既没落库、也没人能让它落库。

**修法（按方案 B：候选按目录派生，写只在真正需要时发生）。**

| 落点 | 改动 |
| --- | --- |
| `school-actor.buildDirectory` | 下发 `colleges`（按名称排序），作为院队派生的唯一来源 |
| `team-service` | 新增 `collegeIdOfTeamId`（编号反查学院）、`virtualCollegeTeam`（不落库的派生视图）、`resolveCollegeTeam`（按编号取队，缺失即补建） |
| `team-event-service.getTeamEvent` | 学院赛候选由**学院目录派生**：学院负责人只看本院，校管看全校；已报名的学院自动消失 |
| `team-event-service.submitTeamEntry` | 学院赛且记录缺失时先 `resolveCollegeTeam` 再走资格判定 |
| `team-event-service.getTeamEntryRoster` | 同上，保证「代 X 学院报名」能打开名单面板 |
| `team-service.getTeam` / `team-event-service.getTeamRecord` | 记录缺失且编号能对上学院目录时先补建，避免点进院队报「球队不存在」 |

写放大为零：读路径只派生，落库发生在第一次「挑人 / 报名 / 打开详情」。

### 13.2 院队没有页面入口

`listTeams` 无条件过滤院队，`team-list` 的「我的球队」筛选也跟着没了，院队详情（挑人面板）
在应用内不可达。现在 `mine=1` 时把本院院队派生进列表并置顶（标注「本院」，不算「我的」），
组队列表仍不列院队。行内不再显示「队长 」（院队没有队长），改显示「学院队 · N 人」。

### 13.3 工作台赛事列表缺学院赛标识

`team-event-list` 行内补「学院赛」标签，报名数按 `N 个学院 / N 支球队` 切换。
`listTeamEvents` 的 `canSubmit` 同时放开给校管（原先只认学院负责人），
否则校管在杯赛页看不到「报名」动作、却能在详情页代报。

### 13.4 报名面板分身份文案

`getTeamEvent` 新增 `entryPanel`（`college_staff` / `school_admin` / `member`），
文案与按钮文案（`为本学院报名` / `代 X 学院 报名`）都由服务端给，模板不判权。
原先只有一句静态提示。
