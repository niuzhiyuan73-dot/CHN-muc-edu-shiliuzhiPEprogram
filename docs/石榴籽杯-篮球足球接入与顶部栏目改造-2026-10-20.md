## 0. 理解校正：v1 错在哪

| | v1 的理解（错） | v2 的理解（本次口径） |
| --- | --- | --- |
| 篮球/足球的石榴籽杯是什么 | 该项目**任意团队赛事**的总入口，把工作台的赛事搬一份到杯赛页 | **按学院分的比赛**：各学院组队参加的学院赛 |
| 参赛单位 | 球队（谁都能建的俱乐部式球队） | **学院（学院代表队）**，报名资格绑学院 |
| 比赛规则 | 沿用团队赛 | 沿用团队赛（这一点 v1 对了） |
| 需要做的 | 纯读端聚合，写端零改动 | 团队赛上加「学院杯」属性 + 学院维度资格校验；其余全部复用 |

一句话：**篮球/足球的石榴籽杯 = 学院赛，只是它的比赛规则（赛制、节次、录分、统计、名次）不另立一套，照搬该项目的团队赛。** 球拍项目的学院赛有「小项（男单/女单/混双）→ 大场 → 排阵」，篮球没有小项，一场就是一场，所以不复用那套结构，只复用「按学院参赛」这一层。

## 1. 定义

**篮球学院赛（石榴籽杯·篮球）**：管理员发起 → 各学院以**学院代表队**报名 → 锁定名单 → 抽签 → 逐场录分 → 发布 → 结算名次。赛制、场地、裁判、记录员、技术统计、名次、荣誉与普通篮球团队赛完全一致。

与两种既有形态的关系：

| 维度 | 球拍学院赛（现有） | 普通篮球团队赛（现有） | **篮球学院赛（本方案）** |
| --- | --- | --- | --- |
| 参赛单位 | 学院 | 球队 | **学院代表队**（球队 + 绑定的学院） |
| 内部结构 | 小项 → 大场 → 小场 → 排阵 | 一场一场 | **一场一场**（同团队赛） |
| 报名资格 | 学院负责人提交名单 | 队长给球队报名 | **本学院负责人/校管为学院队报名**，一院一队 |
| 赛制 | 大场 N 局 | 淘汰/循环/小组+淘汰 | **同团队赛** |
| 录分与统计 | 逐局 | 逐场 + 球员统计 | **同团队赛** |
| 名次 | 学院名次 | 球队名次 | **球队名次 = 学院名次** |

## 2. 方案：给团队赛事加一个「学院杯」属性，不新建模型

### 2.1 为什么不做新模型

篮球/足球的比赛全链路（抽签、赛程、改期、裁判、记录员、实时计分、统计审核、名次、荣誉、我的球队）都长在 `teamEvents / teamMatches / teamMatchStats` 上，代码量在 `team-event-service.js` 与 `football-match-service.js` 里。为「学院赛」另建一套，等于把这套全链路复制一遍，且两边的规则迟早分叉——这正是球拍/团队两套模型已经付过的代价，不该再复制第三次。

### 2.2 新增的字段

| 位置 | 字段 | 说明 |
| --- | --- | --- |
| `teamEvents` | `cupMode: 'college'` | 缺省或空 = 普通团队赛事；`college` = 石榴籽杯学院赛。**只有这一个开关**，不带任何比赛规则 |
| `teams` | `collegeId` | 球队所属学院（稳定编号，来自本校学院目录）。**取代现有自由文本 `college`** |
| `teamEventEntries` | 无新增 | 报名记录不变；学院由所属球队推导，不在报名上重复存一份 |

`cupMode` 只影响三件事：**能不能报名（资格）、出现在哪个入口（杯赛页 or 工作台）、列表文案**。它不碰赛制、不碰规则快照、不碰结算。

### 2.3 报名资格：一院一队

- 报名球队必须绑定**有效 `collegeId`**（本校学院目录里存在），否则拒绝：`这支队没有绑定学院，不能报名学院赛`。
- **同一届赛事内，同一学院只能有一支报名队**（含待审核、已通过、已锁定状态；已退回不占位）。
- 校验放在报名动作里，与现有 `submitTeamEntry` 同一条路径；并发窗口同建队重名检查（云开发事务不允许整表查询，只能事务外先查、事务内点读确认），校园规模下接受。

### 2.4 权限

| 动作 | 谁能做 |
| --- | --- |
| 发起学院赛 | 校管理员；该项目协会负责人（沿用 `canManageAssociationSpace`） |
| 为本学院报名 / 交名单 | **本学院负责人**（`membership.role=staff` 且 `collegeId` 匹配）或校管代报 |
| 审核报名、锁定、抽签、开赛、录分、发布、名次 | 与团队赛现状一致（协会负责人及以上；裁判/记录员按指派） |

普通会员进学院队仍走现有入队申请，只是加入时校验「本人学院 = 球队学院」，跨院入队被拒（校管可豁免，用于并院/跨院联队等特殊情况）。

### 2.5 完全复用、一行不改的部分

赛制（单败/循环/小组+淘汰/双败）、抽签与轮次、逐场改期与整轮顺延、裁判与记录员指派、实时计分台、个人统计与审核、积分表、名次结算、球队荣誉、我的球队页、球员榜。**这是本方案最大的价值：规则只有一套。**

## 3. 页面与入口

### 3.1 石榴籽杯首页（`cup-home`）

页面按当前项目的 `sportType`（`utils/associations.js` 已有）分派数据源，其余控件（项目栏、搜索、年份、状态）通用：

| | 球拍项目 | 篮球 / 足球 |
| --- | --- | --- |
| 列表来源 | `listCollegeEvents` | `listTeamEvents`，只取 `cupMode='college'` |
| 行副信息 | 小项 · 名单 1–5 人 | 5v5 · 已报名 4 院 |
| 行操作 | 交名单（学院负责人） | 报名（学院负责人） |
| 点行进 | `college-event-detail` | `team-event-detail` |
| 发起 | `college-event-edit?projectId=` | `team-event-list?create=1&cupMode=college` |

副标题统一为「学院赛 · 篮球」——两类都是学院赛，不给用户制造第二套叫法。

**为什么不在页面里做统一 DTO 服务**：只有两个分支、字段差异集中在三处（副信息、行操作、路由），页面内按 `sportType` 分派即可；等排球接入（第三个团队项目）时再抽出 `cup-feed`，现在抽是过度设计。

### 3.2 发起（`team-event-list?create=1&cupMode=college`）

- 建赛表单**不新增字段**：赛制、队伍人数上下限、规则预设与普通赛事同一套。
- 进入时按 `cupMode` 打标并以只读文案告知「本赛事为学院赛：一院一队，成绩计入学院」。
- 篮球用页内表单、足球用 `football-event-form` 组件——两条路径都要接 `cupMode` 参数并透传（这是 v1 漏掉的点）。

### 3.3 赛事详情（`team-event-detail`）

- 标题旁一个「学院赛」标签；报名列表按学院聚合展示（「法学院 · 12 人 · 已锁定」）。
- 报名面板：学院负责人看到「为本学院报名」，校管看到「代 X 学院报名」；一院一队的冲突在此拦下并说明原因。
- 积分表、赛程、名次、荣誉全部不变，只把球队名后补学院名。

## 4. 前置条件：学院身份必须可信（阻塞项）

现在 `teams.college` 是**自由文本**（建队时 `String(payload.college||'').trim()`，不校验、不查目录、无长度上限）。学院赛的全部合法性都挂在「这支队属于哪个学院」上，这一层不修，一院一队、学院名次、学院团体总分都不可信。

必须做（C1，先于其他）：

1. `teams` 增加 `collegeId`，建队时从**本校学院目录**选（`schoolCollegeDirectory`），校验存在。
2. 旧数据迁移：`college` 自由文本 → 目录匹配（全名/简称），匹配不上标「未归类」并由校管在球队详情里补。
3. 旧字段保留为展示兜底，不再作为判据。

## 5. 分批实施

### C1 学院身份（规模 M，阻塞）
- `teams.collegeId` + 建队页学院选择器（本校目录）+ 迁移脚本 + 未归类补录入口。
- 加入球队时校验同院（校管豁免）。
- 测试：跨院入队被拒、目录外学院被拒、未归类球队不能报学院赛。

### C2 学院杯标记与资格（规模 M）
- `teamEvents.cupMode`；建赛动作接受该参数（默认空）。
- `submitTeamEntry` 增加三条校验：球队已绑学院、同院唯一、学院在本校目录内。
- `eventView` 下发 `cupMode` / `cupModeLabel` / `collegeEntryText`。
- 测试：一院二队被拒（含待审核占位）、未绑学院被拒、普通赛事不受影响。

### C3 杯赛页与入口（规模 S）
- `cup-home` 按 `sportType` 分派列表与路由；副信息、行操作、发起入口按项目类型切换。
- `team-event-list` 支持 `create=1&cupMode=college`（篮球表单、足球组件两条路径）。
- 测试：篮球杯赛页出现学院赛、球拍页行为不变、足球发起落到表单。

### C4 详情与文案（规模 S）
- `team-event-detail` 的学院赛标签、报名列表按学院展示、报名面板的「本学院/代报名」入口。
- 操作手册补一节「在石榴籽杯发起篮球/足球学院赛」。

### C5 收尾（规模 S）
- 全量回归 + 三项目真机走查；`docs/赛事管理员操作手册.md` 同步。

## 6. 边界与非目标

- **不做**「学院团体总分」跨项目累计：那需要运动会/各项目名次统一折算，属独立课题。
- **不改**球拍学院赛的任何逻辑。
- **不改**普通团队赛的行为（`cupMode` 为空即今天的样子）。
- **不做**「一院多队」（如法院一队/二队）：先按一院一队落地，需要时把 `cupMode` 扩成 `college` / `college-multi`。

## 7. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 学院目录里学院数 > 签表容量 | 20+ 院参赛 | 抽签已按 2 的幂自动轮空（`bracketSizeOf`），报名只有「至少 2 支」的下限、没有上限，无需改动 |
| 一院一队的并发窗口 | 极端情况下同院两队都报名成功 | 与建队重名同一取舍（事务外查、事务内点读）；后台列表能看出，校管可退回一队 |
| 旧球队没有学院 | 无法报学院赛 | C1 迁移 + 未归类补录入口；未归类球队在学院赛报名面板直接提示去补 |
| `cupMode` 被当规则用 | 有人想靠它改赛制 | 代码层面明确：`cupMode` 只参与资格与文案判断，不进入 `rules` 快照 |

1. **学院代表队怎么产生？**
   - 甲（推荐、改动小）：沿用现有「建队 → 报名」，只是球队必须绑学院、一院一队。学院负责人先把本院的队建好，再报名。

## 附：本轮已完成的界面改动（供真机确认）

### A. 我的球队「已记录出场」恒为 0

出场此前只认 `match.lineups`；计分台在名单为空时按整份报名名单录分，个人统计照常发布，于是「有分、没名单、出场 0」。现在出场 = 「该场名单包含本人」**或**「该场已发布统计里有本人的行」（统计只在某项真填了数字时才落行），两处都没有仍不推定；新增 `statOnlyAppearanceGames`，页面提示写明口径。演示数据补了 `lineups`。

### B. 石榴籽杯顶部：一屏三个项目 + 一个框搜两样

- **项目栏**：一屏正好三个，其余左滑；选中项靠 `scroll-into-view` 自动滚进可视区——从别的页面带着 association 进来时，当前项目不会留在屏幕外。
- **搜索**：一个输入框同时搜**项目**（本地匹配项目名/简称/全称/徽标字，命中即出「项目」组，点一下切过去并清空关键词）与**赛事**（服务端按名称/场地过滤，跨分页，聚成「赛事结果」一组）。
- 服务端 `listCollegeEvents` 新增 `keyword`，在分页之前过滤；搜索走后台静默重取 + 请求令牌，不清空列表、不吃过期响应。
