日期：2026-10-16（晚，第二批）。前置：同日 [独立验收 5 条缺陷修复](独立验收缺陷修复-验收记录.md)

## 一、转校（用户口径：只需转入学校同意）

> 用户原话：「做转校需要转过去的学校的校级管理员同意才可以转校，不需要原来学校的任何同意。」

**实现**（`services/school-membership-service.js`，不新增集合）：

- **申请** `applySchoolTransfer({ collegeId, studentId })`：当前浏览的学校就是目标学校。落点是
  **目标学校的一条待审身份申请**（沿用 `schoolMembers` 的 pending 行），额外记 `transferFrom`（原学校）。
  幂等；没有本校身份时提示直接入会；已在目标校则提示无需转校。
- **审批** `reviewSchoolTransfer({ userId, decision, reason, revision })`：只有**目标学校**的
  `reviewMembers` 权限者（校级管理员）能批，且不能批自己。通过时在一个事务里做完整搬运：
  1. 目标校学号占用与学院复核（与首次入会同一把尺子）；
  2. 原校身份转 `transferred`（新状态常量）并记 `transferredTo/At`；
  3. 原校校级角色停用、原校各协会 membership 置 `revoked`（他不再属于那所学校）；
  4. 账号 `primarySchoolId` 指向新学校，`schoolIdentityVersion` +1；
  5. 两侧各写一条审计：目标校 `reviewSchoolTransfer`、原校 `transferSchoolOut`（**备案**，
     不是同意——原学校没有审批权）。
  驳回只改申请状态，申请人留在原校。
- **撤回** `cancelSchoolTransfer`：申请人撤回自己的待审申请。
- **原学校的待办里没有这条**：`getSchoolApplications` 只列本校的 pending 行，转校申请在目标校那一侧；
  列表里带 `transfer` / `transferFromName` 标记，审核页据此走转校审批动作。
- **历史不搬**：比赛、赛事、积分、审计仍留在原校范围（记的是「当时那所学校那个协会发生的事」），
  新学校从普通会员起步、权限需重新指定。

**页面**（`pages/school-identity`）：浏览外校时出现「转入 XX 学校」卡片（选学院 + 学号 + 提交；
已提交则显示待审与「撤回」），审核列表里转校申请带「转校 · 来自XX」标签并走转校审批。

**云函数**：`createSchoolHandlers` 返回的动作即协议 2 注册表，新增的三个动作自动上云；
客户端 `school-cloud.forSchoolIdentity` 同步补上三个动作名。

## 二、交流赛剩余能力（与普通赛事同一口径）

> 用户原话：「开始做交流赛剩余能力，和普通赛事完全一样，同步到云函数」。

| 能力 | 规则（与普通赛事对齐） | 动作 |
|---|---|---|
| 签到 | 名单锁定后到结束前，由管理员在场边**代签**（本人不自助签到），不能替外校签，重复签到幂等 | `checkInExchangeSignup` |
| 退赛 | 本人取消报名（已有）＋管理员**移出报名者**，都只在报名阶段，释放总名额与本校名额 | `cancelExchangeSignup` / `removeExchangeSignup` |
| 失效身份处理 | 锁定名单时把退学 / 转校 / 停用的人**移除并释放名额**（与训练「本人失效自动移除报名」同一处理），仍不足两校则拒绝锁定并说明原因 | `lockExchangeRoster` 内 |
| 邀请撤回 | 主办方可撤任一受邀校、受邀校可撤自己那条；只在报名阶段、该校还没人报名时可撤 | `withdrawExchangeInvitation` |
| 赛事取消 | 主办校管理员或平台管理员；报名中 / 待开赛 / 已抽签都可取消，结束后不可；取消后报名、抽签、录分、名次确认全部停止 | `cancelExchangeEvent` |
| 比分撤销 / 修订 | 与普通比赛同一条规则：**后面还有已确认的场次就先撤后面的**（从最后一轮往前撤）；撤销后退回待确认并清比分，重录即修订 | `revokeExchangeScore` |

**签表自洽**：`exchange-plan.planExchangeMatches` 增加「刷新」逻辑——待确认 / 已撤销的下一轮，
若两侧晋级者变了就按新对阵刷新（比分清空、回到待确认）；已生效的比分一律不覆盖。
于是撤销半决赛后重录、晋级者换人时，决赛不会挂着上一个晋级者（与个人赛 F5 同一条病根、不同治法：
个人赛靠「有下游就不许撤」，交流赛的签表是**投影**出来的，可以在重录时自动刷新）。

**DTO**：`getExchangeEvent` 增加 `canCheckIn` / `canCancel` / `canWithdrawInvitation` / `canceled`，
参选人行增加 `checkInTime` / `checkedIn` / `canCheckIn` / `canRemove`，比赛行增加 `canRevoke`；
`summary` 下发取消信息。名单投影的字段白名单测试同步更新（仍不含学号与身份引用）。

**云端接入**：
- 新增 `cloudfunctions/data/src/core/school-exchange-handlers.js`（实现取自共享库镜像），
  并并入 `school-request.js` 的协议 2 分发；
- `services/school-cloud.js` 新增 `forExchange`（16 个动作）；
- `services/exchange.js` 从「非模拟模式直接抛错」改为按数据源选择本地 / 云端（与协会空间门面一致）；
- 页面 `pages/school-exchange` 去掉「仅开放本地模拟体验」的拦截，并补上签到 / 移出 / 撤回邀请 /
  取消赛事 / 撤销比分五个入口与状态展示。
