## 4. 当前架构：必须理解的边界

### 4.1 两套数据源仍然并存

| 结构 | 主要入口 | 当前用途与风险 |
|---|---|---|
| 旧栈，协议 1 | `services/index.js` → `mock.js` / `cloud.js` | 尚未迁移的页面仍依赖它；不能用它给已迁移页面造业务数据 |
| 学校身份 | `services/school-identity.js` → `school-mock.js` / `school-cloud.js` | 账号、学校身份及权限相关操作 |
| 学校协会空间 | `services/association-space.js` 的 `forScope(scope)` | 绑定学校、协会和数据源的业务客户端 |
| S2 上下文 | `school-context.js` | 从账号、学校成员、校级角色、协会角色构建身份 |
| 仓储 | `school-memory-repo.js`、云端 `src/school-repository.js` | 内存和真实云端仓储语义都要核验 |
| 学校/协会选择 | `school-session.js`、`association-scope.js` | 浏览范围，不是服务器授予权限的依据 |

`school-mock.js` 会把 u01～u24 演示账号接入 S2，但旧 `mock.js` 与新 `school-mock.js` 的业务内存库仍是两套。账号编号相同不代表赛事、比赛或积分会自动共享。

`services/index.js` 的引用不一定表示迁移失败：读取 `isMock` 或共享的数据源开关可以保留。应追踪实际读写调用，不能用 grep 命中数量充当完成率。

### 4.2 分层约定

- 页面与组件：交互、导航、表单、加载状态；不自己发明权限规则。
- `*-view.js`：把 DTO 整形成展示数据，优先复用已有纯构建器。
- `school-*-service.js`：取数、范围检查、能力计算、业务写入及事务。
- `utils/` 和既有纯 service：评分、赛制、资格判定等同一份规则。
- `cloudfunctions/data/lib/`：由同步脚本生成的共享镜像，不手改镜像来修问题。
- `cloudfunctions/data/src/`：云请求处理、真实仓储、路由与适配，不能只测试 mock 而漏掉这些路径。

DTO 不够用时可以增加必要字段或小型读端。不要为了原样复用旧构建器就随意下发旧数值角色；当前迁移已采用服务端能力布尔量，展示层只做形状适配。

### 4.3 必须保留的业务边界

1. 个人赛、学院赛、跨校交流赛是三种业务模型，不能并成一张赛事表或一个状态机。
2. 普通比赛是赛后录分，不新增“发布普通比赛、报名普通比赛”流程；小组限制不加在普通比赛上。
3. 学院负责人只能处理本学院；管理员和学院负责人的能力不能混用。
4. “可浏览学校目录”不等于“可读该校协会内部名单或比赛台账”。已经迁移的比赛、赛事面板不再用外校静态演示数据掩盖访问拒绝。
5. 跨校交流赛当前不影响校内等级分和积分。未经用户改变口径，不要自行接入校内回放。
6. 评分、积分、抽签、撤销、晋级优先复用既有纯规则；不要在新页面另写一套近似算法。
7. 等级分与积分不是一回事；训练积分、赛事名次积分和比赛等级分回放需分别验证。

## 7. B3 详细任务：登录与会话统一

### 7.1 先读这些代码

- `miniprogram/app.js`：启动顺序、恢复缓存、刷新 session、默认协会、退出及全局 userInfo。
- `pages/login/login.js` 及 WXML：登录、账号开通、表单、待审核反馈。
- `services/auth.js`：区分可继续复用的纯校验与旧 `getCurrentUser` I/O。
- `services/school-identity.js`、`school-cloud.js`、`school-mock.js`。
- `services/school-membership-service.js`：`registerSchoolAccount`、`getSchoolIdentitySession`、申请/审核等现成接口。
- `services/school-session.js`、`association-scope.js`、`pages/school-identity/`。
- `tests/app-session.test.js`、`tests/auth.test.js`、`tests/page.test.js` 及学校身份测试。

### 7.2 核对并实施

1. 画清一次登录从页面到后台的调用链，列出身份状态分别存在 app、storage、school-session、mock actor 的哪些位置。
2. 分清“平台账号存在”“本校成员身份有效”“当前浏览的是哪所学校”“本协会有什么管理权”。不能用一个 `loggedIn` 代替四者。
3. 优先复用 S2 账号开通与身份申请，不再向旧 `registerMember` 写入一个新账号后期待 S2 自动同步。
4. 为尚未迁移页面需要的兼容展示数据定义单一适配入口；不得在每页伪造 `_id / role / college`，不得把兼容 role 当服务端授权依据。
5. 登录成功、退出、切换演示身份后明确刷新本人学校、当前浏览范围、成员状态、能力和页面缓存。模型字段以实际接口为准。
6. 防止异步竞态：A 的会话请求晚于 B 登录返回，不能把 A 的数据写回；退出后晚到的请求不能恢复已退出状态。
7. 检查默认协会选择与学校协会启用状态。按现有产品规则处理；某校未启用的协会不能静默读别校默认数据。
8. 对网络故障给出明确状态，不能退回旧 mock 身份或保留旧管理员按钮来“保证能用”。
9. 再跑已经迁移的赛事和比赛闭环，确保 session 改动没有让它们退回旧数据源。

### 7.3 必须验证的场景

| 场景 | 期望 |
|---|---|
| 无账号进入 | 明确登录/开通引导，不显示上一人的内部数据 |
| 有账号但未入会 | 可进行允许的身份申请；不能录分、报名或管理内部业务 |
| 申请待审核/被拒 | 状态与服务器一致，不把旧缓存的 active 身份沿用 |
| 普通会员 | 本人身份及当前学校正确，业务入口按能力显示 |
| 学院负责人 | 仅本学院相关入口开放，无协会管理员权限提升 |
| 校/协会管理员 | 管理能力来自服务器，不来自页面缓存 role |
| 切换演示身份 | 页面与写接口是同一个人，不出现“按钮是管理员，提交是会员” |
| 切学校/协会 | 不串身份、名单、积分与操作对象；无权限时正确清空 |
| 退出后返回页面 | 不再显示旧管理入口或旧内部台账 |
| 慢请求/失败/重复登录 | 旧响应不会覆盖新会话，loading/submitting 能恢复 |

若“微信云端身份仍存在”与“用户点击退出后的产品状态”需要明确约定，先查现有需求和实现；仍有影响业务的歧义时，把具体分歧和推荐行为问清，其他独立工作继续。

转校先确认是否已有相应动作与需求：本校身份、学院角色、协会角色、未结束报名、训练名额、历史记录、积分归属分别如何处理。历史记录保留原发生范围，不因用户当前学校改变而被搬走。需要产品决策的具体状态迁移再问用户，不自行发明批量删除或跨校转分政策。

### B7：跨校交流

已有 `school-exchange` 页面和 `exchange-service.js` 等实现。先读 S4 实施记录，核对邀请方/被邀请方、接收/拒绝、名单锁定、比赛结果及修改权限。保持交流赛与校内计分边界；补全页面路径、身份切换和双方范围测试，不从头重写。

### B8：旧栈收敛

逐个活跃页面追踪真实读写，形成“页面 → 视图 → 客户端 → action → 仓储”的表。搜索旧门面只用于定位，不按模块名称机械删除。

保留纯算法、构建器、必要种子和仍有消费者的兼容层。删除前查所有引用、云端镜像清单及测试。旧云协议是否下线要考虑已发布客户端，不能为了代码清爽未经评估断掉兼容入口。

至少回归普通比赛、个人赛事、学院赛、训练、身份申请、公告、个人成绩、跨校交流八条业务链，并覆盖回退、失败及切换范围。

### B9：真实环境与发布

先读 `cloudfunctions/README.md`、真实仓储和迁移工具。准备环境配置清单、集合与索引、权限规则、协议路由、数据备份、迁移 dry-run、数量/范围核对、回滚步骤和真机脚本。

模拟仓储成功不能证明云端事务、查询限制、分页、并发和权限规则可用。必须用真实环境核对；未拿到环境或数据时先完成本地准备，准确列出外部依赖。

部署、导入真实数据、删除生产集合、推送远程等动作应遵循用户当次授权范围。已有“继续开发”授权不自动等于允许改生产数据。把可审查的包、报告和回滚方案先准备好，再处理必要确认。

## 9. 实现时的固定检查表

- 一次操作开始时绑定范围和客户端，异步等待后不重新从全局读 scope 来完成同一写入。
- 浏览范围不是授权凭证；服务器重新验证 actor、学校、协会、学院和记录归属。
- 事务内应重新读取需要保护的身份/主记录；审计和关键状态保持原子性。内存事务不允许任意集合查询，真实云仓储限制也要遵守。
- 记录 ID 使用学校键工具，不自行拼接；路由参数用 `encodeURIComponent`，页面收到的 query 不重复解码。
- 写接口幂等区分新建 requestId 与已有记录 ID；超时重试不能重复新增比赛/报名/积分事实。
- 守住 DTO 与旧构建器之间的适配，能力以 S2 返回值为准。不要让旧纯构建器默认 mock 权限覆盖 DTO。
- 列表截断必须如实返回更多标记；全量场景循环取完，不能把前 50/100 条当全集。
- 切范围、身份变化、读取拒绝、网络异常后清理旧数据；请求序号或等价机制避免过期响应回写。
- 轮询复用 `live-watch.js`，S2 页面传 S2 fetch，不新建散落定时器。
- 不缓存永久权限；提交时服务器再判，页面状态只是显示依据。
- 不把业务错误包装成成功空列表来让测试变绿；有意的无权限空态必须带可解释的状态。
- 不手工修改评分来“修排行榜”；检查流水、赛事/训练事实、赛季边界与回放输入。

### 10.3 每批完成定义

1. 本批入口链可用，读写同一范围同一仓储。
2. 正常路径、关键权限拒绝、跨范围和必要异常路径已验证。
