## 本批完成

### 1. 解开硬耦合：运行模式搬进中立模块

删门面的**唯一硬耦合点**是「学校维度自己也要知道当前是 mock 还是 cloud」：

    school-identity.js ──isMockNow()──▶ services/index.js（协议 1 门面）

而 `association-space.js` / `exchange.js` 又都靠 `identity.isMockNow()` 判数据源，
`app.js` 则用 `facade.setDataSource()` 拨开关。门面一删，整条链断。

- 新增 `miniprogram/services/runtime-mode.js`：运行模式的**唯一持有者**
  （`getDataSource` / `setDataSource` / `isMockNow` / `resetDataSource`，以及兼容
  既有解构写法的 `isMock` getter）。
- `school-identity.js` 改为 `require('./runtime-mode.js')` 取 `isMockNow`。
- `services/index.js` 不再自持状态，改为**转发** runtime-mode；`resolveSource()`
  与 `createApi()` 均向它取值。门面只保留「按模式挑实现」这一件事。

### 2. 页面层对旧门面归零

B8-a1 的盘点结论是「页面层已无协议 1 业务调用，余下只是 `isMock` 开关与协会
会话」。本批把这一层残留也摘掉：

| 残留类型 | 数量 | 处置 |
|---|---|---|
| `{ isMock } = require('services/index.js')` | 18 处页面 / 组件 | 改接 `runtime-mode.js` |
| `facade.isMockNow()` | 3 处（association / index / login） | 改接 `runtime-mode.js` |
| `facade.getAssociation()` / `setAssociation()` | 4 处（association / index / login / profile） | 改走 `association-scope.js`（会话状态的真正持有者） |
| `app.js` 的模式开关与协会读写 | 各 1 处 | 分别改走 runtime-mode / association-scope |

结果：`miniprogram/pages`、`miniprogram/components` 与 `app.js` 中**不再出现任何
`services/index.js` 引用**。至此「第 2 步：迁剩余页面」在业务与开关两个层面都已
达成，旧门面只剩服务层与云端两个去处（切片 B / C）。

## 验证结果

- 全量测试：**2653 条通过，0 失败**（基线 2643，本批净增 10）。
- 新增 `tests/runtime-mode.test.js`（10 条）：
  - 4 条运行模式行为（默认 mock、切换读数、非法值被拒且不改变状态、复位）；
  - 2 条门面转发（证明「同一份状态、两个入口」，**门面删除后这两条随之一并移除**）；
  - 4 条静态守护：`pages` / `components` 无旧门面引用、`app.js` 无、
    `school-identity.js` 无；服务层仍依赖旧门面的文件**恰好等于**登记清单。

  新增对旧门面的依赖会变红，划掉一个却不更新清单也会变红。清单：
  `announcement-view` / `association-scope` / `auth` / `avatar` / `college-view` /
  `events-view` / `home-view` / `live-watch` / `match-view` /

  **后续进展**：P10-b1 已划掉 `avatar.js` 与 `live-watch.js`，清单降至 **10**，
  见 [P10-b1 验收记录](P10-b1-活代码解绑旧门面-验收记录.md)。
- **反向验证（本批关键一步）**：注入 3 处违反——页面加一处 `services/index.js`
  引用、`school-identity.js` 与 `school-cloud.js` 各加一处 `require('./index.js')`
  ——三条守护用例转红（7 通过 / 3 失败）；还原后复绿。探针文件与临时脚本均已
