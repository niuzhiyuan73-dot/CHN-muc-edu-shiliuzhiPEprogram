# 网球计分 —— 需求与实施方案

> 状态：**已实施**（S1–S4 全部完成，`npm test` 全绿；上线前需重新部署 `data` 云函数）
> 日期：2026-10-19
> 范围：网球协会（`tn`）的比赛录入、比分校验、实时记分台、成绩展示

---

## 一、官方规则（ITF Rules of Tennis 2025）

依据 ITF 现行规则正文与附录 VI（Alternative Procedures and Scoring Methods）：

| 层级 | 规则 | 出处 |
|---|---|---|
| 分 | 0（Love）/ 15 / 30 / 40。先得 4 分且领先 2 分胜一局；40:40 为 Deuce，此后需连得 2 分（占先 / Advantage） | Rule 5 |
| 局 | 先胜 6 局且领先 2 局胜一盘；6:6 时打抢七（Tie-break Game） | Rule 6 |
| 抢七 | 先得 7 分且领先 2 分；胜者以 7:6 拿下该盘 | Rule 6 |
| 盘（变体） | Advantage Set：两局领先，不设抢七，可打到 8:6、10:8 | Rule 6 |
| 场 | 三盘两胜（先胜 2 盘）或五盘两胜（先胜 3 盘） | Rule 7 |
| 变体 | No-Ad（无占先）：40:40 后打一分决胜，接发方选择接发区 | 附录 VI |
| 变体 | Short Set（短盘）：先胜 4 局且领先 2 局，4:4 抢七（也可 3:3 抢七） | 附录 VI |
| 变体 | Match Tie-break：用 7 分或 10 分抢十代替决胜盘 | 附录 VI |
| 变体 | Final Set Tie-break：决胜盘 6:6 时打 10 分抢七（四大满贯 2022 起统一） | 附录 VI |

对校内场景最有用的三条：**短盘（4 局）**、**无占先**、**抢十代替决胜盘**——都是为缩短时长设计的，与当前「11 分制三局两胜」的时长（30–40 分钟）接近。

## 二、为什么现有模型装不下

现有赛制是**两级**：分 → 局 → 场。

```
scoreA: [11, 9, 11]   每局我方得分
scoreB: [9, 11, 9]
gamePoints: 11        每局目标分
bestOf: 3             三局两胜
```

网球是**三级**：分 → 局 → 盘 → 场，且每级的目标值都不一样（4 分 / 6 局 / 2 盘）。三处硬冲突：

| # | 冲突 | 现状 | 网球需要 |
|---|---|---|---|
| 1 | 层级少一级 | 数组元素 = 一局得分 | 数组元素应当是**一盘局数**，中间还有「局」这一层 |
| 2 | 2 分差规则不适用 | `high >= gamePoints && high-low >= 2` | 盘比分允许 **7:6**（1 局差），因为抢七决定 |
| 3 | 目标分写死三档 | `GAME_POINTS_OPTIONS = [11, 15, 21]` | 一局恒定 4 分，可变的是「每盘几局」 |

第 2 条是最容易埋雷的：直接把 `gamePoints` 设成 6，`7:6` 会被判「胜方必须领先 2 分」，而 `6:5` 反倒因为 `6-5<2` 被拒、`6:4` 通过——规则方向是对的，但 7:6 这条主流比分录不进去。

第 3 条之外还有个隐藏点：**实时记分台**（`services/live-score.js`）的状态机也是按「够分且领先 2」写的，`replayRallies` 只会在一级里循环，加盘就得改状态机。

## 三、方案选型

| | 方案 A：只录盘比分 | 方案 B：盘比分 + 实时记分（推荐） | 方案 C：完整裁判级 |
|---|---|---|---|
| 录入 6:4 7:5 | ✅ | ✅ | ✅ |
| 15/30/40 显示 | ❌ 只能填数字 | ✅ | ✅ |
| 6:6 抢七 | 只能事后手填 7:6 | ✅ 自动进入抢七 | ✅ |
| 抢七小分 7:6(5) | ❌ | ✅ 可选 | ✅ |
| 发球局 / 换边 / 无占先决胜分选择接发区 | ❌ | ❌ | ✅ |
| 改动面 | 2 个模块 | 6 个模块（含云镜像） | 12 个模块 + 新数据结构 |
| 风险 | 低 | 中（碰实时状态机） | 高，且大量交互无人验证 |

**推荐 B。** 校内网球的实际用法是「打的时候有人拿手机记分」——如果实时台只能记 11 分制，网球场地边就没人用，最后还是回到微信群里报比分。C 的换边提醒、发球方管理属于裁判工具，本项目没有裁判编制，不做。

## 四、推荐方案的数据模型

### 4.1 关键取舍：`scoreA/scoreB` 语义从「每局得分」变为「每盘局数」

不新增字段、不改数组形状，只改这一层语义：

```js
// 三盘两胜，6:4 7:5
scoreA: [6, 7]
scoreB: [4, 5]

// 一盘制，抢七 7:6(5)
scoreA: [7]
scoreB: [6]
tiebreaks: [{ setIndex: 0, a: 7, b: 5 }]   // 可选，仅用于显示 7:6(5)
```

好处：`bestOf`（3 盘两胜）、`gamesToWin()`、`formatScore()`（`6:4  7:5`）、逐场结算、Elo、个人战绩页面**全部不用改**。历史数据的 `scoring` 缺省即 `'point'`，与 `association` 字段同一套「缺字段视作旧数据」的口径。

代价：一个比赛记录里「局」这个词有两种含义（旧赛制的数组元素 vs 网球盘内的局）。因此**所有面向用户的文案必须按 `scoring` 分支**：旧赛制说「第 1 局」，网球说「第 1 盘」，盘内局数另开一行显示。

### 4.2 比赛记录新增字段

| 字段 | 示例 | 说明 |
|---|---|---|
| `scoring` | `'tennis'` | 缺省 `'point'`（现有全部赛制） |
| `setGames` | `6` | 每盘局数，短盘为 `4` |
| `tiebreakAt` | `6` | 局分到几打抢七；`null` 表示 Advantage Set 不抢七 |
| `tiebreakPoints` | `7` | 抢七分数，决胜盘抢十则用 `10` |
| `noAd` | `false` | 无占先：40:40 后一分决胜 |
| `tiebreaks` | `[{setIndex,a,b}]` | 可选；不存则显示 `7:6`，存了显示 `7:6(5)` |

`gamePoints` 在网球记录上**不再写入**（一局恒定 4 分），校验时忽略该字段。

### 4.3 注册表配置（`miniprogram/utils/associations.js`）

`baseRules().format` 里已经预留了 `gamePointsOptions / bestOfOptions / defaultFormat` 三个字段，但**目前全项目没有任何地方消费它们**（`match-entry-view.js` 直接 import 全局常量）。这次把它激活：

```js
// 网球（tn）覆盖 baseRules 的 format
format: {
  scoring: 'tennis',
  setGamesOptions: [6, 4],        // 标准盘 / 短盘
  bestOfOptions: [1, 3],          // 一盘决胜 / 三盘两胜
  tiebreakPointsOptions: [7, 10],
  defaultFormat: {
    scoring: 'tennis',
    bestOf: 1,                    // 校内日常默认一盘决胜
    setGames: 6,
    tiebreakAt: 6,
    tiebreakPoints: 7,
    noAd: false,
  },
},
```

其余三个协会保持 `baseRules()` 不动，即 `scoring: 'point'`。

### 4.4 校验规则（`utils/match-format.js` 新增分支）

`validateMatchScore` 按 `format.scoring` 分派，外层骨架（局数一致、超盘数、决胜盘必须是最后一盘）完全复用，只换「一盘」的判据：

**标准盘（setGames=6, tiebreakAt=6）**

| 比分 | 结果 | 理由 |
|---|---|---|
| 6:0 ~ 6:4 | ✅ | 到 6 局且领先 ≥2 |
| 7:5 | ✅ | 5:5 后连下两局 |
| 7:6 | ✅ | 抢七决定 |
| 6:5 / 6:6 | ❌ | 盘未结束 |
| 7:4 | ❌ | 6:4 时就该结束，不存在 7:4 |
| 8:6 / 9:7 | ❌ | 抢七盘不会打到 8:6（那是 Advantage Set） |

**短盘（setGames=4, tiebreakAt=4）**：4:0~4:2 ✅、5:3 ✅、5:4 ✅、4:3 ❌。
**Advantage Set（tiebreakAt=null）**：`a >= 6 && a-b >= 2`，允许 8:6、10:8。
**无占先（noAd）**：不影响盘比分合法性，只影响实时记分台的一局内判定（40:40 后下一分直接赢局）。

## 五、界面改动

### 5.1 录入页（`pages/match-entry`）

| 现状 | 网球下 |
|---|---|
| 「分制：11 分制 / 15 分制 / 21 分制」 | 「盘制：一盘决胜 / 三盘两胜」 |
| 「局制：一局一胜 / 三局两胜 / 五局三胜」 | 「每盘局数：6 局（标准）/ 4 局（短盘）」 |
| 比分行标签「第 1 局」 | 「第 1 盘」 |
| 胜方实时提示「11:9 领先」 | 「6:4 7:5 胜」+ 提示「若 6:6 则抢七」 |

picker 的选项从**当前协会的 `format`** 取，不再读全局常量——这是让「乒乓球 21 分制、网球盘制」能共存的前提。

### 5.2 展示（`utils/format.js: formatScore`）

现成实现 `formatScore([6,7],[4,5])` 已经输出 `6:4  7:5`，**不用改**。只需在网球记录上补抢七后缀：`7:6(5)`。加一个 `formatTennisScore(scoreA, scoreB, tiebreaks)` 包装，避免改到旧赛制的调用点（`match-view` / `profile-view` / `events-view` 共 4 处）。

### 5.3 实时记分台（`services/live-score.js` + `pages/live-score`）

状态机加一级，`replayRallies` 变成「分 → 局 → 盘」三层循环：

- 一局：先得 4 分且领先 2；noAd 时 40:40 后下一分直接赢局
- 一盘：到 `setGames` 且领先 2；或先到 `setGames+1`；或 6:6 进入抢七，抢七先到 `tiebreakPoints` 且领先 2
- 一场：盘数过半

页面显示从「局数 + 当前局比分」变成「盘数 + 当前盘局分 + 当前局分」：

```
  1 : 0        第 2 盘 4:3       30 : 15
  盘数          当前盘局分        当前局分（15/30/40/AD）
```

`describeLive()`（`services/live-view.js`）要多吐 `setsText`、`pointTextA/B`（把 0/1/2/3 翻成 Love/15/30/40/AD），其余字段不动。

### 5.4 演示数据（`services/school-demo.js`）

北航网球桶里现有的 `scoreText: '15:13 11:9'` 这类文案要换成网球比分（如 `6:4 7:5`、`7:6(3)`），否则演示模式下网球比赛的比分一眼假。

### 6.1 学院赛的阻塞项（必须先解决，否则网球在石榴籽杯里比分会录错）

`college-tie.js:315` 建小场时直接用 `COLLEGE_LEG_FORMAT`，而石榴籽杯的项目**就是协会**（`cup-home` 读 `activeAssociations()`），所以「网球」项目会自动出现在石榴籽杯里，它的每一小场都会被当成 11 分制一局。

两条路：
1. **网球暂不进石榴籽杯**：`cup-home` 过滤掉 `scoring !== 'point'` 的协会，界面上给一句「网球赛事单独安排」。改动 1 处，最省。
2. **学院赛按协会取赛制**：`COLLEGE_LEG_FORMAT` 变成函数 `collegeLegFormatOf(association)`，网球小场用「一盘制短盘 4 局」。改动 4 处（含云镜像与测试），但学院赛能真正办网球。

推荐 2，但可以和主体功能分两批做。

## 八、5 件事的结论（2026-10-19 拍板）

1. **盘制**：两种都做，可选 —— 一盘决胜 / 三盘两胜，默认**一盘决胜**。
2. **每盘局数**：两种都做，可选 —— 6 局标准盘 / 4 局短盘，默认**6 局**。
3. **决胜盘**：正常打，6:6 打 7 分抢七，不提供抢十。
4. **无占先**：提供开关，默认**关闭**（按标准规则打）。
5. **抢七小分**：记，落库为 `tiebreaks: [{ setIndex, a, b }]`，展示成 `7:6(5)`。
6. 另加一条：**网球必须能进石榴籽杯**——杯赛小场对网球走 4 局短盘 + 无占先（见 `collegeLegFormatOf`），不把网球排除在团体赛之外。
