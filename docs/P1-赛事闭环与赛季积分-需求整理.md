## 二、赛事等级与赛事积分

### 2.1 赛事等级

| 等级 | 称呼 | 名次分倍数 |
|---|---|---|
| 1 | 一级赛事 | **×4** |
| 2 | 二级赛事 | **×2** |
| 3 | 三级赛事 | **×1** |

> 这里的「倍数」只作用于**名次分**；等级分（elo）的放大规则见第三节，两者是两回事。

### 2.2 创建赛事时必须选择的两项

管理员**发布赛事时**必须显式选择，不允许留空：

1. **赛事等级**：1 / 2 / 3 级。（默认值为三级，但必须经过选择确认。）
2. **三四名赛**：
   - **并列**：半决赛两名负者并列季军，**都得 10 分**；
   - **打三四名**：额外打一场三四名决赛，产生真正的第三名与第四名。

### 2.3 名次分表

基础分：

| 名次 | 基础分 |
|---|---|
| 冠军 | 20 |
| 亚军 | 14 |
| 季军 | 10 |
| 第四 | 7 |
| 八强 | 4 |

最终名次分 = 基础分 × 等级倍数：

| 名次 | 一级（×4） | 二级（×2） | 三级（×1） |
|---|---|---|---|
| 冠军 | **80** | **40** | **20** |
| 亚军 | **56** | **28** | **14** |
| 季军 | **40** | **20** | **10** |
| 第四 | **28** | **14** | **7** |
| 八强 | **16** | **8** | **4** |

### 2.4 名次 → 档位的映射规则

现有淘汰赛产出的名次是 `1 / 2 / 3 / 5 / 9 …`（两名半决赛负者并列 3，无独立第 4）。
档位映射按下表：

| 名次值 | 档位 | 说明 |
|---|---|---|
| 1 | 冠军 | |
| 2 | 亚军 | |
| 3 | 季军 | 「并列」模式下两名半决赛负者都取此档 |
| 4 | 第四 | **仅「打三四名」模式会出现** |
| 5 – 8 | 八强 | 8 人赛的首轮负者即此档 |
| ≥ 9 | 未进八强 | **只有参与分 2 分**，名次分 0 |

### 2.5 赛事积分

- 单次赛事所得赛事积分 = **参与分（2 分） + 名次分**。
- 同一场赛事打多轮，**只按最终名次计一次**，不逐轮累加。
- **双打赛事不积分**（与决策 3 一致）。

### 2.6 清零与留存

| 数据 | 生命周期 |
|---|---|
| **赛季积分** | **每个赛季清零**，只统计当前赛季内已结束的赛事 |
| **赛事成绩**（哪次赛事、什么等级、拿了第几名、得多少分） | **永久保存**，不随赛季清零；**离校后仍可查看** |

「赛事成绩」在**「我的」页面**展示（现有 `templates/member-view.wxml`「赛事名次」卡片扩展）。

## 三、赛事比赛的等级分（elo）规则（新增）

**适用于所有赛事比赛（含双打赛事）：**

1. **K 值按等级取固定值**，与选手的场次、分数都无关：

| 等级 | 赛事比赛 K 值 |
|---|---|
| 一级 | **32** |
| 二级 | **24** |
| 三级 | **16** |

2. **日常约球 K 统一为 16**（`kStandard`），不再按场次分「定级期」，也不再按分数降 K。
   因此赛事一律取上表的值：一级、二级放大影响，三级与日常持平。
3. **场次照常计入定级样本**：赛事比赛**仍计入 `matchCount`**，也**仍算进前 5 场**
   （`placementMatchCount`）的定级样本 —— 那套定级只决定新会员从多少分起步，与单场 K 无关。

> 三级赛事 K=16 与日常 K 相同，二级、一级逐级放大，体现「赛事越重要、对分数影响越大」。
> 实现上赛事 K 由**独立配置**（按等级取值）给出，并已把 `ALGO_VERSION` 加一
> （`season.js`），否则容器里缓存的旧分数不会重算。

## 四、日常比赛与积分的关系

- **日常比赛不产生任何积分**，只影响等级分（elo）。
- 现有的 `win = 3 / loss = 1 / 连胜奖励` 全部**不再计入任何榜单**。
- **积分 = 仅赛事积分**（2.5 节）。
- 连带清理：`absencePenalty`（决策 7）与`win/loss/连胜`相关配置一并移除或停用。

## 五、三项 P1 的最终范围（顺序 3 → 2 → 1）

### 5.1 第三项（先做）：赛季管理页 + 软重置同步刷新起点分

**要解决的问题**：现有 `startElo` 是「生涯入池起点分」（`replay.js:239` 一次性写入），
**不是赛季快照**。软重置只改 `elo`、不动 `startElo`（`rating.js:177-183`），
导致「进步 / 赛季涨幅」把跨赛季涨幅算进去，数字虚高。

**范围**：

1. 赛季文档 `seasons/current` 新增**重置时间**字段（如 `resetTime`）与重置策略参数。
2. 新增**赛季软重置**写接口（**仅管理员**）：写 `resetTime`、`version` +1；
   重放时以 `resetTime` 为界；**同时把 `startElo` 刷成重置后的新起点**（核心修复）。
3. 修 `rating.js:166 applySeasonalResetToUser`：重置 `elo` 时**同步更新 `startElo`**。
4. 新增 `pages/season-manage`（仅管理员），放到「我的」页管理入口区，
   失败处理对齐 `announcement-manage`（**失败即拒绝**）。

**推荐默认值**：`retentionFactor = 0.75`、`anchorRating = 1450`、`onlyPlayed = true`。

### 5.2 第二项：榜单改版

1. **删除周榜、月榜**（`constants.js:161-173` 的 `WEEK` / `MONTH` 及标签清理）。
2. 两个榜**分处两个界面**：
   - **等级分榜（elo）**：留在「排行榜」tab（男单 / 女单 / 双打）。
   - **赛季积分榜**：放在**新的「赛事」tab**（决策 14），**只统计本赛季**，**不含双打**。
3. 数据层复用现成的 `buildLeaderboard(players, { sortBy: 'points' })`
   （`utils/leaderboard.js` 已支持，从未接线）。

### 5.3 第一项（最后做）：赛事闭环（发布 → 报名 → 签到 → 名次）

**现状**：赛事是**只读种子数据**（`status` 写死字面量 `2`＝已结束，`seed.js:699`）；
`event_signups` 只在 `COLLECTION`（`constants.js:187`）占了名字，从未接线。

**范围**：

1. **赛事状态机**：新增状态常量。⚠️ **「已结束」必须仍取值 `2`**，否则种子数据全废。
2. **发布赛事**：管理员发布，**必选等级（1/2/3）**与**三四名赛方式（并列 / 打三四名）**。
3. **报名**：会员报名 / 取消；`event_signups` 正式接线（自然键去重，防重复报名）。
4. **签到**：仅管理端代签。
5. **录入名次 / 结束赛事**：作为积分计算依据；「打三四名」模式下需容纳一场三四名决赛。
6. **激活赛事积分**：按第二节规则计入赛季积分；参与分改为按赛事计一次；双打赛事不计分。
7. **赛事比赛 elo**：按第三节规则，K 值按等级取固定值（32 / 24 / 16），
   场次照常计入定级样本。
8. **「离校」状态**：`USER_STATUS` 新增离校 / 校友值；离校后**不上榜、不可报名**，
   但**个人页与赛事成绩仍可见**（满足「离校后也能看到成绩」）。
9. **赛事 tab**：`app.json` 新增第 4 个 tab「赛事」（位于「我的」前），tabBar 4 → 5。

## 九、工程约束（实现时必须遵守）

1. **镜像同步**：`miniprogram/utils|services` 下纯模块会被 `tools/sync-cloud-lib.js`
   逐字节复制到 `cloudfunctions/data/lib/`；改完必须跑 `npm run sync:cloud`，
   否则 `tests/cloud-lib-sync.test.js` 失败。
2. **动作注册表锁定**：新增云端接口要同步改 5 处（`services/cloud.js`、`mock.js`、
   `cloudfunctions/data/src/actions.js`、dispatch 与 handler 模块、测试），
   否则 `tests/cloud-core.test.js` 对拍断言失败。当前 **22 读 + 18 写 = 40 个动作**
   （P1 定稿时为 30 个；P1、P2 实现后新增至 40）。
3. **等级分与积分不落库**：一律由 `replaySeason()` 重算，按 `season.version` 记忆化。
   **任何改变分 / 积分 / 名次语义的改动，必须把 `ALGO_VERSION` 加一**。
4. **赛季锚点写入后钉死**：`anchorTime` 只在首次写入时落库，此后不重算。
5. **云函数失败契约**：顶层 `ok:false` 只表示基础设施故障；业务失败包在 `ok:true` 里，
   形状与 mock 一致，页面行为才不分叉。
