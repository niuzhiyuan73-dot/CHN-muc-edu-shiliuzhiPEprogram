# 前端样式规范与本次统一（2026-10-23）

> 起因：一次前端视觉审查指出「两个分包没遵守全局设计体系」。本文是修复记录，
> 也是后续开发要守的规则——**规则只有三条，其余都是这三条的推论**。

## 一、结论

`app.wxss` 的设计体系本身是完整的（主色 + 强调色 + 中性色 + 语义色 + 间距 + 圆角 + 字号 + 圆角阴影 + 6 套协会主题）。问题不在体系，在**两个分包绕过了它**：

| 问题 | 性质 | 处理 |
|---|---|---|
| 引用了 10 个从未定义的 CSS 变量 | **真 bug**：卡片背景透明、阴影消失、标题色靠继承 | 在 `app.wxss` 补齐（别名指向既有 token，不是新造一套） |
| `packageMeet` 7 个页面硬编码主色、没挂主题类 | 换肤失效 | 改 `var(--color-primary)` + 根节点挂 `themeClass` |
| 分包里 16 个 `.btn` / `.card` / `.tag` 重定义 + 5 个 `.btn-primary` | 同一控件两种长相 | 删除，统一走全局 |
| 语义色两套写法（警告黄、成功绿各 5 种） | 视觉噪音 | 各收敛成一对「浅底 / 深字」变量 |
| 324 处硬编码字号 | 级外尺寸失控 | 变量化，字号表扩到 10 档 |
| 17 个列表页缺空状态 | **经核实不成立**（见 §五） | 未改 |

## 二、变量体系

### 2.1 颜色

| 组 | 变量 | 用途 |
|---|---|---|
| 主色 | `--color-primary` / `-dark` / `-light` | 品牌色。**会随协会换肤** |
| 强调色 | `--color-accent` / `-light` | 关键行动、高亮 |
| 中性 | `--color-bg` / `-card` / `-border` / `-divider` | 页面底、卡片、边框、分隔 |
| 正文 | `--color-text` / `-secondary` / `-tertiary` | 三档字色 |
| 灰阶 | `--color-text-strong/body/muted/faint` | 页面里长期散落的 #222/#555/#888/#999，先给名字 |
| 语义 | `--color-success` `-light` `-text`<br>`--color-warning` `-light` `-text`<br>`--color-danger` `-light` `-text` | 每个语义色一对「浅底 + 深字」。徽章、提示条一律用这一对 |
| 奖项 | `--color-gold` / `-silver` / `-bronze` / `--color-honor` | 奖牌与荣誉 |
| 阴影 | `--shadow-card` / `--shadow-float` | 卡片、浮层 |

**历史别名**（`--color-surface`、`--color-text-primary`、`--brand-color`、`--bg-muted`、`--border-color` 等）全部定义成 `var(原变量)`，指向上面这套。新代码不要再用别名；它们只是为了让早期页面不再静默失效。

> 别名的关键细节：**必须写成 `var(--color-primary)` 而不是复制色值**，否则换肤时别名不跟着变。

### 2.2 字号（10 档）

| 变量 | 值 | 用在哪 |
|---|---|---|
| `--font-2xs` | 20rpx | 徽章、脚注 |
| `--font-xs` | 22rpx | 紧凑标签 |
| `--font-caption` | 24rpx | 卡片副标题、表头、提示 |
| `--font-sm` | 26rpx | 次级正文 |
| `--font-body` | 28rpx | 列表行主文案 |
| `--font-md` | 30rpx | 正文基准（`page` 默认） |
| `--font-lg` | 36rpx | 区块标题 |
| `--font-xl` | 44rpx | 页面标题 |
| `--font-display` | 48rpx | 排名、统计大数字 |

**为什么不压到 5 档**：级数太少，页面就会自己造中间档——原先 24rpx 出现 71 次、28rpx 30 次，都在这张表之外，那才是失控的来源。原则是「**每个用到的尺寸都有名字，且只有一个名字**」。

> 64/72/88/96rpx 仅用于 logo 字、头像占位、巨型数字，不属文本层级，保留字面量。

### 2.3 间距 / 圆角

`--space-xs..xl`（8/16/24/32/48）、`--radius-sm/md/lg`（8/16/24）。新增间距不要造 12rpx、20rpx 这类值。

## 三、三条硬约束

### 1. 不硬编码颜色与字号

```css
/* 错 */  color: #b23a2e;            font-size: 24rpx;
/* 对 */  color: var(--color-primary); font-size: var(--font-caption);
```

唯一的例外是 `app.wxss` 里的变量定义本身，以及 JS 里的品牌常量（`utils/associations.js` 的 `theme` 是注册表，CSS 读不到，只能以它为准并在 `app.wxss` 手抄一份）。

### 2. 不重定义全局类

`app.wxss` 里已有 `.btn` / `.card` / `.tag` / `.empty-state` 及其变体。页面样式里**不要**再写同名块——页面样式的优先级高于全局，等于悄悄给这一个页面换了套按钮。

需要差异就加变体：

| 变体 | 用途 |
|---|---|
| `.btn-primary` | 主行动（渐变，比实心多一层质感） |
| `.btn-accent` | 强调行动 |
| `.btn-outline` | 次要行动（描边） |
| `.btn-ghost` | 低权重行动（返回、取消、加载更多） |
| `.btn-danger` | 破坏性行动（描边红） |
| `.btn-block` | 通栏 |

### 3. 随协会切换的页面必须挂 `themeClass`

```js
const { currentThemeClass } = require('../../services/branding.js');
Page({
  data: { themeClass: '' },
  onLoad() { this.setData({ themeClass: currentThemeClass() }); },
});
```
```html
<view class="page-container {{themeClass}}">
```

**为什么必须这样**：小程序不能给 `page` 元素加类，主题只能落在页面内部的根容器上，子节点靠 `var()` 继承。**根容器之外的元素（`position: fixed` 的浮层、`picker` 弹窗）拿不到主题色**——这类元素要么放进根容器，要么显式用主色变量。

**例外：运动会（`packageMeet`）不换肤。** 一届运动会同时包含篮球、足球、匹克球等多个协会的项目，配色不该由某一个协会决定——跟着变会出现「切到匹克球，篮球项目也变蓝」的错位。

七个页面根节点固定挂 `page-container meet-theme`，`app.wxss` 的 `.page-container.meet-theme` 把四个主题变量覆盖成金色：

| 变量 | 值 | 说明 |
|---|---|---|
| `--color-primary` | `#96700f` | 深金，作按钮/选中态底色时白字对比 **4.6:1**（AA 达标） |
| `--color-primary-dark` | `#7a5a0c` | |
| `--color-primary-light` | `#f9efdb` | 与 `--color-honor-light` 同值 |
| `--color-accent` | `#c9a227` | 石榴籽金原值 |

三个容易踩的点：

1. **主色不能用 `--color-accent` 的 `#c9a227`**。它要当按钮底色，白字对比度只有 2.4:1，文字会糊。同一个色相下沉两档到 `#96700f` 才既「是金色」又「读得清」。
2. **选择器必须写两个类**（`.page-container.meet-theme`，特异性 0,2,0），才压得过 `.assoc-*` 的 (0,1,0)。这样即使将来某页误挂了协会主题类，运动会仍然是金色——「恒定」写在 CSS 优先级里，而不是靠「记得别挂那个类」。
3. **导航栏要单独配**。全局默认是石榴红 `#B23A2E`，七个页面 json 各自写了 `navigationBarBackgroundColor: "#96700F"`；不配就是「红顶配金内容」。

危险语义（报错、删除裁判、抽签失败、作废）**不吃主色**，一律 `--color-danger-text`。否则主题一换，错误提示会从红色变成金色，语义就丢了——这条也由测试盯着。

## 六、没做的三项

| 项 | 为什么不做 | 什么时候做 |
|---|---|---|
| 深色模式 | 不是「加个 `@media`」的事：现有 168 个色值里约 60 个是浅底专用（`#fff`、`#f5f6f8`、各种浅色徽章底），深色下全部要换一套。而 `page` 背景与 `navigationBar` 颜色还要各自适配 | 有明确需求时，先做「变量双轨」（每个语义变量给 `dark` 值），再谈页面 |
| emoji 当功能图标 | 三端渲染不一致是真的，但替换要先有图标资源（现在是 `assets/` 下只有 tabbar 图标）。空状态图标已有统一底座（`--color-divider` 圆形），各页 emoji 不同但底座一致，观感上不散 | 设计提供图标集后，按 `empty-state-icon` 一处替换 |
| 1rpx / 2rpx 边框混用 | 视觉上 1rpx 在部分安卓机型会被四舍五入成 1px 或消失，2rpx 更稳。全局统一到 2rpx 会改变一批输入框与分隔线的粗细，收益低 | 与上面的深色模式一起做 |

## 七、怎么验（真机，不是测试能覆盖的）

自动化测试只保证结构（173 文件 / 2976 用例），**视觉效果必须真机看**：

1. **卡片有没有底与阴影**——打开球队列表、赛事列表：卡片应是白底 + 轻阴影，不是透明贴在一起。
2. **换肤是否生效**——切到匹克球协会，进运动会列表 / 详情：标题、主按钮、选中态应是蓝色（`#1565c0`），不是石榴红。
3. **按钮是否一致**——同一屏里看「主行动 / 次要行动」：高度都是 88rpx，主按钮是渐变，次要按钮是描边或浅底，不再出现 72rpx 与 88rpx 并存。
4. **运动会详情底部那排按钮**——「结束运动会 / 编辑基本信息 / 继续配置 / 删除草稿 / 加载更多」应有描边、有内边距，不再是浏览器默认按钮。
5. **字号是否过密**——重点看 packageMeet / packageTeam 的列表行：24rpx 归到 `--font-caption`（24），26/27 归 26，整体应比之前略整齐，不应出现换行错位。
6. **空列表**——把某个协会的球队清空，应看到「还没有球队」而不是白屏。

## 八、维护约定

- 新增颜色先问「它是主色 / 语义色 / 中性色里的哪一类」，能归入现有变量就不要造新值；
- 新增字号只能从 10 档里选，选不下来说明这一档确实缺，**先改 `app.wxss` 再改页面**；
- 新页面第一行模板就带 `{{themeClass}}`，别等到「换肤不生效」再补；
- **例外**：运动会（`packageMeet`）的页面一律挂 `meet-theme`，不要挂 `{{themeClass}}`，也不要在页面 json 里漏掉金色导航栏。新增运动会页面时照抄同目录任一页的四件套即可，`tests/meet-theme.test.js` 会检查；
- 改完跑 `npm test`：`tests/cup-home-pages.test.js` 一类的用例会检查关键样式是否还在（它们接受变量写法，但不接受「样式消失」）。

## 九、补记：本地全绿、真机白屏的一次事故

样式统一提交之后，真机出现**首页白屏 + `ReferenceError: process is not defined`**。原因不在样式，在同期加的「身份上下文缓存」：

```js
// 错：小程序运行时没有 process，模块加载阶段就会抛错
let ttlMs = readTtl();                       // 顶层立即执行
function readTtl() { const raw = process.env.CONTEXT_CACHE_TTL_MS; ... }
```

`school-context.js` require 了它，而 `school-context.js` 在小程序端也会被加载——于是整条链路在 `require` 阶段就断了。**单元测试 2976 条全绿**，因为测试跑在 Node 里，`process` 一直都在。

修复是两件事：

1. 先判环境：`typeof process !== 'undefined'`，小程序端恒返回 `ttl = 0`（缓存只服务云函数入口，小程序端本来就不走那条路径）；
2. 加 `tests/miniprogram-runtime-safety.test.js`，两条互补的断言：
   - **静态扫描**：`miniprogram/` 下不得出现裸 `process.` / `Buffer` / `__dirname` / `require('fs')`；
   - **沙箱模拟**：用 `node:vm` 在**没有 process 的沙箱**里加载模块，验证真能跑起来。

> 只靠扫描会漏（分不清「裸写」与 `typeof` 保护后的使用），只靠模拟又得给每个模块写沙箱。两条都要。
> 白名单里的条目必须给出理由，并且补一条沙箱用例——否则白名单会变成漏洞清单。

**给后续开发的提醒**：这个项目的测试全部跑在 Node 里，任何依赖 Node 全局的写法都不会被测试发现。小程序端只能用的能力（`wx.*`）与 Node 专有能力（`process` / `fs` / `Buffer`）之间，**共享模块（`miniprogram/services/**`）只能站在小程序这一侧**——云端专用的环境判断必须写成 `typeof` 保护。

## 2026-10-28 界面体验共用规则

主按钮使用主题的深色搭配 `--color-on-primary`，金色强调按钮使用 `--color-on-accent` 深色文字。高频操作以 `--control-min-height` 的 44px 作为最小触达高度；数字使用等宽数字，长名称优先换行。

**2026-10-28 补充**：分池页签、协会切换徽章、签表小按钮与赛事探索器控件也纳入 44px 触控下限。禁用主按钮改用 `--color-disabled-bg` + `--color-disabled-text`，保持“不可点”语义同时满足可读对比度；不再使用浅底白字。状态标签允许自动增高与换行，长协会名或长状态不能撑破列表行；协会来源用“文字徽标 + 名称”双重标识，不只用颜色。

跨分包的阶段、导航、底部行动、折叠、复核、错误摘要和选中状态样式放在 `templates/experience.wxss`，由 app 统一导入，页面不重定义 `.btn/.card/.tag`。客户端交互装饰器放在 `templates/*-experience.js`，纯整形 `utils/interface-view.js` 进入云端镜像。

表单折叠使用 hidden 保留输入节点；复核必须绑定当前内容，输入变化后重新复核。会话和学校切换使旧请求失效，组件隐藏时停止主动取数。普通详情仅显示已有 can* 对应动作，不能用进度条推导授权。底部行动给页面预留安全区，减少动效设置下去掉非必要过渡。代表界面须核对窄屏，微信原生字体、输入键盘和横屏安全区仍要真机检查。
