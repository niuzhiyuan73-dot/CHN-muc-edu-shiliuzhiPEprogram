## 3. 接入组件的约定

父页面未来通过 `usingComponents` 注册 `/components/football-event-form/football-event-form`，只在足球范围挂载；篮球仍使用既有建赛表单。

组件属性：

- `submitting`：父页面网络请求是否进行中。
- `serverError`：建赛失败时的可读提示。

组件事件：

- `submit`：`event.detail` 为 `name / format / sportFormat / presetKey / rules / requestId`，调用当前学校与协会范围内的 `createTeamEvent`。
- `cancel`：由父页面关闭表单。

父页面收到提交后应立即设置 `submitting=true`、清空旧错误；成功后关闭组件并刷新列表；失败后将 `submitting=false` 和服务端原因传回。组件内部同样会拦截重复点击；同一内容重试使用原 `requestId`。

表单预览属于前端提示；人数、资格、规则锁定、权限及并发限制仍需后端独立验证，不能因组件已经校验就省略。

## 5. 延期部分与恢复顺序

篮球修复稳定后，重新读取共享文件的最新内容，再按以下顺序接入；不要用本批开始时的文件副本覆盖修复结果。

1. **足球注册与品牌**：将 `createFootballAssociation()` 的定义接入协会注册表，补 `.assoc-fb` 主题；检查首页/协会选择与工作台三页签、学校启用配置以及旧链接回退。
2. **自由组队复用**：核对 `team-service.js` 中目前固定写入/兜底的 `basketball` 字段，按可信协会元数据区分足球；验证跨学院组队、建队审核、入队申请、队长权限和学校/协会隔离。
3. **共享报名校验**：在团队赛事服务中落实同赛事单人单队约束，覆盖有效待审、已通过、已锁定报名；拒绝非本校有效成员、非本队成员及非法号码。需要考虑并发，不能只依赖页面或事务外扫描。
4. **列表与详情接入**：团队赛事列表按运动挂载独立组件；详情展示足球规则与报名信息，避免使用篮球统计表、胜场排序或实时入口。F2/F3 未开放的名单、录分和统计操作不能显示成可正常使用。
5. **演示合并**：在种子内容装载处按集合追加 `createFootballDemoContent()`。现有 `Object.assign(content, createTeamDemoContent())` 会替换数组，不能再次用 Object.assign 把篮球数组覆盖掉；所有球队、报名及角色都保留各自学校/协会范围。
6. **同步与验收**：需要在云端运行的新模块加入共享清单，基于最新源文件同步；运行足球自由组队、报名、表单页面、权限和篮球回归，最后执行全量测试及云端一致性检查。

只有完成上述接入和验证，才把 F1 标记为完成。本批没有建立自动唤醒或后台接入任务；接手时依据此清单继续。
