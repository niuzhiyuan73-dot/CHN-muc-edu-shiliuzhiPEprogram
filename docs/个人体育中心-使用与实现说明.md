# 个人体育中心使用与实现说明

2026-10-28。F01–F17 已提交为 `581104f`；F18 的个人赛程、待办和运动护照已完成。场地看板、校园赛历、成绩分享卡暂不做，用户明确要求本批排除，待后续单独确认范围。

同日的前端体验批次在不改接口的前提下补充：首页“我的下一步”按目标给明确行动文案；“运动护照”顶部增加只取已核验记录的“生涯节点”横向时间轴。时间轴只使用当前已加载页，不宣称完整生涯总量，也不新增成长值或综合能力分。见[前端探索与现场体验优化-验收记录](前端探索与现场体验优化-验收记录.md)。

## 入口与使用

首页登录后展示“我的下一步”和最多三条“我的待办”；行动文案按服务端下发的目标类型显示“确认比分 / 处理名单 / 审核报告 / 提交成绩”等明确动词，点击仍进入原有处理页面并重新核验权限。“全部安排”进入“我的体育”。“我的”页面增加运动护照及待办入口。个人中心提供赛程、待办、护照三个页签，可按六个协会或运动会筛选，默认每页 20 条，按钮继续加载；“已显示”只是当前已加载数量。

未登录不读取个人聚合。只有当前浏览学校是本人有效主校时可读取；外校浏览和待审身份会给出说明。换账号、学校、页签或筛选时旧响应失效；读取失败提供重试，续页网络失败保留已加载记录，权限或游标失效则清空列表并要求刷新。

## 三类内容

| 内容 | 数据事实与展示 |
|---|---|
| 我的赛程 | 未来 90 天未结算个人/学院小场、本人锁定球队名单对应的场次、团队裁判/记录员安排、运动会本人正式报名及执裁；进行中优先，同场合并角色 |
| 等待赛程 | 个人赛有效报名、学院已通过名单、球队已通过或锁定名单，在尚未产生对应赛程的阶段标明时间待定；不虚构开赛时间 |
| 我的待办 | 本人按现行规则可确认的比分、授权管理学院的退回名单、当前有效队长的退回报名、管理范围内待审核团队报告、本人仍有该场指派的未提交裁判草稿、校级审核申请提醒 |
| 运动护照 | 已确认个人比分、已发布个人赛事名次、当前发布版本的运动会成绩、已结束赛事的学院/球队名单记录、已发布篮球/足球报告中的本人记录 |

运动会分组名次不显示为正式奖牌；只有正式发布或个人赛事已发布的前三名加荣誉强调。名单入选不推定实际出场，报告收录也不增加出场断言；没有新增成长值或综合能力分。护照当前显示证明类型、对阵/名次、时间和详情入口，测量成绩和完整报告继续在原详情查看。护照顶部的“生涯节点”只从当前已加载的、带名次/荣誉/证明的记录中提取，按下一条加载继续补充，不把报名名单写成实际出场。

待办是受权限约束的摘要入口，不是完整审批台账。入会及转校提醒使用通用标题，申请人的学号、真名、联系方式不会出现在摘要。未形成草稿的裁判安排列在赛程；旧的完整审批、报名和录分工作台继续保留。

## 处理入口

个人比赛直接打开现有 `match-panel` 的单场模式，保留现行录分、确认、驳回和事务校验；该模式使用 `getSchoolMatch({matchId,presentation:true})`，只补本场最多五人的昵称，不加载整校选人名册。原接口默认响应不变。

单场模式打开指派裁判时才按页搜索本校有效候选，每页 20 人，支持继续加载、失败重试和关闭后作废回调；候选范围不被本场五人限制。协会比赛列表原有选人方式保留，后续随对应页面迁移。

学院退回名单进入学院名单编辑器；球队报名和篮球报告进入团队赛事详情；足球报告进入原比赛详情；裁判安排进入原运动会录分页并选中实际场次；校级审核进入当前学校身份页。用户在处理页面提交时仍由原写接口在事务内核验权限与状态。摘要可能在读取后变化，返回或下拉刷新会重新核对。

## 接口与查询

新增协议 2 身份组只读 action `getMySportsDashboard`。`section` 为 `overview/schedule/tasks/passport`，`project` 为空、协会编号或 `meet`，`limit` 默认 20、最多 30，`cursor` 为续页返回值。`overview` 返回 `schedule`（最多 1 条）和 `tasks`（最多 3 条）；其他分区返回 `items/hasMore/nextCursor/asOf`。没有精确总量和其他用户参数，客户端传 `userId` 不改变认证本人。

入口独立构造学校级新鲜身份；逐协会点读启用状态及本人授权。仓储原语 `personalSports.readPage` 使用同一查询规格，云端执行聚合，演示仓储执行等价操作；事务内禁止查询。按学校及本人关系/管理范围过滤后关联父记录，核验归属和状态，再去重、排序、取多一行、投影。账号和球队名称只补当前页所需记录。新增两个纯服务模块已登记 MANIFEST 并同步镜像，无新集合、写接口或回填。

游标绑定学校、本人、分区、项目、启用协会及当前管理权限，有效期 30 分钟；同一页链保持时间锚点。各来源分别保存位置再合并，避免跨来源分页重复。它不提供跨请求数据库快照，期间新增/变更的记录需要刷新后核对。被撤权、作废、结束或发布版本变化的内容会按读取时状态过滤；仓储故障向调用方暴露，不包装成成功空列表。

## 发布与验收边界

部署前按[索引清单 §2.7](数据库索引清单.md#27-个人赛程待办与运动护照查询2026-10-28)新增 13 条关系/管理范围索引，核对六类关联外键索引，再同步镜像并重新部署 `data`，最后上传小程序。现有同前缀索引可复用，数组路径分开建立。

原语控制应用层返回量；数据库仍需处理本人的相关历史，不能据此推断云端扫描、耗时或成本恒定。真实执行计划、冷启动、长历史账号耗时、微信编译包体、原生组件和真机交互尚未验证。本地证据见[第十二轮验收](第十二轮个人体育中心-验收记录.md)。
