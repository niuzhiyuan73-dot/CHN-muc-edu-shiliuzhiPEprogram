# 文档地图（谁是什么、什么时候必改）

`docs/` 现有 82 份 md + 1 份 html，加根目录 3 份 docx 与 README。按用途分四类，**只有 A1 是每批必须校对的**。

## A1 数字校对型（4 份，每批 audit 归零）

| 文件 | 职责 | 真值来源 | 常改的位置 |
|---|---|---|---|
| `README.md` | 唯一对外入口：定位、规模、架构、命令、部署 | `doc-truth.js` + `npm test` + `check:cloud-sync` | §1 自检行、§5 架构图与 action 计数、§6 目录（页面数）、§8 集合数 |
| `docs/交接说明.md` | 接手人第一小时读的东西 | 同上 | §1「规模」行、§3 数据模型、§6 部署三步 |
| `docs/云开发控制台操作指南.md` | 控制台实操：集合、角色、赛季、救急 | `constants.COLLECTION` | 第三节集合清单与总数 |
| `docs/数据库索引清单.md` | 索引台账 + 读放大记录 | 新建索引的代码与查询 | 各域索引表、§4 读放大改法 |

校对器只认这四份。其它文档不参与数字比对 —— 不是不重要，而是里面混着历史段落，扫了必然误报。

## A2 定点更新型（4 份，只改指定位置）

| 文件 | 只改这里 | 不要动 |
|---|---|---|
| `docs/AI接手与后续施工指南.md` | 顶部「现状补丁」表 + 更新日期 | 正文 683 行历史叙述（含已被推翻的 replay / revoke 描述） |
| `docs/施工切片账本.md` | 队列表**追加行** | 历史行的提交号与结论 |
| `docs/前端样式规范-2026-10-23.md` | §二 变量表、§三 三条硬约束、§八 维护约定 | §四 本次改了什么、§五 与审查报告的出入 |
| `docs/专项方案-需求与实施方案` 类（网球计分、石榴籽杯、协会空间、场地分配…） | 规则变化时的对应小节 | 已落地的验收结论 |

A2 的共同特征：**同一份文件里既有现行规则又有历史留痕**。改之前先确认目标段落是「规则」还是「记录」。

`docs/安全与性能优化-实施方案.md` 属 A2 现行方案，按实现更新迁移、索引与发布步骤。

## B 产物型（3 份 docx）

| 源 md | 产物 | 构建 |
|---|---|---|
| `docs/赛事管理员操作手册.md` | `赛事管理员操作手册.docx` | `doc-build.cjs` |
| `docs/云开发控制台操作指南.md` | `云开发控制台操作指南.docx` | 同上 |
| `docs/交接说明.md` | `交接说明.docx` | 同上 |

规则：md 改了必须重建 docx；不许反向手改 docx（下次构建会覆盖，且产生两份不一致的真相）。

> 其它 docx（项目策划书、未定产品决策跟踪表）是外部产物，不在此链路内，改动需单独确认来源。

## C 冻结型（默认冻结，改需用户明示）

模式命中即冻结（共 41 份）：

| 模式 | 数量 | 为什么冻结 |
|---|---|---|
| `*验收记录*` | 24 | 记录当时的验证结论与提交号 |
| `*需求整理*` | 7 | 当时的需求快照，产品口径可能已变 |
| `*实施记录*` | 5 | 实施过程留痕 |
| `*审计*` | 2 | 只读审计发现与编号（H1/H9 等被代码注释引用） |
| `*隐患*` | 2 | 已修/未修的判断带时间点 |
| `*修复记录*` | 2 | 缺陷复现与修法 |
| `*调查*` | 1 | 结论依赖当时的代码 |
| `docs/*.html` | 1 | 生成物 |
| `.workbuddy/memory/*.md` | — | 每日工作日志，只追加 |

**放行白名单**（命中模式但属现行文档，不冻结）：

```
网球计分-需求与实施方案.md
石榴籽杯-需求确认与实施方案.md
Elo逐场结算改造-交付与发布准备.md
运动会栏目-发布准备.md
施工切片账本.md
```

判定口径：文件名含「实施方案 / 发布准备 / 操作手册 / 操作指南 / 交接说明 / 索引清单 / 样式规范 / 演示账号 / 施工指南 / 账本」→ 现行；含「验收记录 / 需求整理 / 实施记录 / 审计 / 隐患 / 修复记录 / 调查」且不在白名单 → 冻结。

两者都命中时以白名单为准，并在同步报告里记一行「分类有歧义，按现行处理」。

## 怎么判定一份文档属于哪类（遇到新文件时）

```
能算出真值、且读者会当作现行事实？ → A1
讲规则但混着历史？               → A2
由别的文件生成？                 → B
讲「当时发生了什么」？            → C
```

拿不准时按 A2 处理：只改明确属于规则的位置，并在报告里标注待确认。
