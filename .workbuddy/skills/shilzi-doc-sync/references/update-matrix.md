# 更新矩阵（改了什么 → 必改哪几份）

左侧是「你实际改的代码」，右侧是「不改就会让读者拿到错误信息」的文档位置。**必改**列是硬要求，**易漏**列是实测中最常被忘掉的位置。

## 1. 页面增删

| 必改 | 位置 |
|---|---|
| `README.md` | §1 进度句、§5.1 分包表（体积与页数）、§6 目录注释「app.json N 页：主包 X + 分包 Y」 |
| `docs/交接说明.md` | §1「规模」行的页面数 |

易漏：README §5.1 的分包体积表 + §6 的括号注释是两处，只改一处就自相矛盾。

## 2. action 增删

| 必改 | 位置 |
|---|---|
| `README.md` | §5 架构图注释「共 N 个」、§5「当前 N 个 action 按领域分成四组：会员与身份 a、协会空间与个人赛/团队 b、跨校邀请赛 c、运动会 d」 |
| `docs/交接说明.md` | §1「规模」行的 action 数 |
| `docs/AI接手与后续施工指南.md` | 顶部「现状补丁」表的 action 行 |

易漏：分组四个数要一起改。实测出现过「总数 187 正确、分组写成 13/101/15/53 但实际 119」的情况 —— 总数与分解必须同时成立。

## 11. 新文档诞生

新建 md 后三件事：

1. 若是验收记录 → 挂进账本；
2. 若是现行方案 → 挂进 `README.md §9 文档地图`；
3. 在 `references/document-map.md` 里归入 A1/A2/B/C 某一类。

漏了第 3 步，下一轮 `--frozen-check` 会把它当未知文件，报告里会出现「分类未定」提示。

## 12. 不触发任何文档更新的改动

这些改了不用动文档，避免过度同步：

- 纯重构（行为不变、无新接口、页面数不变）
- 测试内部改写（用例数变了才更新 README §1）
- 注释、日志、变量名
- 局部样式微调（规则未变）

判断口径：**读者读完文档后会不会做出错误动作**。会，就必改；不会，就不改。
